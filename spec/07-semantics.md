# 7 语义层

**范围。** 本章定义语义层五种语句——concept、pattern、check、style、variant——的求值：两阶段求值的次序与保证（D9）、语义层的命名空间与可见性、语义层里可用的全部集合构件与关系谓词、`where` 字段在语义层的精确定义、每种语句的语义与输出形状、变体模板与外包络的接口、皮肤的不可见性与材质来源、style 与节点自身 `mat=` / `color=` 的优先级（D8）。本章同时定义只改外观的 `over` 与 style / variant 的等价关系。

本章**不**定义：语法与表达式文法（见 01-syntax.md）、实体与曲线的几何与包围盒（见 02-geometry.md）、定位与朝向的求解（见 03-solving.md）、over / drop 两个时机的判定与模板展开（见 04-derivation.md）、层的平铺顺序（见 05-layers.md）、空间事实的推导与关系索引（见 06-facts.md）、元数据的传播与输出（见 08-metadata.md）、材质解析的通用顺序（见 10-materials.md）。

**依赖的章。** 01（词法、语句形态、表达式、名字解析、选择器、`where` 字段的类型）、02（局部包围盒、紧包围盒）、03（世界变换、世界包围盒、容器的包围盒与包络、`at` / `pin`）、04（def 的展开、copy、副本与影子、over 的两个时机）、05（层的平铺顺序，即"后写"的含义）、06（事实、关系索引）、10（材质）。被依赖：04（外观时机 over 的效果）、05、09、10。

**本章术语。** 在第 1 章术语之上补充：

| 术语 | 含义 |
|---|---|
| 语义语句 | concept、pattern、check、style、variant，以及被 4.5.1 登记为 style / variant 的外观时机 `over` |
| 语义名 | 概念名与模式名；全场景一张表（5.3.1 的"语义名与词法名"） |
| 最终定义 | 同名语义语句在 $P$（5.1.1 的展开序列）里的最后一条有效语句（5.3.5） |
| 选择集 | 一条 style / variant 语句的选择器求值得到的节点集合 |
| 宿主 $N$ / 皮肤 $K$ | 被变体选中并挂载的节点 / 挂在它下面、段为 `skin` 的模板实例节点（1.6.4、4.7） |
| 关系索引 | 由空间事实上提构造的七个有序对集合（06-facts.md 的 6.7.1；本章记作 $R_{\text{rel}}(x)$，7.2.4），关系谓词与 pattern 的关系约束查它 |
| 集合类 | 1.5.5 定义的能转成集合的值：集合、引用、列表、模式值 |
| 失败 | 一条语义语句（或一个语义名）求值没有得到值而得到一条错误（7.4.3） |

## 7.1 概述与求值次序

### 7.1.1 两个阶段

语义层在 4.1.1 的阶段 7 与阶段 8 工作，分成**两个阶段**（D9；PLAN 第 3 节第 7 条）：

- **阶段一**（阶段 7，"几何 + 事实 + 语义"）：对阶段 6 定稿的场景树（含影子、副本组、copy 节点、退化节点，**不含**任何皮肤）求解全部节点（第 3 章）、推导空间事实（第 6 章）、构造关系索引（6.7.1；本章 7.2.4 的记法）；然后求值全部语义语句：概念的成员、模式的匹配、检查的结果，以及**每条 style 与 variant 的选择集**。阶段一结束时，`nodes[]` 里非皮肤节点的一切（路径、种类、变换、包围盒、紧包围盒、`late`、`ghost`、`of`）、`facts[]`、`concepts[]`、`patterns[]`、`checks[]` 与每条 style / variant 的选择集都已确定，之后**不再改变**。
- **阶段二**（阶段 8，"外观时机"）：按阶段一的选择集**只替换外观**：变体把宿主标记为隐藏并挂皮肤（7.8.3、4.7），样式改外观时机的有效材质 $E$（7.7、10.3.3）；最后解析每个节点的材质（10.3）并生成输出条目（10.6）。阶段二不改任何非皮肤节点的变换、包围盒、紧包围盒与事实，不改概念 / 模式 / 检查的结果，不改任何选择集。

**保证（D9 的精确表述）。** 设场景 $P$，$P^\circ$ 是把 $P$ 里全部 `style`、`variant` 与外观时机的 `over` 删掉（其余不动）得到的场景。则 $P$ 与 $P^\circ$ 的编译结果在 05-layers.md 的 5.4.4 列出的五项上**逐位相同**：(1) 去掉 `skin: true` 条目后的 `nodes[]` 序列，及每个非皮肤节点的 `path kind id tags concepts line file types meta depth late ghost of curve`；(2) 每个非皮肤节点的 `world`（$R$、$t$）、`box`、`tight`；(3) `facts[]` 的条数、顺序与每条的全部字段，以及 `factsSkipped`、`factProviders`；(4) `concepts[]`、`patterns[]`、`checks[]` 的条目、成员、匹配、通过与否与顺序；(5) 归属于几何层语句、只读语义语句、以及节点路径不在皮肤子树里的全部错误与警告。允许不同的只有 5.4.4 列出的那些：`nodes[]` 的 `hidden`；皮肤节点（`skin: true`）及其一切；`items[]` 与 `curves[]` 的**条目集合**（被隐藏的节点没有条目、皮肤有，10.6）与 `items[]` 的 `material`；`variants[]`（$P^\circ$ 没有删任何 `def` / `material`，所以 `defs` 与 `materials` 输出也相同）；归属于外观层语句、或节点路径在皮肤子树里的诊断；由此变化的错误排序（1.1.5）。被变体隐藏的原物体仍进 `all()`、仍参与事实、概念与模式（7.8.4；5.4.3 依赖此），所以隐藏不是上面五项里任何一项的变化。这是 5.4.4 对语义层的落实；它由本章的构造保证——阶段二读不到的量不可能被它改变——不是一条需要额外实现的规则。

**与原型的关系。** 原型 compile 把有变体的文件编译**两遍**（compileOnce 第一遍得到替换计划 plan，第二遍按 plan 挂皮肤后重新求解、推导事实、求值语义）；本版是一遍编译里的两个阶段。原型第二遍重算的变换、包围盒、事实、`all()` / `kind()` / `#tag` 与第一遍逐位相同（皮肤不计入宿主的盒、不参与事实、被 allNodes 过滤），但第二遍的语义语句是在**有皮肤的树上**求值的：`descendants(S)`、`children(S)`、通配与直接路径 `x.skin` 能选到皮肤节点（小例子 07/t2.s3d：`variant g use=sk` 之后 `concept desc = descendants(g)` 得到 `g.a g.skin g.skin.base`，`check count(descendants(g)) == 1` 不通过，皮肤节点带 `concepts` 标注）。本版规定全部语义语句在皮肤生成之前求值（7.2.5 第 3 条），这类表达式只得到非皮肤节点；两者只在选择器对宿主子树用了这四种构件时不同（7.9.4）。实现**可以**用两遍实现，只要输出满足本节的保证。

### 7.1.2 阶段一的次序

阶段一按下面的顺序进行；每一步的输入是前面各步的输出，步内的顺序在各节定义：

1. **求解**：全部非皮肤节点的局部变换、世界变换、局部 / 世界 / 紧包围盒（第 3 章；后置节点也在此阶段求解完成）。出错的节点按 1.1.4 退化。
2. **事实**：第 6 章；宿主关闭事实推导时为空（7.1.4）。
3. **关系索引**：6.7.1，只读事实的 `rel`、`a`、`b`（7.2.4 给出语义层的记法与后果）；事实未推导时为空（7.1.4）。
4. **语义名字空间**：按 5.3.5 对 $P$ 折叠出每个概念名与模式名的最终定义（7.2.2）；此时做 7.4.2、7.5.2、7.7.1 与 7.8.1 的静态检查。
5. **强制求值**：按 $P$ 的顺序对每个模式的最终定义求匹配（7.5.4），再按 $P$ 的顺序对每个概念的最终定义求成员（7.4.1）。求值是**惰性且纯的**：一个语义名在第一次被读到时求值一次，值缓存（失败不缓存，7.4.3）；它的值只依赖阶段一的量与其他语义名的值，与被谁先读到无关。本步只保证每个名字都被求值过并产生输出条目。
6. **检查**：按 $P$ 的顺序求值每条 `check`（7.6）。
7. **样式的选择集**：按 $P$ 的顺序求值每条 style（含登记为 style 的外观时机 over）的选择器（7.7.2）。
8. **变体的选择集与裁决**：按 $P$ 的顺序求值每条 variant（含登记为 variant 的外观时机 over）的选择器，再按 7.8.2 裁决出挂载表。

第 5–8 步之间没有数据依赖（选择器与检查读概念、模式、事实与几何，不读样式或变体的结果；`where mat` 读 $E_g$，10.5.3），所以这个顺序只影响：节点标注 `concepts` 的顺序（7.4.4）与错误列表排序前的发现顺序（1.1.5 排序后与顺序无关）；哪些语句失败、失败的文案都与顺序无关（7.4.3：成功的值缓存、失败的每次重算，文案只由进入点决定）。

语义语句的求值上下文（1.5.8 表"语义层语句"行）：词法环境 = **语义帧**（7.2.1），场景位置（搜索起点）= **根**，时机 = 阶段一。pattern 的约束行也在这个上下文里求值，另加角色绑定帧（7.5.3）；variant 写明的参数值用同一词法环境与搜索起点，但在阶段二挂载时求值（7.8.3 第 3 条）。

### 7.1.3 阶段二的次序

1. **挂载**：按挂载表（7.8.2）的节点顺序，对每个宿主 $N$ 执行 4.7 的挂载：标记隐藏（不改变任何可读的量：隐藏的节点仍进 `all()`、仍有变换、包围盒、事实与有效材质，7.8.4）、构造并展开皮肤语句、绑定参数、定位（7.8.3）。各宿主互相独立；一个宿主的错误不影响其他宿主（1.1.4 第 6 条）。
2. **皮肤的求解**：求解全部皮肤子树（第 3 章；皮肤可以引用阶段一已求解的任何非皮肤节点，反之不能），生成皮肤里的副本树（4.4.2），施加皮肤模板体里的 over / drop 与 copy（4.7 第 6 条）。皮肤的局部包围盒、紧包围盒按第 2 章计算，只用于皮肤自己的定位（7.8.3）、渲染与输出。
3. **样式**：按 $P$ 的顺序把每条 style 的样式动作施加于它的选择集（10.3.3），得到每个节点的外观时机有效材质 $E$；皮肤经终点 $E(N)$ 间接受影响（10.4.3）。
4. **输出**：材质解析（10.3）、条目（10.6）、`nodes[]` 的 `hidden` / `skin` 字段、`variants[]`（7.8.9）。

阶段二里没有任何选择器求值：样式与变体的选择集来自阶段一；阶段二求值的表达式只有 variant 写明的参数值（7.8.3 第 3 条）、皮肤模板体里的属性值、`let`、元数据与皮肤体内 over / drop 的选择器（它们的搜索起点在皮肤子树里，4.7 第 6 条）。"只替换外观"的精确清单就是 7.1.1 的保证（5.4.4 的五项与允许不同的项）。

### 7.1.4 没有变体与没有语义语句的情形

- $P$ 里**没有任何语义语句**：阶段一的第 4–8 步什么都不做；输出 `concepts: []`、`patterns: []`、`checks: []`、`variants: []`，每个节点的 `concepts: []`，没有节点带 `hidden` 或 `skin`；阶段二只做材质解析与输出。语料 basics、curves、rotation、spaceport、spaceport_edit 都是这种情形（参考输出里这四个数组为空）。
- **有语义语句、没有变体**：阶段二只有样式与输出；节点集合与基线相同（没有皮肤、没有隐藏）。
- **有变体但选择集全空**（选择器合法、选不中任何节点）：不是错误（1.7.1，style / variant 的空选择合法）；`variants[]` 里该语句的 `members` 为 `[]`；没有节点被隐藏。登记为 variant 的外观时机 `over` 空选择时按 5.4.2 第 7 条报错"X 没有选中任何对象"，语句无效，`members` 为 `[]`。
- **宿主关闭了事实推导**（6.6.4；输出 `factsSkipped: true`）：事实为空，关系索引（6.7.1）为空，七个关系谓词都得到空集（6.7.3），pattern 的关系约束都不成立；每条调用了关系谓词的语句（concept、pattern、check、style、variant、外观时机的 over；pattern 的关系约束视同调用，7.2.4）记一条**警告**"空间事实未推导，X() 为空集"（每条语句一条，不论调用了几次；6.6.4、6.9），语句照常求值、不报错。概念、检查照常求值，结果按空事实计算。原型 compileOnce 不警告（`buildRelations([])` 静默）；本版按 6.9 加警告。宿主**应**在界面上提示事实未推导，这不属于本规范。
- **退化节点**（1.1.4）照常进入 `all()`、`kind()`、`#tag`、概念与模式的候选集，`where` 字段按 7.3.2 取值，不参与事实（第 6 章）因而不在任何关系谓词的结果里；可以被样式与变体选中（7.8.2）。

## 7.2 命名空间与可见性

### 7.2.1 语义帧与名字解析

**语义帧**（1.5.8 的帧表最后一行）是语义层表达式的词法环境：它含全部概念名与模式名（各自的最终定义，7.2.2），父帧是**全局帧**（全部文件最外层的 `let` 与 `metre`）。语义语句里一个裸标识符或路径首段按 1.6.5 的顺序解析，在语义层展开为：

1. **最内层的局部帧**（有则查）：`where` 帧（1.7.3 的字段、成员的元数据键；8.2.2 的顺序）→ 模式的**角色绑定帧**（7.5.3：角色名 → 当前绑定）。
2. **语义帧**：概念名 → 该概念的成员集合（集合）；模式名 → 模式值（7.5.7）。读到的名字在此刻求值（惰性，7.4.3）。
3. **全局帧**：最外层 `let`（在它自己的上下文里求值并按时机缓存，1.5.8）、`metre`。
4. **场景树**：搜索起点是根，所以第一段在根的直接子节点里按 `child(根, s)`（含匿名容器穿透）查找；命中则按 1.6.5 第 5 步下降。
5. **全局索引**（1.6.5 第 3 步）；恰一个命中则用它，多个报错"名字 X 不唯一…"，没有则：在 `where` 谓词里按 8.2.2 作元数据键读取（缺失值）；在其他位置报错"找不到对象 X"（D4：**不**退化成字符串）。

后果：

- 语义名**遮蔽**同名节点：`concept cabin = kind(box) & supports(kind(wedge))` 之后，`check cabin - on(ground)` 里的 `cabin` 是概念；场景里名为 `cabin` 的节点要在语义层按路径引用时须写它的完整路径（`watch.cabin`），或在几何层引用（几何层看不见语义帧，5.4.2）。原型 Env 的查找顺序相同（semantic → globals → S.find）。
- 语义名与最外层 `let` 同名是错误（5.3.5），所以第 2、3 步之间没有遮蔽问题。
- 最外层 `let` 的词法环境是全局帧（1.5.8 表第二行），**看不见语义帧**：`let x = pier | deck` 在被语义语句读到时报错"找不到对象 pier"（pier 是概念不是对象）。要给集合取名用 `concept`。`let` 可以含 `all()`、`kind()`、`where`、关系谓词，在语义层读到时合法（5.4.2 第 6 条）。
- 模板参数、阵列索引、over / copy 块的 `it` 不在语义层的帧链上；在语义语句里使用它们报错"找不到对象 X"（1.5.8）。
- 语义语句里的对象名从根起解析：`style watch.cabin mat=wood` 是路径；`style cabin mat=wood` 在没有同名概念时经穿透 / 全局索引找到 `watch.cabin` 与 `watch2.cabin` 两个候选→报错"名字 cabin 不唯一，请写完整路径（watch.cabin / watch2.cabin）"。

### 7.2.2 同名定义的覆盖

按 05-layers.md 的 5.3.5：

- 同名 `concept`、同名 `pattern`：$P$ 里**最后一条有效**语句是最终定义；所有引用（不论写在前面还是后面的语句、哪个文件）都用最终定义。被覆盖的定义不求值、不输出、不留任何效果。有效 = 通过了 1.3.9 / 1.3.10 的文法与 7.5.2 / 7.4.2 的静态检查；无效的语句不改变当前定义（1.1.4 第 4 条）。
- 概念名、模式名、最外层 let 名三者异种同名：报错"名字 X 已经用作 concept / pattern / let"，报在 $P$ 里**后出现**的那条上，该语句无效（5.3.5；原型 semantic.setLazy 让 pattern 静默压过同名 concept，本版报错）。
- 输出：`concepts[]` / `patterns[]` 里每个名字**恰出现一次**，条目的 `line` / `file` / `src` / `meta` 是最终定义的；条目在数组里的位置 = 最终定义在 $P$ 里相对其他最终定义的先后（原型 elaborate 对 concept 的 splice + push 等价于此；对 pattern 原型两条都输出，5.5.4 已列）。
- 层级概念（7.4.2）里 `: 上位` 引用的也是上位概念的最终定义：库里的 `concept platform : slab = …` 在场景覆盖 `slab` 之后用新的 `slab`。
- `check`、`style`、`variant` 没有名字，不覆盖：每条都求值、都输出（check）或都施加（style、variant），按 $P$ 的顺序（5.3.6）。

```s3d
import "../lib/semantics.s3d"                 // 库里：concept roof = kind(wedge) & on(volume) | slab & on(wall | column)
concept roof = kind(wedge) & on(kind(box))    // 覆盖：场景里任何压在盒子上的楔形都是 roof；库里引用 roof 的地方也用这条
```

### 7.2.3 语义层可用的集合构件

语义语句（concept、pattern、check、style、variant、外观时机 over）里可以写 1.7.1 的全部选择器形式。下表逐一给出它们在**阶段一**（7.1.2）的值；"节点"指阶段 6 定稿的树里的节点，不含根与皮肤（皮肤在阶段一不存在）。

| 构件 | 值 | 备注 |
|---|---|---|
| `all()` | 全部节点：实体、曲线、容器、repeat 节点与阵列实例、模板实例、副本式节点、副本组、影子、copy 节点、退化节点（1.7.2） | 不含根、不含皮肤 |
| `kind(a, b, …)` | 种类 ∈ 参数、或类型链 ∩ 参数 ≠ ∅ 的节点（1.6.7、4.2.7） | 副本式节点与影子按原件的种类与类型链；不认识的名字得到空集并警告（1.5.6） |
| `#tag` | 标签集合含 tag 的节点（1.6.7） | 影子与副本式节点带原件的标签，所以同时选中 |
| 路径 `a.b.c` | 单元素集合（引用 → 集合） | 可经阵列段、副本段；在阶段一写 `x.skin` 报错"x 中没有子对象或锚点 skin"（皮肤不存在） |
| 通配 `a.*`、`a.*.b` | 1.5.4 | 阶段一不含皮肤 |
| `children(S)`、`descendants(S)` | 各成员的直接子节点 / 全部后代之并 | 含阵列实例、副本组、影子；阶段一不含皮肤 |
| 列表 `[a; b]` | 各项转集合后并 | 项必须是集合类 |
| `S \| T`、`S & T`、`S - T` | 并、交、差（数学集合运算） | 操作数必须是集合类（1.5.5） |
| `S where P` | 筛选（7.3） | |
| 概念名 | 该概念的成员集合（7.4.1） | 失败的概念使读它的语句失败（7.4.3） |
| 模式名 | 模式值（7.5.7）；作集合时是全部角色之并 | |
| `模式名.角色` | 该角色在全部匹配里绑定的节点之并 | 角色不存在报错"模式 X 没有角色 Y（有：…）" |
| 关系谓词 `on(S [, k])` 等七个 | 7.2.4 | |
| 集合值的 `let` | 它的值 | 1.5.8 |
| `count(S)` | 数：成员数；`count(模式名)` 是匹配数 | |

规则：

1. **集合的顺序一律是节点顺序**（1.5.5、1.6.1）：上表每一行的结果、它们的并交差、`where` 的结果、概念的成员、关系谓词的结果，都按节点顺序排列，与书写顺序、求值顺序、操作数顺序无关。原型的并集按操作数拼接（`[...A, ...B]`）、关系谓词按索引的插入顺序；本版统一为节点顺序（7.9.1 列出语料里因此不同的两个概念）。
2. **引用转集合**：一个不带锚点与偏移的对象引用是单元素集合；带锚点或偏移的引用（`a.top`、`a + (0,1,0)`）当集合用报错"X 不是集合（锚点与偏移不能当集合）"。原型 asSet 忽略锚点取其节点；本版报错，因为写了锚点说明作者想要的不是集合。集合值的 `let` 或概念名带锚点（`walls.top`）是 3.2.8 的集合锚点——一个点，可以作 `at=` 等点属性的值；当集合用时同样按本条报错。
3. **集合不是容器**：成员之间没有坐标系；集合作为参照物或点时按成员的总世界包围盒（3.2.8）。
4. **隐藏的节点**在阶段一不存在"隐藏"这件事（隐藏发生在阶段二），所以被变体选中的节点与其他节点一样出现在所有集合里；这正是"变体对语义层不可见"的含义（7.8.4）。
5. 退化节点在集合里，`where` 字段按 7.3.2。
6. `count()` 的参数不是集合类或模式值时报错"count() 需要集合或模式"；`count(引用)` 是 1。

### 7.2.4 关系谓词

七个关系谓词 `on supports against inside contains touching intersects`（1.5.6）读 06-facts.md 的 6.7 定义的**关系索引**，不直接读事实列表：

**索引（6.7.1）。** 由 `facts[]` 里每条 `contact` 事实 $(r, A, B)$ 构造七个有序对集合 $I_{\text{on}}, I_{\text{supports}}, I_{\text{against}}, I_{\text{inside}}, I_{\text{contains}}, I_{\text{touching}}, I_{\text{intersects}}$：关系从对象**上提**到 $A$、$B$ 各自的祖先链（含自身，不含根），但不上提到两者的公共祖先；`on` 同时加入 $I_{\text{supports}}$（反向）与 $I_{\text{touching}}$（双向），`against` 与 `intersects` 各自双向加入并加入 $I_{\text{touching}}$（双向），`inside` 只加入 $I_{\text{contains}}$（反向）、不派生 `touching`；其他提供者的事实不进索引。定义与表都在 6.7.1，本章不重复；本章记

$$R_{\text{rel}}(x) = \{\, y : (x, y) \in I_{\text{rel}} \,\}$$

（节点 $x$ 在表 rel 里的对方集合），7.5.3 的关系约束用同一记法。上提的后果：**容器因其任一部件满足关系而满足关系**——语料 semantics.s3d 的 `street` 与 `watch` 因此 `on(ground)`（参考大纲里它们带 "· on ground"），但 `watch.legs.0.leg on watch.cabin` 不使 `watch` on 自己（`watch` 是公共祖先）；`touching(S)` 是"与 S 有任何接触类事实"（语料里 `rampW intersects slab` 使 `rampW ∈ touching(deck)`，于是 `rampW ∈ bridge`，7.9.1）。原型 Solver.buildRelations 与 6.7.1 逐条相同。

**谓词的值（6.7.2）。** `rel(S, k)`（$k$ 缺省为 1）：

$$\mathrm{rel}(S, k) = \{\, x \in \mathrm{all}() \;:\; \lvert R_{\text{rel}}(x) \cap S \rvert \ge k \,\}$$

按节点顺序排列。$S$ 必须是集合类（否则报错"X() 需要参照集合，如 X(ground)"）；$k$ 必须是与某个整数 $m \ge 1$ 相差不超过 $\varepsilon_{\text{int}}$（3.1.7）的数，取 $m$，否则报错"X() 的第二个参数需要不小于 1 的整数"（1.5.6），该语句无效。原型 relSet 接受任何数（`c >= k`：`on(ground, 0)` 选中索引里有任何 on 项的全部节点，`on(ground, 1.5)` 等价于 2）；本版按 1.5.6 要求整数 $\ge 1$。$S$ 为空时结果为空，不报错。$x$ 与 $S$ 的成员是同一节点时不计（索引里没有 $(x, x)$，6.7.2）。

要点：

- 谓词的结果只含非皮肤节点（阶段一没有皮肤；索引里的节点都在 `all()` 里，6.7.1）；退化节点不是事实的对象（6.2.1），所以不在任何 $R$ 里，也就不在任何谓词的结果里；影子、副本式节点、副本组、被变体选中的节点都按它们的事实进入索引（事实对它们的定义见 6.2.1）。
- `supports` 与 `contains` 是 `on` / `inside` 的反向关系：由 6.7.1 的表，$y \in R_{\text{supports}}(x) \iff x \in R_{\text{on}}(y)$，$y \in R_{\text{contains}}(x) \iff x \in R_{\text{inside}}(y)$；所以 `supports(S)` 是"托着 S 的某个成员（或其后代）"的节点及其祖先（不跨公共祖先）。
- pattern 的关系约束 `L rel M`（7.5.1 第 2 种、7.5.3）读**同一索引**：`a on b`（两个标量角色）成立 ⟺ $b \in R_{\text{on}}(a)$ ⟺ $a \in \mathrm{on}(\{b\})$。
- 谓词**只在语义层与外观时机可用**（1.5.6、5.4.2）；几何时机的选择器里报错"X() 依赖求解后的空间事实，不能用来决定位置 / 几何"（7.2.5 第 5 条）。
- **事实未推导**（`factsSkipped: true`，6.6.4）：索引为空，每个谓词得到空集，每条调用了谓词的语句（含写了关系约束的 pattern）记一条警告"空间事实未推导，X() 为空集"（7.1.4；6.9）。
- 关系索引是事实的函数：两份实现的事实相同（第 6 章的定义与容差）则谓词的结果相同；事实在容差边界上不同时，谓词的差异限于那几对节点及其链。

```s3d
concept pier = kind(cyl) & on(river) & supports(kind(box))   // 立在水里且托着某个盒子（含盒子的祖先，若事实的一方是盒子）
concept deck = kind(box) & on(pier, 2)                        // 至少架在两根 pier 上
concept tree = kind(cyl) & on(ground) & supports(kind(sphere)) | kind(sphere) & on(kind(cyl) & on(ground))
```

### 7.2.5 两个时机的选择器

5.4.2 的表规定了几何时机与语义层 / 外观时机的选择器各能用什么；本节只补充语义层这一侧的精确含义：

1. **所见的树**：阶段 6 定稿后的树——全部几何时机修改已施加（含推迟到阶段 6 的，4.4.4），影子与副本组已生成，copy 已展开，被 drop 的不在；**没有皮肤**。
2. **所见的量**：全部节点的最终变换与包围盒（7.3），全部事实与关系索引（6.7.1、7.2.4），全部概念与模式（惰性），$E_g$（`where mat`，10.5.3；样式不计），元数据（8.2.2）。
3. **皮肤不可选**：本规范里没有任何选择器在皮肤存在之后求值（7.1.3）；因此 concept、pattern、check、style、variant、外观时机 over 的选择集**不可能**含皮肤节点。`descendants()`、通配与直接路径对皮肤的可见性（1.6.4）只在皮肤模板体内的表达式里（over / drop 的选择器、`on=` 等属性，4.7 第 6 条）与工具事后的查询里有意义；皮肤对各种机制可见与否的精确清单在 7.8.4。10-materials.md 的 10.4.3、10.5.3 据此把"样式选中了皮肤"、"`where mat` 的成员在皮肤子树里"记为编译里不会发生的情形（只在皮肤体内 over / drop 的选择器与工具查询里出现）。
4. **style / variant / 外观时机 over 的选择器**与 concept 的表达式在同一个上下文里求值（7.1.2），可以写同样的东西；它们的差别只在语句的效果与空选择的处理（1.7.1：外观时机 over 空选择报错，style / variant 不报）。
5. **几何时机**的选择器按 5.4.2 的构件表，本章只索引、不另定义。可用：路径、通配、`#tag`、`kind()`、`all()`、`children()`、`descendants()`、列表、集合运算、`where` 里的 `kind` / `name` / `mat` / 元数据键、只作引用比较（`it == a`）或作集合的 `it`、`count(S)`（$S$ 由这些静态构件组成）。不可用：`where` 里的 `w h d x y z top bottom`，任何对象或 `it` 的锚点 / 度量 / 分量 / 坐标后缀（`it.top.y`、`it.w`、`a.top`），关系谓词，概念名 / 模式名 / `模式名.角色`，以及读到了这些的 `let`。文案两种：字段、锚点、概念 / 模式与读了它们的 `let` 报 1.7.4 的"几何时机的选择器只能用静态量（路径、#标签、kind()、name / 元数据 / mat）"；关系谓词报 1.5.6 的"X() 依赖求解后的空间事实，不能用来决定位置 / 几何"。判定是静态的：求值前对表达式树检查，不依赖成员集合，每条语句至多一条（5.4.2 第 1 条）；裸标识符在几何时机的环境里解析失败时，若它是 $P$ 里某个 concept / pattern 的名字则报时机错误，否则报"找不到对象 X"（5.4.2 第 2 条）；被几何时机选择器读到的 `let` 按 1.5.8 归属该 `let` 语句（5.4.2 第 6 条）。

## 7.3 `where` 的字段在语义层的定义

### 7.3.1 字段表

`S where P` 对 $S$ 的每个成员 $m$ 在 where 帧里求 $P$（1.5.5、1.7.3）。语义层（阶段一）里字段的精确取值：

| 字段 | 类型 | 定义 |
|---|---|---|
| `w` `h` `d` | 数 | $m$ 的**局部包围盒**沿 $m$ 局部 $x$、$y$、$z$ 的边长（2.1.3）。实体：第 2 章各节的盒；容器：2.6 / 3.7.1 的包络（group 有 `envelope` 时用它；布尔容器按 2.5.4；repeat 节点是全部非后置实例之并；阵列实例是其子节点之并）；曲线：采样折线的盒（2.3.8）；影子：原件（或孪生体，4.4.4）的局部包围盒；副本式节点 $R$：原件 $A$ 的局部包围盒；副本组：影子之并。与 `m.w` / `m.h` / `m.d`（3.2.6）相同，**不随朝向变**：`box a size=0.3,4,0.3 roll=90` 的 `h` 仍是 4 |
| `x` `y` `z` | 数 | $m$ 的**世界包围盒**（3.1.6：局部包围盒经世界变换后取 AABB）的中心的世界坐标 |
| `top` `bottom` | 数 | $m$ 在世界里占据的 $y$ 范围的上端 / 下端：$m$ 是**实体**（1.1.2 的 12 种，含副本式实体与影子实体）时取**紧包围盒**（2.1.8；按真实形状，所以转过的圆柱、倾斜的板不被 AABB 放大）的 $y_{\max}$ / $y_{\min}$；其他节点（容器、布尔容器、曲线、副本组、阵列实例、repeat 节点）取世界包围盒的 $y_{\max}$ / $y_{\min}$。$\text{top} - \text{bottom}$ 是"在世界里竖直方向占多高"，语义库用它判断竖放还是平放 |
| `kind` | 字符串 | 1.6.7 的种类名（模板实例是最派生的模板名；副本式节点与影子是原件的种类——原件是模板实例时就是那个模板名。原型 evalAst 对副本式节点与影子取 `m.template ?? K(m)`，原件是模板实例时得到 `group`，7.9.4） |
| `name` | 字符串 | 1.6.7 的名字（匿名为空串；影子取原件的名字） |
| `mat` | 字符串或缺失 | 10.5.3：$E_g(m)$ 的 name；内置材质为缺失；曲线为缺失 |
| `it` | 引用 | $m$ 本身，不带锚点；可取锚点、度量与分量（`it.top.y`、`it.w`），可与引用比较（`it == a`）、可作集合（`descendants(it)`） |
| 元数据键 | 元数据值或缺失 | 8.2.2（影子读原件的） |

规则：

- 字段遮蔽同名的元数据键、let、参数与对象（where 帧最内层，1.7.3）；要读名为 `w` 的元数据键，没有写法（8.1.4 的警告）。
- 比较与运算按 1.5.5、8.2.3；`kind == box`、`name == a`、`mat == steel` 右侧裸标识符按名字字面量。`kind ~ /^(box|cyl)$/`、`name ~ /^tank/` 合法。
- 字段的值在阶段一对每个成员各算一次，与成员在哪条语句、哪个集合里无关；实现**可以**缓存（值是节点的函数）。
- `where` 的条件必须得到布尔（否则报错"where 的条件需要真假值"，该语句无效）；条件为缺失值时该成员不选中、不报错（1.5.5）。

```s3d
concept member = solid_kinds where max(w,h,d) > 4 * (w+h+d-max(w,h,d)-min(w,h,d))   // 细长体，任意朝向
concept column : member = where max(w,h,d) > 2.5 * metre and top - bottom > 0.95 * max(w,h,d)  // 竖着的
concept beam   : member = where top - bottom < 0.5 * max(w,h,d)                                  // 横着的
check "每栋房子都有屋顶" kind(house) where count(descendants(it) & roof) == 0
```

### 7.3.2 缺失值与退化节点

| 成员 $m$ 是 | `w h d` | `x y z` | `top bottom` | `kind` `name` | `mat` | 元数据 |
|---|---|---|---|---|---|---|
| 退化节点（1.1.4） | 0, 0, 0（零盒） | 它的世界原点（零盒的中心） | 都等于世界原点的 $y$ | 照常 | 照常（10.3.2：退化节点有有效材质） | 照常 |
| 空容器（3.7.4） | 0, 0, 0 | 容器原点 | 原点的 $y$ | 照常 | 照常 | 照常 |
| 曲线 | 采样折线盒的边长（闭合或退化曲线按 2.3.8） | 世界盒中心 | 世界盒 | 照常 | **缺失** | 照常 |
| 被变体选中的节点（阶段一尚未隐藏） | 照常 | 照常 | 照常 | 照常 | 照常 | 照常 |
| 影子 | 原件（孪生体）的局部盒 | 自己的世界盒 | 实体影子按自己世界变换下的紧包围盒 | 原件的 | 按影子的链（10.3.1） | 原件的 |
| 没有该元数据键的节点 | — | — | — | — | — | **缺失** |

缺失值的运算规则见 1.5.5 与 8.2.3：任何比较、`~`、逻辑运算遇到缺失为假，所以 `all() where mat == steel` 不选中内置材质的节点也不报错；`all() where not (mat ~ /./)` 选中 `mat` 缺失的节点（10.5.3 的例子）。把缺失值当集合、点、数用（`count(fit)`、`fit + 1` 作条件）报错"元数据键 X 缺失"（1.5.5：算术得到缺失，条件为缺失则不选中；只有需要集合 / 点 / 属性值时报错）。

## 7.4 concept

### 7.4.1 定义与求值

语法见 1.3.9。`concept 名字 = 表达式` 定义一个**具名的集合**：

- **求值**：表达式在语义上下文（7.1.2）里求值；结果必须是集合类（1.5.5），否则报错"concept X 的值需要集合，得到 Y"（Y 按 1.5.2 的显示规则），该概念**失败**（7.4.3）。集合类的值转成集合（7.2.3 第 2 条）；**成员按节点顺序**。
- **时机**：阶段一，惰性：第一次被读到（被另一个概念、模式、检查、样式或变体的表达式引用，或被 7.1.2 第 5 步强制）时求值一次，成功的值缓存。
- **纯**：值只依赖阶段一的量与其他语义名的值；不依赖求值顺序、不依赖它被引用的次数、不依赖样式与变体。
- **成员可以是任何节点**：实体、曲线、容器、阵列实例、影子、副本式节点、copy 节点、退化节点（7.2.3）。
- **空集合法**，不报错、不警告。
- 概念不是节点、不是容器：没有坐标系、没有自己的包围盒；作参照物或点时按成员的总包围盒（3.2.8）；不能被 `over` / `drop` 选中（几何时机看不见它，5.4.2），不能被 `copy`。

```s3d
let solids = kind(box, cyl, cone, sphere, wedge)
concept pier  = kind(cyl) & on(river) & supports(kind(box))
concept lamp  = (kind(cyl) & on(deck) where h >= 2) | kind(sphere) & on(kind(cyl) & on(deck))
concept building = kind(house)                       // 模板就是使用者定义的类型：含 chimney_house 的实例（4.2.7）
concept imported = all() where src ~ /./             // 带 src 元数据的全部节点（8.2.2）
```

### 7.4.2 层级概念

`concept 名字 : 上位 = …`（1.3.9 的第二种形态）定义一个**下位概念**，等价于：

| 写法 | 等价于 |
|---|---|
| `concept N : U = where P` | `concept N = U where P` |
| `concept N : U = E`（`=` 右边不以 `where` 开头） | `concept N = U & E` |

规则：

1. `U` 必须是**概念名**——$P$ 里某条通过了 1.3.9 的文法与 5.3.5 的异种同名检查的 `concept` 语句的名字（可以定义在后面或别的文件里；N 求值时读到的是 U 的最终定义）。判定**只看名字是否存在**，不看那条语句自己是否通过本条检查，所以判定没有循环：`concept a : b = …` 与 `concept b : a = …` 都合法登记（求值时按 7.4.3 失败）；`concept b : nothing = …` 无效而 `concept a : b = …` 合法——若 `b` 没有别的有效定义，a 求值时读 `b` 按 7.2.1 解析，报"找不到对象 b"而失败。`U` 不是概念名（是模式名、let、对象名或不存在）时报错"上位概念 U 没有定义"，这条 `concept` **无效**（不登记、不改变 N 的当前定义，1.1.4 第 4 条）。原型 makeStmt 把 `U` 当普通路径求值（`concept E : ground = where h > 0` 得到对象 ground 的单元素集合）；本版要求 U 是概念：层级是概念之间的关系，`parent` 字段才有意义。判定在阶段一第 4 步（语义名字空间折叠完成后）做。
2. `U` 等于 `N` 自己：按第 1 条，U 的最终定义就是这条语句，合法登记，但求值时读到自己而**失败**（7.4.3："N 循环引用了自己"）。
3. 由等价写法可知 $N \subseteq U$ 恒成立（两种形态都是 U 的子集）。层级只有这一层含义：`parent` 字段输出 `U`（7.4.4），`kind()`、`#tag`、`where` 都不读它，没有"N 的成员自动算作 U 的成员"之外的推理（那是集合包含本身）。多级层级（`concept a : b`、`concept b : c`）同理逐级成立。
4. 覆盖：`U` 被后面的层重定义时，N 用新的 U（7.2.2）；N 自己被重定义为不带 `: U` 的形式时，`parent` 为 `null`。

```s3d
concept slab     = solid_kinds where min(w,h,d) < 2.5 * metre and …
concept platform : slab = (on(all()) | supports(all())) - terrain      // ≡ slab & ((on(all()) | supports(all())) - terrain)
concept column   : member = where max(w,h,d) > 2.5 * metre and top - bottom > 0.95 * max(w,h,d)   // ≡ member where …
```

### 7.4.3 相互引用、循环与失败的传播

概念、模式、检查、样式与变体的表达式可以引用任何概念与模式，不论定义的先后与所在文件（7.2.2）。求值用一个**正在求值的名字栈**：

1. 读到语义名 $X$：$X$ 已有缓存的值 → 用它；$X$ 在栈上 → 这次读取**失败**，错误文案"X 循环引用了自己"；否则把 $X$ 压栈，求 $X$ 的表达式（概念）或匹配（模式），弹栈；成功则缓存值。
2. 一个表达式的任何子表达式失败，整个表达式失败，文案不变（最先遇到的那个失败）。`and` / `or` 不短路（1.5.5），所以 `false and 失败的概念` 也失败。
3. **失败不缓存**：失败的名字下次被读到时重新求值（再次失败，文案由那次求值决定）。每条**语句**（concept、pattern、check、style、variant、外观时机 over）独立求值，自己失败时**各报一条**错误，归属该语句的文件与行（5.2.5），文案是它遇到的失败文案。
4. 失败的后果：concept → 成员为空集，输出带 `error`（7.4.4）；pattern → 匹配为空，输出带 `error`（7.5.8）；check → `ok: false`，输出带 `error`（7.6.2）；style / variant → 语句无效（不作用于任何节点；7.7.2、7.8.2）。
5. 一个名字成功求值过就不会再失败（值已缓存），所以"失败"是语句级的局部事件，不污染场景的其他部分。

后果举例（与原型 Env.lookup 的 busy 标记行为一致，7.9.4 的小例子核对过）：`concept A = B | #post`、`concept B = A & kind(box)`、`concept C = A | c`——求 A：A 压栈 → 读 B → B 压栈 → 读 A（在栈上）失败"A 循环引用了自己" → B 失败 → A 失败，A 报错；求 B：B 压栈 → 读 A → 读 B 失败"B 循环引用了自己" → B 报错；求 C：读 A → 读 B → 读 A 失败 → C 报错"A 循环引用了自己"。三条各报一条，D 等无关概念不受影响。

与 `let` 的循环（"X 循环引用了自己"，1.5.8）用同一个栈：`let` 在语义层被读到时也压栈。

### 7.4.4 成员顺序与输出形状

- **成员顺序** = 节点顺序（1.6.1 的先序深度优先）。
- **`concepts[]`**：每个最终定义一个条目，按 7.2.2 的位置，形状
  ```
  { "name": 字符串, "parent": 字符串 | null, "line": 数, "file": 字符串, "src": 字符串, "members": [路径…], "meta": {…} [, "error": 字符串] }
  ```
  `parent` 是 `: 上位` 的名字（没有则 `null`）；`src` 是 `=` 右边的源码文本（首尾空白去掉；层级形态是 `=` 右边原样的文本，例如 `where w > 1.6`）；`members` 按节点顺序；`meta` 按 8.4.3；`error` 只在失败时出现，此时 `members` 为 `[]`。
- **节点标注**：`nodes[]` 每个条目的 `concepts` 字段是一个字符串数组，按下面的顺序、**不重复**：
  1. 对 `patterns[]` 里的每个模式（按输出顺序），对它的每个角色（按声明顺序），若该节点在该角色的任一匹配里（7.5.7 的 `模式.角色` 集合），追加 `"模式.角色"`；
  2. 对 `concepts[]` 里的每个概念（按输出顺序），若该节点是成员，追加概念名。
  皮肤节点的 `concepts` 总是 `[]`（阶段一没有皮肤）；被隐藏的宿主与它的后代照常标注。原型 compileOnce 按同样的"模式先、概念后"顺序追加，但模式内按匹配的绑定顺序、且不去重（一个节点在两个匹配里扮演同一角色会出现两次）；本版去重、按角色声明顺序。语料里每个节点在每个模式里至多出现一次，输出相同（7.9.1）。

```json
{ "name": "deck", "parent": null, "line": 79, "file": "examples/semantics.s3d", "src": "kind(box) & on(pier, 2)", "members": ["slab"], "meta": {} }
```

## 7.5 pattern

### 7.5.1 角色与约束

语法见 1.3.10：`pattern 名字(角色, 集合角色*, …) { 约束行… }`。

- **角色**：每个角色是一个标识符；带 `*` 的是**集合角色**（匹配到一个节点集合），不带的是**标量角色**（匹配到恰好一个节点）。至少一个角色；角色名不得重复、不得是保留名（1.6.9）。**标量顺序** = 标量角色在签名里的先后，记 $r_1, \dots, r_s$；集合角色记 $T_1, \dots, T_t$（签名顺序）。
- **约束**三种（1.3.10 的判定顺序）：
  1. **域约束** `角色 in 表达式`：限定该角色的候选集。每个角色**至多一条**；没有的角色候选集是 `all()`。同一角色第二条 `in` 报错"角色 X 的 in 约束重复"，该 pattern 无效（原型 makePattern 让后一条覆盖前一条；本版报错）。
  2. **关系约束** `表达式 关系词 表达式`，关系词是七个谓词名之一（`on supports against inside contains touching intersects`）。原型 makePattern 的关系词表不含 `intersects`（`a intersects b` 被当作布尔表达式解析而失败）；本版七个都接受（1.3.10 已定）。
  3. **布尔约束**：一个表达式，求值必须得到布尔。
- 一个 pattern 可以没有任何约束（只有角色）：每个标量角色的候选集是 `all()`，匹配是全部不重复节点的排列——会立刻触及 7.5.6 的上限。约束行里不接受元数据（8.1.2）。

```s3d
pattern home(body, roof*, door) {
  body in kind(box) where h > 2
  roof in kind(wedge)
  door in kind(box) where h < 2.5 and d < 0.5
  roof on body
  door against body
}
```

### 7.5.2 角色引用与静态检查

约束表达式里的裸标识符或路径首段若等于某个角色名，就是**角色引用**（角色绑定帧在语义帧之内，7.2.1：角色名遮蔽同名的概念、let 与对象）。一条约束**引用的角色集合** $\mathrm{deps}(c)$ = 它的表达式树（关系约束取两侧之并）里出现的角色名集合，包括 `where` 条件、函数参数、列表项、坐标后缀里的；`模式名.角色` 这种路径不算角色引用（它的首段是模式名）。

登记时（阶段一第 4 步，在最终定义上）做下面的静态检查；任一不满足时报错，这条 `pattern` **无效**（不登记、不改变同名的当前定义）：

1. **域的引用**：标量角色 $r_i$ 的域只能引用 $r_1 \dots r_{i-1}$（更早的标量角色）；集合角色的域只能引用标量角色。违反报错"角色 X 的 in 不能引用 Y（只能引用更早声明的标量角色）"。原型在匹配时才发现（未绑定的角色名退化成字符串后报"需要集合（…），得到 y"）；本版静态报错。
2. **关系约束里的集合角色**：$\mathrm{deps}(c)$ 里的集合角色至多一个；有一个时，它必须**单独**构成关系的一侧（那一侧的表达式就是该角色名本身）。违反报错"一条关系约束里最多一个集合角色，且它要单独站在关系的一边"（原型 matchPattern 相同，但在匹配时报）。
3. **布尔约束**可以引用任意角色（含多个集合角色）。
4. 关系词必须是七个谓词名之一（文法已保证）；`in` 左边的名字必须是角色（1.3.10：否则报错"X 不是这个 pattern 的角色"）。

不是角色的名字按 7.2.1 在匹配时解析（概念、模式、let、对象）；解析失败使匹配失败（7.5.8）。

### 7.5.3 约束的语义

一个**绑定** $\beta$ 是从角色到值的部分映射：标量角色 → 一个节点；集合角色 → 一个节点集合（节点顺序）。约束在绑定 $\beta$ 下的求值上下文 = 语义上下文（7.1.2）加一个最内层的**角色绑定帧**：角色名 → $\beta$ 的值（标量角色是不带锚点的引用，集合角色是集合）。

- **域** $\mathrm{dom}(r, \beta)$：角色 $r$ 的 `in` 表达式在 $\beta$ 下求值，结果必须是集合类（否则报错"角色 r 的 in 需要集合，得到 Y"，**整个模式失败**，7.5.8——与关系约束、布尔约束的求值失败同一处理，不是"该候选不成立"），转成集合按节点顺序；没有 `in` 时是 `all()`。
- **关系约束** `L rel M` 在 $\beta$ 下成立，当且仅当 $\exists\, x \in X,\ y \in Y:\ y \in R_{\text{rel}}(x)$（6.7.1 的关系索引，7.2.4 的记法；事实未推导时索引为空，约束不成立并给 7.1.4 的警告），其中 $X$、$Y$ 是两侧的集合：一侧是标量角色名 → 该角色绑定的单元素集合；是集合角色名（整侧）→ 7.5.4 规定它逐成员判定；其他表达式 → 在 $\beta$ 下求值并转成集合。注意它与谓词 `rel(S)` 的关系：`a on b`（两个标量角色）成立 ⟺ $a \in \mathrm{on}(\{b\})$。
- **布尔约束**在 $\beta$ 下求值必须得到布尔，否则报错"模式 X 的约束需要真假值，得到 Y"，整个模式失败。原型 asBool 把非空集合与非零数当真；本版按 1.5.5 只接受布尔。

### 7.5.4 匹配算法

匹配是对标量角色按标量顺序做**深度优先搜索**，集合角色在全部标量角色绑定后一次性确定。算法是定义的一部分：匹配的集合、每个匹配的内容、匹配的输出顺序、步数都由它唯一确定。

**约束的检查点。** 对每条非域约束 $c$：

- $c$ 的 deps 含集合角色 → **收尾约束**；其中关系约束按它含的那个集合角色 $T$ 归入 $T$ 的**成员规则** $\mathrm{rules}(T)$；布尔约束归入**收尾布尔约束**。
- 否则 $\mathrm{depth}(c) = \max\{\, i : r_i \in \mathrm{deps}(c) \,\}$；$c$ 在第 $\mathrm{depth}(c)$ 个标量角色绑定之后立即检查。deps 为空的约束（关系约束或布尔约束都可能，例如 `kind(box) on ground`、`count(kind(box)) > 3`）记 $\mathrm{depth}(c) = 0$，是**收尾约束**：在 finish 时检查，不是任何集合角色的成员规则。

**搜索。**

```
matches ← 空列表；keys ← 空集合；steps ← 0；truncated ← false
dfs(i, β):
  steps ← steps + 1
  若 steps > STEP_MAX：整个模式失败（7.5.6）
  若 |matches| ≥ MATCH_MAX：truncated ← true；返回
  若 i > s：finish(β)；返回
  对 dom(r_i, β) 的每个成员 c（节点顺序）：
    若 c 已绑定给 β 里的某个标量角色：跳过            // 一个节点不能同时扮演两个标量角色
    β' ← β ∪ {r_i ↦ c}
    若 depth 为 i 的每条约束在 β' 下成立：dfs(i + 1, β')
finish(β):
  used ← β 里全部标量角色的节点
  对每个集合角色 T_j（签名顺序）：
    β[T_j] ← { t ∈ dom(T_j, β) : t ∉ used 且 rules(T_j) 的每条关系约束在 β 下、把 T_j 的那一侧换成 {t} 时成立 }
  若某条收尾约束在 β 下不成立：返回                   // 收尾布尔约束 + deps 为空的关系约束；成员规则不在此重查
  key ← β 里全部角色绑定的全部节点的路径，去重后按码点排序、用 "|" 连接
  若 key ∈ keys：返回                                 // 7.5.5 去重
  keys ← keys ∪ {key}；matches 追加 β
dfs(1, ∅)
```

规则与说明：

- 标量角色的域 $\mathrm{dom}(r_i, \beta)$ 在每次进入该层时按当时的 $\beta$ 求值（它可以引用更早的标量角色，7.5.2）；不引用角色的域每次结果相同，实现**可以**缓存。
- 集合角色的成员**可以为空**（匹配仍成立，除非收尾布尔约束如 `count(T) >= 2` 排除它）；两个集合角色可以有共同成员（只排除标量角色占用的节点）；集合角色的成员规则里关系的另一侧若也是表达式，按 7.5.3 求值。
- 深度为 $i$ 的约束在 $r_i$ 绑定后立刻检查并剪枝；deps 为空的约束（`count(kind(box)) > 3`、`kind(box) on ground`）在 finish 时检查（原型 matchPattern 的 `final` 列表相同：小例子 07/t8.s3d 里 `pattern p(x, y) { … kind(box) on ground }` 对每个完整绑定都检查这条关系约束）。
- 关系约束与布尔约束的求值失败（名字解析、类型错误）使整个模式失败（7.5.8），不是"该候选不成立"。
- `steps` 从 1 起计（`dfs(1, ∅)` 是第 1 步）；每个通过了本层约束的部分绑定使 steps 加一；被约束拒绝的候选不计步。
- 匹配的**输出顺序** = 进入 matches 的顺序（标量角色按节点顺序的字典序）。
- 算法与原型 matchPattern 相同（含步数的计法、去重键、集合角色的确定方式）；差别只在域的顺序（节点顺序，7.2.3）与 7.5.6 的上限处理。

```s3d
pattern crossing(deck, piers*, ramps*) {   // 标量：deck；集合：piers、ramps
  deck in kind(box)                        // dom(deck)
  piers in pier                            // dom(piers)：概念 pier
  ramps in kind(span)
  deck on piers                            // rules(piers)：piers = { t ∈ pier : deck on t }
  ramps touching deck                      // rules(ramps)：ramps = { t ∈ kind(span) : t touching deck }
  count(piers) >= 2                        // 收尾布尔约束
}
```

### 7.5.5 去重

两个绑定的**节点集合**（全部角色、全部成员合在一起，不看谁扮演哪个角色）相同时是同一个匹配，只保留**先发现**的。所以：

- 标量角色互换的两个绑定算一个（`pattern gate(post1, post2, lintel)`：post1 = p1 / post2 = p2 与 post1 = p2 / post2 = p1 只算一个）；
- 节点集合相同、角色分配不同的两个绑定也只算一个（例如一个盒子在一个绑定里是 body、在另一个里是 door，而其余节点相同）——这是定义的一部分，写模式时若要区分，用域约束把角色分开。
- 节点集合不同的绑定各算一个，即使它们共享大部分节点。

去重键是路径的排序串，与路径的比较规则（1.6.10）一致；节点顺序不参与去重。

### 7.5.6 搜索上限

| 常量 | 值 | 含义 |
|---|---|---|
| $\text{STEP\_MAX}$ | 200 000 | 一个模式的 `steps` 上限 |
| $\text{MATCH\_MAX}$ | 500 | 一个模式保留的匹配数上限 |

- `steps` 超过 $\text{STEP\_MAX}$：这个模式**失败**（7.5.8），报错"模式 X 的搜索空间太大，请用 in 缩小各角色的范围"，匹配为空；读到它的语句失败（7.4.3）。
- 匹配数达到 $\text{MATCH\_MAX}$ 后搜索停止：保留已发现的前 500 个（按发现顺序），输出照常；7.5.4 的 `truncated` 为真（匹配数已达上限后又进入了一次 `dfs`，即还有候选未检查）时另给**警告**"模式 X 的匹配超过 500 个，只保留前 500 个"（1.10.3；归属该 pattern 语句）；恰好 500 个匹配且搜索自然结束（`truncated` 为假）不警告。停止的方式就是 7.5.4 的算法：上限到达后每次 `dfs` 调用立即返回但仍计一步，外层循环照常走完（原型 matchPattern 相同：小例子 07/t7b.s3d 101 个候选、3 个标量角色，得到 500 个匹配、steps = 796）。原型静默截断；本版加警告，因为被截断的结果不是模式的真值，依赖它的 check 可能误判。
- 两个上限都是 7.5.4 算法的一部分，与节点顺序一起使结果可复现；实现**不得**用别的上限或墙钟预算。

### 7.5.7 模式值

一个模式名在表达式里的值是**模式值**（1.5.7），由匹配列表构成：

| 用法 | 值 |
|---|---|
| `count(P)` | 匹配数（保留的） |
| `P` 作集合（并交差、`where`、关系谓词的参数、concept 的值、check 的值） | 全部角色在全部匹配里绑定的节点之并，节点顺序 |
| `P.r` | 角色 `r` 在全部匹配里绑定的节点之并（标量角色：每个匹配一个节点；集合角色：成员），节点顺序 |
| `P.z`（z 不是角色） | 报错"模式 P 没有角色 z（有：x、y）" |
| `P.r.top`、`P.r.w` 等 | 报错"模式 P 没有角色 r.top（有：…）"：模式值后面只能跟**一个**角色名（1.6.5 第 1 步；原型 evalPath 相同）。要取角色集合的锚点或度量，先用 concept 给它命名（`concept lintels = gate.lintel`，然后 `lintels.top`，3.2.8） |
| `P == Q`、`P != Q` | 按集合比较（1.5.5） |
| `P` 作点、参照物 | 作集合处理（3.2.8；空集报错"集合是空的，不能当参照物"） |

模式失败时（7.5.8）读它的任何用法都失败。

```s3d
concept lintels = gate.lintel
check "每座房子都匹配到 home 模式" count(home) == count(kind(house))
style enclosure.walls color=#ddccaa
```

### 7.5.8 输出形状与节点标注

- **`patterns[]`**：每个最终定义一个条目，按 7.2.2 的位置：
  ```
  { "name": 字符串, "line": 数, "file": 字符串, "roles": ["deck", "piers*", …], "matches": [ { 角色: 路径 | [路径…], … }, … ], "meta": {…} [, "error": 字符串] }
  ```
  `roles` 按签名顺序，集合角色带 `*`；`matches` 按发现顺序，每个匹配是对象：标量角色 → 路径，集合角色 → 路径数组（节点顺序），键按签名顺序。
- **失败**（静态检查之外的求值错误：约束里的名字解析、类型错误、步数超限、读到失败的名字）：`matches: []`、`roles` 照常、带 `error`，并在 `errors[]` 报一条（归属 pattern 语句；文案就是失败文案，不附"第 N 行"前缀——行在 `line` 字段里；原型对集合角色规则那条错误把约束行号写进文案）。原型 compileOnce 对失败的模式输出 `roles: []`；本版 `roles` 照常（7.9.4）。静态检查失败的语句**无效**：没有条目（它不是最终定义；若它是该名字唯一的语句，这个名字不存在）。
- **节点标注**：7.4.4 第 1 条（`模式.角色`）。
- 原型两条同名 pattern 都输出；本版只有最终定义（5.5.4 已列）。

## 7.6 check

### 7.6.1 求值与通过条件

语法见 1.3.11：`check ["说明"] 表达式`。表达式在语义上下文里求值（阶段一第 6 步，按 $P$ 的顺序）；结果按种类判定：

| 结果 | `ok` | `violators` |
|---|---|---|
| 布尔 | 该值 | `[]` |
| 集合类（集合、引用、列表、模式值） | 转成集合后**为空**则 `true`，否则 `false` | 该集合的成员路径，节点顺序 |
| 其他（数、字符串、向量） | `false` | `[]`；并报错"check 的结果需要真假值或集合，得到 X"（7.6.2） |

"集合为空或条件为真即通过"：检查用集合表达"违反规则的对象"，用布尔表达"必须成立的条件"。原型 asBool 把非零数与字符串 `"true"` 当真（`check count(#post)` 在有柱子时通过）；本版只接受布尔与集合类——`count(#post)` 作为检查没有确定的含义，要写 `count(#post) > 0`。

```s3d
check "桥墩数量与变量一致" count(pier) == n_piers           // 布尔
check "每栋房子都有屋顶" kind(house) where count(descendants(it) & roof) == 0   // 集合：违例者
check "高脚屋的每根桩都落地" stilt - on(ground)
check "没有悬空的实体" solids - on(all()) - ground
check count(#post) >= 2                                      // 没有说明：message 是表达式原文
```

### 7.6.2 错误

- 表达式求值失败（名字解析、类型错误、读到失败的概念或模式、`where` 条件不是布尔、结果种类不合法）：该条目 `ok: false`、`violators: []`、带 `error`（失败文案），**并且**在 `errors[]` 报一条同样文案的错误，归属该 check 语句（1.1.4 第 4 条、5.2.5）。原型 compileOnce 只把文案写进 `checks[].error`、不进 `errors[]`；本版两处都记，使"编译有没有错误"只看 `errors[]` 就够。
- 一条 check 的失败不影响其他 check 与其他语句。
- 本节不定义警告；一条 check 可能带的警告只有 6.9 的"空间事实未推导，X() 为空集"（事实未推导时调用了关系谓词，7.1.4）。

### 7.6.3 输出形状

`checks[]`：每条 `check` 语句一个条目（全部保留，不去重，按 $P$ 的顺序，5.3.6）：

```
{ "line": 数, "file": 字符串, "message": 字符串, "ok": 布尔, "violators": [路径…], "meta": {…} [, "error": 字符串] }
```

`message` 是说明字符串；没有说明时是表达式的源码文本（首尾空白去掉，1.3.11）。

## 7.7 style

### 7.7.1 语句与材质值

语法见 1.3.12：`style 选择器 { mat=材质名 | color=颜色 | ~k=v }`。下面的检查在阶段一第 4 步做（7.1.2；材质表在阶段 2 结束后定稿，所以 `mat` 引用的材质可以定义在 style 之后、别的文件里）：

- 属性只能是 `mat` 与 `color`，各至多一次，至少一个；其他键报错"style 只支持 mat 和 color"，整条语句无效（10.5.1、10.7）。没有任何属性报错"style 需要 mat 或 color"，语句无效。
- `mat` 的值是材质名字面量（裸标识符或字符串，1.4.2；原型不接受字符串），必须在材质表里（10.1.3）；不在报错"未定义的材质 X"，整条语句无效（1.10.2 的材质错误）。
- `color` 的值是颜色字面量（1.2.7）；不合法报错"颜色写成 #rgb、#rgba、#rrggbb 或 #rrggbbaa"，语句无效。
- 元数据按 8.3.8（属于该语句，不输出）。

样式动作的效果（`mat` 整体替换、`color` 只换颜色与 alpha 给出的 opacity；同一条里 `mat` 先于 `color`）由 10.3.3 定义，本章不重复。

### 7.7.2 选择集与作用范围

- **选择集** $S$：选择器在阶段一第 7 步、语义上下文里求值，必须是集合类（否则报错"style 的选择器需要集合，得到 X"，语句无效）；读到失败的概念或模式时语句无效（7.4.3）。$S$ 为空合法（不报错、不警告）。
- **作用范围** = $S$ 的成员及其**全部后代**（场景树意义上；皮肤子树除外，10.4.3），在阶段二施加（7.1.3 第 3 步）。成员可以是 `all()` 里的任何节点：实体、曲线（曲线没有材质，对它本身无效、对它的后代——曲线没有后代——无效）、容器、阵列节点与实例、模板实例、副本式节点、副本组、影子、copy 节点、被变体选中的宿主（它仍被样式选中：皮肤经 $E(N)$ 继承，10.4.3）、退化节点（有有效材质，无条目）。
- 副本的规则见 10.3.3：原件被选中时影子跟随；直接选中副本（式节点、副本组、影子）的样式与原件的样式按语句顺序一起应用。
- 选择集在阶段一确定并冻结：样式不改变任何选择器能读到的量（`where mat` 读 $E_g$，10.5.3），所以样式之间没有依赖，`style all() where mat == plain mat=stone` 之后 `style all() where mat == plain color=#f00` 仍选中原来是 plain 的节点。

### 7.7.3 多条 style 的顺序与优先级

- 多条 style（含登记为 style 的外观时机 over）按 $P$ 的顺序依次施加（5.3.6）；同一节点被多条选中（直接或经祖先）时**后写的赢**：带 `mat` 的后一条整体替换前一条的结果，只带 `color` 的后一条只换颜色（10.3.3）。
- **样式压过节点自身的 `mat=` / `color=`**（D8 的 "style > color > mat > 父级 > default > 内置"，10.3.4）：任何作用于节点或其祖先的样式都压过该节点及其祖先链上的自有外观属性；节点自己写了 `mat=brick`、祖先被 `style … mat=stone` 选中，结果是 stone。要让某些部件不受样式影响，别让样式选中它们或它们的祖先（用 `where`、`-`），或在其后再写一条样式。
- 祖先与后代同时被选中：两条都在作用范围内，按语句顺序；没有"更具体的赢"的规则。
- 样式对皮肤：不直接作用（10.4.3）；皮肤部件自己写的 `mat` 优先，其余经终点 $E(N)$ 得到宿主的样式结果（语料：`style deck mat=wood` 使 `slab.skin.pl.*.plank` 为 wood）。
- `style` 没有输出条目（8.4.3）；它的效果只体现在 `items[]` 的 `material`（10.6）。

```s3d
style pier mat=stone
style railing|lamp mat=metal
style tree mat=leaf
style kind(cyl)&tree mat=wood        // 后写的赢：树干 wood、树冠 leaf
style all() where src ~ /^merged_/ color=#ffcc00   // 元数据（8.2.2）
```

### 7.7.4 与外观时机 over 的等价

4.5.1：最外层、无块、无换形、至少一个属性、没有 `use` 时属性键 ⊆ {mat, color}（有 `use` 时其余键是 `mat` / `color` 或模板参数）的 `over` 是外观时机的；没有 `use` 时它在阶段 2 被登记为一条 **style**，`over 选择器 mat=… color=…` 与 `style 选择器 mat=… color=…` 在 7.7.1–7.7.3 的每一条上都相同（选择器的求值上下文、作用范围、顺序、材质效果、无输出条目），只有两处差别：

1. **空选择**：登记为 style 的 `over` 选择集为空时按 1.7.1 报错"X 没有选中任何对象"，语句无效——over / drop 在**两个时机**都报（几何时机的在 4.5.2，外观时机的在此；5.4.2 第 7 条、7.1.4）；`style` 不报（空选择合法，7.7.2）。原型 compileOnce 对两者都不报；本版按 1.7.1。
2. **错误的归属**：外观时机的 over 只允许 `mat` / `color` / `use`（4.5.1 第 4 条已保证键合法），所以不会出现 1.4.8 的"X 没有属性 k"；`mat` 未定义同样报"未定义的材质 X"，`color` 不合法同样报 7.7.1 的文案；差别只在错误携带的语句种类与首行（1.10.1：是 over 而不是 style）。

写在块里、带块、带换形或混写其他键的 `over mat=…` 是几何时机的（4.5.1）：它写节点的自有外观属性，参与 $E_g$，**会被样式压过**（10.5.2）。所以同一个 `color=#f00`，写成最外层的 `over a color=#f00` 是样式（压过一切自有属性），写成 `group g { over a color=#f00 }` 是属性（会被任何选中 a 或 g 的样式压过）。

## 7.8 variant

### 7.8.1 语句与属性

语法见 1.3.13：`variant 选择器 use=模板名 { 参数=值 | mat=材质名 | color=颜色 | ~k=v }`；登记为 variant 的外观时机 `over 选择器 use=模板名 …`（4.5.1）与它完全等价（含 7.8.9 的输出条目），只有空选择的差别（7.7.4 第 1 条）。

**静态检查**（阶段一第 4 步，模板表与材质表已定稿；任一不满足时报错，整条语句无效：不进挂载表、**不隐藏任何宿主**、不作用于任何节点，`variants[]` 条目带 `error`、`members: []`。4.7 第 2 条依赖此——挂载时不会再遇到这些错误）：

1. `use` 必填，值是模板名字面量（裸标识符或字符串）；缺省报错"variant 需要 use=模板名"；`T` 不是模板表里的名字（最终定义，4.2.1）报错"variant 的模板 T 没有定义"。原型 compileOnce 在挂载时对每个宿主报这条错误；本版在语句上报一次。
2. 除 `use`、`mat`、`color` 之外的每个键必须是 T 的参数表（4.2.5，含派生链）里的名字，否则报错"模板 T 没有参数 k"。`at`、`pin` 报错"变体的位置由外包络决定"（1.3.13；原型 compileOnce 静默用 `at=宿主底面 pin=bottom` 覆盖）。其他 P 组键（`on`、`size`…）按本条报"模板 T 没有参数 k"。原型只在挂载时报"模板 X 没有参数 k"且仍挂载（宿主已隐藏）；本版语句无效。
3. T 的每个**必填参数**必须由语句写明，或是 `w`、`h`、`d` 之一（7.8.3 自动传参）；否则报错"模板 T 缺少参数 p"。原型在挂载时报错，宿主已被隐藏、皮肤退化为零盒（物体从画面消失）；本版语句无效、宿主不隐藏。
4. `mat` 必须是材质表里的名字（否则"未定义的材质 X"）；`color` 必须是颜色字面量。
5. 选择器为空（只有 `variant use=T`）报错"variant 需要选择器"（1.3.13 的形态错误，语法错误）。

**参数值**是表达式，求值上下文与时机由 7.8.3 第 3 条规定（语义帧、根、阶段二挂载时；对皮肤不可见）；不能引用角色、`it`、`i j k idx`；可以引用对象（`gap=slab.w/40`）、let、概念（作集合）、关系谓词。每次挂载（每个宿主）各求值一次；值与宿主无关（没有 `it`），所以每次相同。求值失败按 4.2.3 的实例语句规则：该皮肤节点退化（1.1.4 第 2 条），宿主照常隐藏（7.8.8）——这是运行时错误，不能静态判定。

```s3d
def planks(w=1, h=1, d=1) { repeat pl n=floor(w/0.9) step=w/floor(w/0.9),0,0 center=true { box plank size=w/floor(w/0.9)-0.08,h,d } }
variant deck use=planks                                // 换外观：w h d 自动来自宿主的外包络
variant tall_building use=townhouse
over hangar.roof use=ribbed                             // 外观时机的 over ≡ variant hangar.roof use=ribbed
variant #cargo use=crate_skin mat=steel                 // mat 落在皮肤节点上（10.4.3）
```

### 7.8.2 选择（阶段一）

阶段一第 8 步：

1. **选择集**：按 $P$ 的顺序对每条有效 variant 求选择器（语义上下文；必须是集合类，否则报错"variant 的选择器需要集合，得到 X"，语句无效；读到失败的名字时语句无效）。候选宿主可以是 `all()` 里的任何节点：实体、曲线、容器、布尔容器、repeat 节点、阵列实例、模板实例、copy 节点、副本式节点、副本组、影子、退化节点。
2. **后写的赢**：一个节点被多条 variant 选中时，归 $P$ 里**最后**一条（5.3.6；原型 compileOnce 的 `nextPlan.set(path, i)` 相同）；前面那些条的 `members` 不含它。
3. **祖先裁决**：令 $V$ 是第 2 步之后被任一有效 variant 选中的全部节点之集（每个节点已归到唯一一条语句）。$V$ 里的节点 $N$ 若有某个**真祖先**也在 $V$ 里——归哪条语句不论，该祖先自己是否又因更高的祖先而不挂载也不论——$N$ **不挂载**：$V$ 里最上层的那个祖先整体被替换、$N$ 随它隐藏，$N$ 自己的皮肤没有意义；$N$ 不出现在任何 `members` 里，不报错、不警告。判定只读 $V$ 与场景树，与语句顺序无关（原型 compileOnce 相同：`paths.some(q => path.startsWith(q + '.'))`）。
4. **挂载表** $M$：剩下的 (节点, 语句) 对，按节点顺序；7.8.6 对布尔容器操作数的拒绝在挂载时按成员判定（被拒绝的成员不在 `members` 里，但它仍在 $V$ 里、仍能使其后代按第 3 条不挂载）。原型按路径字符串排序处理；节点顺序与它只在 `members` 的排列上可能不同（语料里每条至多一个成员）。
5. 选择集一经确定不再改变：挂载皮肤不会使别的节点被选中或落选（皮肤不在 `all()` 里，隐藏不改变任何可读的量）。

两条 variant 选中同一个节点、用不同模板：只有后一条生效。要按条件分派不同模板，用互斥的选择器（`where`、`-`）。

### 7.8.3 挂载与模板接口（阶段二）

对挂载表里的每个 (宿主 $N$, 语句 $v$，模板 $T$)，按 4.7 执行；本节是两章的**接口**，规定变体一侧给出什么：

1. **隐藏**：$N$ 与它当时的全部后代（含 $N$ 下面的副本式节点、影子、副本组、copy 节点）标记 `hidden`；$N$ 之外的节点不受影响（含 $N$ 的影子与副本式副本——变体不传播到副本，4.4.5，7.8.5）。
2. **皮肤语句**（4.7 第 2 条）：模板实例语句 `T skin { 参数… mat color }`，以 $N$ 为父节点在阶段二展开（4.2.3、4.2.4）：皮肤节点 $K$ 段 `skin`、种类 T、类型链 = T 的派生链、名字 `skin`、无标签、元数据空、`file` / `line` = 语句 $v$ 的，追加在 $N$ 现有子节点之后；$K$ 与其全部后代标记 `skin`（不隐藏）。$N$ 是 repeat 节点时 $K$ 是 repeat 节点的直接子节点（不是阵列实例），路径 `row.skin`；$N$ 是布尔容器时见 7.8.6。
3. **参数绑定**（4.7 第 3 条）：**写明的参数**的值在挂载时求值，上下文 = (语义帧，根，阶段二)：词法环境是语义帧（1.5.8 表"语义层语句"行——概念名、模式名、最外层 `let`、`metre` 可见；角色、`it`、`i j k idx` 不可见），搜索起点是根，所见的树与量是阶段一定稿的（7.2.5 第 1、2 条）——皮肤对它不可见（7.8.4），所以值与宿主、与挂载顺序无关，对每个宿主各求值一次得到相同的值。原型 compileOnce 用全局帧（`new Env(elab.globals)`：参数值里的概念名解析为同名对象或报找不到）；本版用语义帧，与选择器一致，全局帧里能写的表达式在语义帧里值相同。**自动传参**：`w`、`h`、`d` 三个名字中 T 声明了而语句没写的，分别绑定为 $N$ 的局部包围盒（7.3.1 `w h d` 行的同一个量：实体的盒、容器的包络、有 `envelope` 的 group 用 envelope、退化节点为 0）沿 $N$ 局部 $x$、$y$、$z$ 的边长；T 没有声明的不传；其余参数用默认值。所以模板按 `w h d` 把自己做成宿主的尺寸：`def ribbed(w=1, h=1, d=1) { box base size=w,h*0.35,d; … }`。
4. **外观**：语句的 `mat` / `color` 是 $K$ 的自有外观属性；皮肤的材质链在 $K$ 处终止、终点是 $E(N)$（10.4.3）。
5. **定位**（4.7 第 5 条、3.7.6）：$R_K = I$，$t_K = b_N - \pi_K$——$b_N$ 是 $N$ 的**包络**（第 3 条的同一个盒：实体的局部包围盒、容器的子节点之并、有 `envelope` 的 group 用 envelope）的底面中心 $(c_x, \min_y, c_z)$，$\pi_K$ 是 $K$ 自己的局部包围盒（2.6）的底面中心；即皮肤的局部包围盒底面中心落在宿主包络的底面中心，轴向与 $N$ 相同；皮肤的尺寸由模板决定，不强制等于宿主（`planks` 的板比宿主窄 0.08；`townhouse` 的 parapet 比宿主宽 0.3）。$N$ 是退化节点或空容器时 $b_N$ 是原点。$K$ **不计入** $N$ 与任何祖先的包络（2.6、4.7），所以这条对祖先的依赖不成环（3.7.6）。$K$ 的 `late` 由 3.7.6 的规则直接给出：$N$ 的包络由子节点算出（容器且没写 `envelope`：group、union、intersect、repeat 节点、阵列实例、容器式 mirror / rotate 节点、模板实例、copy 节点）时为真，否则（实体、曲线、有 `envelope` 的 group、subtract、退化节点）为假；它只是输出字段，不改变任何量。参考输出：`slab.skin` 与 `hangar.roof.skin`（宿主是 box）`late: false`，`street.h4.skin`（宿主是模板实例）`late: true`。
6. **求解**：皮肤子树按第 3 章求解；皮肤体可以引用 $N$ 之外已求解的节点（`on=ground`），不能引用 $N$ 自己或 $N$ 的其他后代（它们对皮肤体的对象名解析可见——搜索从 $K$ 向上经过 $N$——但引用祖先 $N$ 按 3.6.2 报错；引用 $N$ 的其他子节点合法）。皮肤里的 mirror / rotate、over / drop、copy 按 4.7 第 6 条。
7. **独立性**：每个宿主独立挂载；一个皮肤体内的错误只影响那个皮肤里的节点（按各自语句的规则退化），不影响其他宿主、不影响 $N$ 的隐藏。

接口的另一侧（4.7）保证挂载不改变 $N$ 与任何祖先的包围盒、不改变事实、不进 `all()`。语料核对见 7.9.1、7.9.2（三个皮肤的 w / h / d 与底面中心）。

### 7.8.4 隐藏与皮肤的不可见性

本节是隐藏与皮肤对各种机制可见与否的**唯一定义处**；1.6.4、1.7.2、4.7、5.4.2、8.3.7、10.4.3、10.5.3 与 decisions.md 的 D9 都引用这里。

**被隐藏的宿主 $N$ 及其后代**：

- 仍在场景树里，路径不变；仍进 `all()`、`kind()`、`#tag`、全局索引；仍可被路径引用（别的节点 `on=N` 照常）；仍有变换、局部 / 世界 / 紧包围盒、事实（第 6 章：事实按隐藏前的几何，隐藏不改变它们）；仍有 $E_g$ 与 $E$（10.4.3）；仍被样式选中。
- 不输出条目：`items[]` 里没有它们的实体与布尔条目，`curves[]` 里没有它们的曲线（10.6）；不渲染。`nodes[]` 条目带 `hidden: true`，其余字段照常。
- 概念、模式、检查的结果与标注不变（它们在阶段一已确定）。

**皮肤 $K$ 及其后代**——对每种机制：

| 机制 | 皮肤 | 说明 |
|---|---|---|
| `all()`、`kind()`、`#tag` | **不可见** | 1.7.2、1.6.7：范围是除皮肤子树与根之外的全部节点 |
| 全局索引（1.6.5 第 3 步） | **不可见** | 皮肤外的表达式写裸名字找不到皮肤里的节点；非皮肤节点引用不到皮肤，依赖图里没有从皮肤指向非皮肤的边（5.4.4）；阶段一写 `x.skin` 报错"x 中没有子对象或锚点 skin"（7.2.3） |
| 空间事实与关系索引 | **不参与** | 6.2.1 第 3 条、6.7.1；谓词的结果不含皮肤 |
| 宿主与任何祖先的包围盒 / 包络 | **不计入** | 2.6、4.7、3.7.6 |
| 概念成员、模式匹配、检查、样式与变体的选择集、`nodes[].concepts` 标注 | **不可能含皮肤** | 全部在皮肤生成前求值（7.2.5 第 3 条）；皮肤节点的 `concepts` 为 `[]` |
| 样式的作用范围 | **不含皮肤子树** | 10.4.3：样式作用于成员及其后代时在 `skin` 段停下；皮肤只经终点 $E(N)$ 间接受样式影响 |
| 通配 `a.*`、`children()`、`descendants()`、直接路径 `a.skin.b` | 可见 | 只在两处有意义：**皮肤模板体内的表达式**（体内 over / drop 的选择器、`on=` 等属性，4.7 第 6 条；搜索起点在皮肤子树里）与**编译后的工具查询**（`slab.skin.pl.0.plank`）。这些构件写在语义层或外观时机的选择器里时皮肤尚不存在（7.1.3），所以不改变上面各行。原型第二遍在有皮肤的树上求值语义语句，这四种构件在那里能选到皮肤（7.1.1、7.9.4）；本版不会 |
| 皮肤体内 over / drop 的选择器里的 `where mat`、元数据键 | 可见、按常规读 | 10.5.3 的皮肤子树分支（沿链到 $K$ 找 `mat`，再取 $E_g(N)$）、8.3.7 |
| 输出 | 照常 | `items[]` 含皮肤的实体、`curves[]` 含皮肤的曲线（10.6）；`nodes[]` 条目带 `skin: true`、`hidden: false`，`file` / `line` 按 5.2.5（$K$ 归 variant 语句，皮肤体的节点归模板的 def 所在文件） |

**不可见性的检验表述**：对任何场景 $P$ 与它的任一 variant 语句 $v$，令 $P'$ = 删掉 $v$ 的 $P$；则 7.1.1 保证表里的各项在 $P$ 与 $P'$ 之间逐位相同，不同的只有 $v$ 的宿主子树的 `hidden`、$v$ 的皮肤节点、条目集合与 `variants[]`。语料 spaceport_blueprint 对 spaceport 的 193 个非皮肤节点与 203 条事实逐位相同（5.5.3、7.9.2）。

### 7.8.5 皮肤里的派生与副本的传播

- **皮肤体里允许的语句**与模板体相同（1.3.15）：实体、曲线、容器、模板实例（嵌套模板，深度按 4.1.4）、copy、over、drop、let。皮肤里的 mirror / rotate 按 4.4.2 末段"皮肤里的副本"在阶段二挂载后生成副本树（原件是皮肤里的节点；`of=` 可以指向皮肤外已存在的节点，影子同样标记 `skin`）；皮肤里的 over / drop 的选择器只作用于皮肤子树、在皮肤展开时求值（4.7 第 6 条，4.5.2 的作用范围规则）；皮肤里的 copy 立即展开（4.3.5 末段）。
- **变体不传播到副本**（4.4.5、10.4.3）：$N$ 的影子（容器式 mirror / rotate 里的、副本式节点下的）与以 $N$ 为原件的副本式节点照常显示 $N$ 的几何、照常输出条目，不隐藏、不挂皮肤；要替换它们须另写一条 variant 选中它们（选择器可以写副本路径或用 `kind()` / `#tag` 同时选中原件与影子）。理由：副本树是原件子树在阶段 6 的函数（4.4.2），皮肤是阶段 8 的外观；若让皮肤传播到副本，副本的皮肤还要再次镜像展开，而影子没有源语句。语料 semantics.s3d：`street.h4` 被替换，`street.h4.half2`（副本式节点）随 h4 一起隐藏（它是 h4 的后代），没有自己的皮肤。
- **变体不传播到拷贝**：copy 在阶段 4 复制源语句，与变体无关；`copy watch2 of=watch` 之后 `variant watch.cabin use=…` 只换 `watch.cabin`；选择器写 `cabin`（概念）则两个都换——语料里 `concept cabin` 的两个成员各自可以被同一条 variant 选中。
- **皮肤不能嵌套**：被选中的节点都是阶段一的节点，皮肤里的节点不可能被选中（7.2.5）。皮肤体里的模板实例是普通嵌套（`skin` 下面可以有 `skin.pl.0.plank`），不是变体。
- **皮肤的元数据**：$K$ 空；皮肤体里的节点各带自己语句的元数据（8.3.7）。标签：$K$ 无；体内节点各按语句，但它们不进 `#tag` 索引（1.6.7）。

### 7.8.6 布尔容器

- **宿主是布尔容器**（union / subtract / intersect）：整个布尔体（容器与它的全部操作数）隐藏，不出布尔条目；皮肤 $K$ 是容器的一个子节点（段 `skin`），但**不是操作数**：布尔容器的包围盒（2.5.4）、几何与条目（10.6 的操作数列表）都不含段为 `skin` 的子节点（原型 buildItems.single 过滤 `skin` 相同）。皮肤子树作为普通子树渲染与输出。`w h d` 自动传参用布尔容器的盒（2.5.4：subtract 是第一个操作数的盒，intersect 是操作数盒之交）。
- **宿主是布尔容器的操作数**（如 `subtract crate { box shell; box hollow }` 里的 `shell`）：**不挂载**，报错"X 是布尔容器的操作数，不能挂变体：请对整个布尔容器挂"，该成员跳过（其他成员照常；该语句的 `members` 不含它）。理由：操作数不单独渲染，隐藏它会改变布尔结果、皮肤又无处参与布尔运算；原型 compileOnce 隐藏操作数但 buildItems.single 不看 `hidden`，结果是操作数照常参与布尔、皮肤既不渲染也不出条目——没有可取的定义。
- **宿主在布尔容器里更深处**（操作数是容器、变体选中它的后代）：按上一条同样处理（它仍是布尔几何的一部分，2.5.1 的嵌套规则）。
- **皮肤体里的布尔容器**：普通的布尔容器，按第 2 章渲染（皮肤的 base 可以是 `subtract`）。

### 7.8.7 皮肤的材质

由 10.4.3 定义，本节只列接口：皮肤子树的材质链在 $K$ 处终止，终点 $E(N)$ 是宿主的**外观时机**有效材质（含作用于 $N$ 及其祖先的样式）；变体语句的 `mat` / `color` 是 $K$ 的自有外观属性，所以是整组皮肤的基础材质；皮肤部件自己写的 `mat` 优先。样式不直接作用于皮肤。语料：`style deck mat=wood` + `variant deck use=planks` → `slab.skin.pl.*.plank` 是 wood；`variant tall_building use=townhouse` → `street.h4.skin.core` 是模板自带的 brick、`pane` 是 glass、`parapet` 是 plain（模板写了）；`over hangar.roof use=ribbed` → `hangar.roof.skin.base`、`skin.rib.*.r` 继承 roof 的 steel（10.8）。

### 7.8.8 错误与警告

| 文案 | 触发 | 恢复 |
|---|---|---|
| variant 需要选择器 / variant 需要 use=模板名 | 1.3.13 | 整条语句无效 |
| variant 的模板 T 没有定义 | `use` 的名字不在模板表（7.8.1 第 1 条） | 整条语句无效，宿主不隐藏 |
| 模板 T 没有参数 k | 键不是参数也不是 `mat` / `color`（7.8.1 第 2 条） | 整条语句无效，宿主不隐藏 |
| 变体的位置由外包络决定 | 写了 `at` 或 `pin`（1.3.13） | 整条语句无效，宿主不隐藏 |
| 模板 T 缺少参数 p | 必填参数未给且不是 `w h d`（7.8.1 第 3 条） | 整条语句无效，宿主不隐藏（原型在挂载时报错、宿主已隐藏且皮肤为零盒，物体消失；本版静态拒绝） |
| 未定义的材质 X / 颜色写成 #rgb、… | `mat` / `color` 的值不合法（7.8.1 第 4 条） | 整条语句无效 |
| variant 的选择器需要集合，得到 X | 选择器不是集合类（7.8.2） | 整条语句无效 |
| 选择器里的名字解析、类型、失败传播的错误（7.4.3） | 7.8.2 | 整条语句无效，文案是失败文案 |
| X 没有选中任何对象 | 登记为 variant 的外观时机 over 选择集为空（5.4.2 第 7 条） | 整条语句无效 |
| X 是布尔容器的操作数，不能挂变体：请对整个布尔容器挂 | 7.8.6 | 该成员不挂载，其他成员照常 |
| 参数值求值失败（找不到对象、类型错误…） | 7.8.3 第 3 条，挂载时；唯一不能静态判定的参数错误 | 皮肤节点 $K$ 退化（零盒，体不展开），宿主**仍隐藏**；报在 variant 语句、带 $K$ 的路径 |
| 皮肤体内语句的错误 | 模板体里的语句按各自规则 | 只影响皮肤里的那个节点；归属 def 所在文件（5.2.5） |
| 皮肤的求解错误（循环依赖、找不到对象） | 第 3 章 | 皮肤里的该节点退化 |

"整条语句无效"对 variant 的含义统一按 7.8.1：不进挂载表、不隐藏任何宿主、不作用于任何节点，`variants[]` 条目带 `error`、`members: []`。所有静态检查在语句上各报一条（不按宿主重复）；挂载时的错误带宿主或皮肤节点的路径（1.10.1）。本节不定义警告；一条 variant 可能带的警告只有 6.9 的"空间事实未推导，X() 为空集"（选择器调用了关系谓词而事实未推导，7.1.4）。

### 7.8.9 输出形状

- **`variants[]`**：每条通过了文法检查的 variant 语句与登记为 variant 的外观时机 over 一个条目，按 $P$ 的顺序：
  ```
  { "line": 数, "file": 字符串, "use": 字符串, "src": 字符串, "members": [路径…], "meta": {…} [, "error": 字符串] }
  ```
  `use` 是模板名；`src` 是选择器的源码文本（首尾空白去掉）；`members` 是这条语句**实际挂载**的宿主路径，节点顺序（被后面的语句夺走的、被祖先裁决掉的、被 7.8.6 拒绝的都不在）；语句无效时 `members: []` 并带 `error`。原型只为登记成功的语句输出条目、`members` 按路径字符串排序；本版无效语句也有条目（带 `error`），`members` 按节点顺序。
- **`nodes[]`**：每个条目带 `hidden`（布尔）与 `skin`（布尔）；皮肤节点 $K$ 的 `kind` 是模板名、`types` 是派生链、`id` 是 `"skin"`、`file` / `line` 是 variant 语句的、`meta` 为 `{}`、`concepts` 为 `[]`、`of` 为 `null`、`ghost` 为 `false`；皮肤体内节点按各自语句。
- **`items[]`**、**`curves[]`**：不含隐藏节点的条目，含皮肤的（10.6）。
- **`defs`**：变体模板与其他模板一样列出（4.2.7）。

## 7.9 用参考输出验证

核对脚本（scratchpad 的 `verify7.mjs`）只读 corpus/reference/examples/*.compile.json 的 `nodes[]`（`path kind types tags box tight world hidden skin concepts late`）与 `facts[]`（`rel a b`），**不**用原型的任何语义代码：按 7.2.4 建关系索引，按 7.3.1 从盒算 `w h d x y z top bottom`（旋转节点的局部盒边长由 `items[].geom` 的参数按 2.1.3 推出），按 7.2.3 实现集合运算（节点顺序），按 7.5.4 实现匹配算法，再把语料里每条 concept / pattern / check / variant 的表达式按本章规则算一遍，与参考输出的 `concepts[]`、`patterns[]`、`checks[]`、`variants[]`、`nodes[].concepts`、`hidden`、`skin` 比。"一致"指集合或值相同；成员**顺序**另列。

### 7.9.3 通用语义库对语料的概念命中

参考大纲 `*.outline.txt` 由 `--outline=2 --semantics` 生成：把 lib/semantics.s3d 追加在文件末尾（所以库里的 `concept roof` 覆盖 semantics.s3d 自己的 `roof`，7.2.2），只打印深度 ≤ 2 的节点，每行末尾的 〔…〕是该节点的 `concepts` 标注。脚本把库的 12 个概念按本章规则在三个文件上各算一遍（`metre = 1`；表达式只用 `min / max / 中间边 / top − bottom`，对旋转节点按 2.1.3 从 `geom` 取局部盒边长），与大纲里每个可见节点的标注比（集合比较）：

| semantics | 24 | 12 | 24 / 24 | terrain 1 · slab 3 · platform 2 · wall 2 · member 53 · column 21 · beam 1 · roof 6 · volume 9 · tank 0 · prop 49 · step 0 |

### 7.9.4 因本章定义而预期不同的项

本章以"原型 …；本版 …"标出的差异汇总如下（供第 9 章引用）。语料里出现的只有第一行（成员顺序）；其余是边界情形，用 scratchpad 的小例子（e7/a.s3d、b.s3d、c.s3d；07/t1.s3d … t8.s3d）在原型上确认了原型行为。

| 节 | 项 | 原型行为（函数） | 本版 | 理由 |
|---|---|---|---|---|
| 7.2.3 | 集合的成员顺序 | evalAst 的 `or` 按操作数拼接（`[...A, ...B]`）、relSet 按索引插入顺序：`lamp` 的成员是 4 根 pole 后 4 个 bulb，`tree` 是 12 trunk 后 12 crown | 节点顺序：`lamps.0.pole lamps.0.bulb …` | 1.5.5 已定（D15）；两个概念的成员集合相同 |
| 7.2.3 | 带锚点 / 偏移的引用当集合 | asSet 取其节点、丢掉锚点 | 报错"X 不是集合（锚点与偏移不能当集合）" | 写了锚点说明要的不是集合 |
| 7.2.4 | 关系谓词的第二个参数 | relSet 接受任何数（`on(ground, 0)` = 索引里有 on 项的全部节点；1.5 等价于 2） | 必须是整数 ≥ 1，否则报错 | 1.5.6 已定 |
| 7.2.5、7.8.4 | 皮肤对语义语句的可见性 | `all()` / `kind()` / `#tag` 不含皮肤（allNodes 过滤 skin，相同）；但第二遍的语义语句在有皮肤的树上求值，`descendants()`、`children()`、通配、直接路径 `x.skin` 能选到皮肤（07/t2.s3d：`concept desc = descendants(g)` 含 `g.skin`、`g.skin.base`，皮肤节点带 `concepts` 标注，`check count(descendants(g)) == 1` 不通过） | 没有任何语义语句在皮肤存在后求值：这些构件只得到非皮肤节点，皮肤的 `concepts` 恒为 `[]` | 7.1.1 的保证；消除 10.4.3 / 10.5.3 的分支 |
| 7.3.1 | `where` 的 `kind` 对副本式节点与影子 | evalAst 取 `m.template ?? K(m)`：原件是模板实例时得到 `group`（07/t4.s3d：`mirror m of=a`，a 是 `hut` 实例，`all() where kind == hut` 只有 a，`kind(hut)` 却有 a 与 m） | 原件的种类（1.6.7）：`hut`，与 `kind(hut)` 一致 | 1.6.7 已定；`kind()` 与 `where kind` 不应给出不同答案 |
| 7.4.2 | `concept N : U` 的 U | makeStmt 把 U 当普通路径求值，可以是对象（`concept E : ground = where …` 得到 {ground}） | U 必须是概念名，否则报错、语句无效 | `parent` 字段的含义；层级是概念之间的 |
| 7.4.4 | `nodes[].concepts` 的标注 | compileOnce 不去重、模式内按绑定顺序 | 去重；模式按输出顺序、角色按声明顺序，再概念 | 可判定；语料无影响 |
| 7.5.1 | 同一角色两条 `in` | makePattern 后一条覆盖 | 报错"角色 X 的 in 约束重复"，pattern 无效 | 覆盖没有理由 |
| 7.5.1 | 关系词 `intersects` | makePattern 的关系词表不含它（当作布尔表达式解析而失败） | 七个谓词名都是关系词 | 1.3.10 已定 |
| 7.5.2 | 域引用了未绑定的角色 | 匹配时报"需要集合（…），得到 y"（未绑定的名字退化成字符串） | 登记时静态报错 | 1.6.5：找不到的名字不退化成字符串；错误更早 |
| 7.5.3 | 布尔约束的值 | asBool：非空集合与非零数为真 | 必须是布尔 | 1.5.5 |
