# 5 层

**范围。** 本章定义"层"：一个文件就是一层；`import` 把另一个文件的语句按出现位置内联；一个场景是根文件与它（递归）import 的文件展开后的**一条语句序列**。本章定义展开的精确过程（顺序、文件身份、循环与重复的判定、缺失与版本错误、错误的归属与排序）、展开后序列上的同名与冲突规则（按名字种类分别定义：节点、模板、材质、概念 / 模式 / let、修改语句）、几何层与外观层的区分（按语句的时机，不按文件声明），以及"外观层不改变空间事实与包围盒"这一保证的精确表述与依据。最后给出典型的层组合作为示例（只是示例，不规定工程布局）。

本章**不**定义：`import` 的词法与路径字符串的解析（01-syntax.md 的 1.3.6 与 1.8 节）；节点同级重名的判定（1.6.6 节）；名字解析顺序（1.6.5 节）；over / drop 两个时机的判定条件与效果、def 的展开（04-derivation.md）；concept / pattern / check / style / variant 的求值与变体的挂载（07-semantics.md）；材质的解析顺序与 `default` 的裁决（10-materials.md）；元数据的记录与输出（08-metadata.md）。本章只规定这些机制在"多个文件"下如何组合。

**依赖的章。** 01-syntax.md（语句形态、位置限制、路径解析、名字解析、求值环境、错误恢复与错误顺序）、04-derivation.md（两个时机、def 的折叠与展开、copy）、07-semantics.md（两阶段求值、变体与皮肤的可见性）、10-materials.md（材质的有效定义）。被依赖：07、08、09、10。

**记法。** 文件用大写字母 $A, B, F, G$ 表示；$\mathrm{seq}(F)$ 是文件 $F$ 展开后的语句序列；$P$ 是场景，即根文件的展开序列。"来自 F 的语句"指在 F 的源码里写下的语句，含它的块里的子语句与 def 体里的语句。

## 5.1 层与场景

### 5.1.1 定义

- **层**（layer）= 参与一次编译的一个 `.s3d` 文件。**根文件**是宿主交给编译器的那个文件；其他层经 `import` 进入。一个文件单独编译时它就是根文件（库文件也可以单独编译）。
- **场景** = 根文件的展开序列 $P = \mathrm{seq}(\text{根文件})$（5.1.2）。编译的全部后续步骤（模板表、材质表、节点树、求解、事实、语义层、外观）都只看 $P$，不再区分语句来自哪个文件。文件只决定三件事：语句在 $P$ 里的位置、相对路径的解析基准（5.2.2）、错误与输出里的 `file` 字段（5.2.5）。
- 每条语句记录它来自的文件与在该文件里的行号（1.3.16 节）；这两项不随内联改变。
- 层**不是作用域**：所有文件共享同一棵场景树（全部最外层节点语句的节点都是根的直接子节点）、同一个全局帧（全部最外层 `let`，1.5.8 节）、同一张模板表、同一张材质表、同一个语义名字空间（5.3.1）。本规范没有"按文件限定"的名字写法，也没有导出 / 隐藏的概念。
- 场景单位与内置常量 `metre` 对整个场景唯一（由宿主给出，1.5.8 节）；文件不能声明自己的单位。

### 5.1.2 展开后序列

$\mathrm{seq}(F)$ 由 F 的最外层语句按源码顺序定义。设 F 的最外层语句依次是 $s_1, \dots, s_n$（文件头不是语句，不在其中），则

$$\mathrm{seq}(F) = s_1' \,\Vert\, s_2' \,\Vert\, \cdots \,\Vert\, s_n'$$

其中 $\Vert$ 是序列连接，并且

- 若 $s_i$ 不是 `import`：$s_i' = [\,s_i\,]$（一条语句，连同它的块）；
- 若 $s_i$ 是 `import "p"` 且按 5.2.3 成功加载为文件 $G$：$s_i' = \mathrm{seq}(G)$（`import` 语句本身不进序列）；
- 若 $s_i$ 是 `import` 且加载失败（5.2.3 的任一错误）：$s_i' = [\,]$（报错，什么都不插入）。

规则：

- 内联是**语句级**的，不是文本级的：每个文件独立做词法与语法分析（自己的行号、自己的文件头、自己的块配对），然后把解析好的语句插进序列。一个块不能跨文件；F 里没有闭合的块（报错"缺少 }"，1.3.2 节）不会吞掉它 import 的文件的语句，被 import 的文件里多余的 `}` 也不会关闭 F 的块。
- 展开是深度优先的：`import` 所在位置被 $\mathrm{seq}(G)$ 整体替换，$G$ 自己的 `import` 在 $\mathrm{seq}(G)$ 内部已经展开。
- 展开不做任何合并、去重、重排或过滤：同名定义、同名节点、重复的修改都原样进入 $P$，由 5.3 节的规则处理。
- $P$ 里语句的**位置**是全部后续规则里"先后"的唯一依据（5.2.4）。

### 5.1.3 等价原则

场景 $P$ 的编译结果**必须**与"把 $P$ 里的语句按同样顺序写在一个文件里"的编译结果相同，只有下面四处例外：

1. 错误、警告与节点输出里的 `file` 与行号按语句来自的文件（5.2.5）；
2. `import` 路径字符串的解析基准是写它的文件所在目录（5.2.2）；
3. 文件头元数据属于各自的文件（5.1.4）；
4. 错误的排序用文件序号作第一键（1.1.5 节）。

因此本规范里凡是"先后"（后写的覆盖先写的、节点顺序、修改的应用顺序）在多文件下都指 **$P$ 里的先后**（5.2.4），而"跨文件覆盖"与"同一文件里后写覆盖先写"是同一条规则。实现**不得**给来自不同文件的语句任何额外的优先级（例如"根文件优先"或"后 import 的文件优先"）。

### 5.1.4 文件头与文件级信息

- 每个文件可以有自己的文件头（1.3.1 节：第一个非空、非注释行只由元数据项组成）。文件头不是语句，不进 $\mathrm{seq}(F)$，不随内联传给别的文件，也不与根文件的文件头合并；它按文件记录（08-metadata.md）。
- `lang` 按文件独立判定（D7）：被 import 的文件 G 的 `lang` 不是 2 时，报错"不支持的语言版本"（归属于 G、文件头所在行），G 不编译，$\mathrm{seq}(G) = [\,]$；导入它的文件与其他文件不受影响。G 仍算"已加载"（5.2.3），再次 import 它报"已经 import 过"而不是再报一次版本错误。
- `import` 语句自己的元数据（`import "x.s3d" ~k=v`，D2）随该语句记录（08-metadata.md），不参与加载，不传给被导入的文件，不写到任何节点上。
- 文件的编码与换行按 1.2.1 节，各文件独立。

## 5.2 import 规则

### 5.2.1 位置与形态

- 形态 `import string { meta }`（1.3.6 节）。只能写在文件的最外层：写在容器块、模板体、repeat 体、over 块、copy 块里报错"import 只能写在最外层"，该语句无效，不导入（1.3.15 节；原型报"未知的类型 import"）。
- `import` 可以出现在最外层的任何位置、任意多条，也可以写在节点语句之后；语句写在哪里，被导入的语句就展开在哪里。
- 带块的 `import`、路径不是双引号字符串、缺少路径：语法错误，整条语句丢弃（1.10.2 节）。路径字符串为空或只含 `.`、`..`、分隔符（规范化后没有文件名）按 5.2.3 第 4 条报"找不到文件"。

```s3d
~lang=2
import "spaceport.s3d"
over tower lv=10
import "style.s3d" ~why="评审稿"
```

### 5.2.2 路径与文件身份

路径字符串的解析规则在 1.8 节；本节只规定展开所依赖的结论：

- 相对路径相对**写这条 import 的文件所在目录**解析——不是相对根文件，也不是相对宿主的当前目录。根文件没有路径时（宿主从字符串编译）相对宿主的当前目录。`/` 是唯一的分隔符；`.` 与空段丢弃；`..` 弹出前一段，已到开头时报错"import 路径越出根目录"；`\` 报错"import 路径用 / 分隔"。以 `/` 或 `字母:/` 开头的是绝对路径。
- 解析并规范化后的**绝对路径是文件的身份**。同一个文件无论经哪条 import、用什么写法（`lib/a.s3d`、`./lib/../lib/a.s3d`、绝对路径）到达，身份相同；宿主必须保证"同一文件 ⇒ 同一身份"（符号链接、大小写由宿主决定，1.8 节）。
- 根文件的身份按同样规则得到。根文件没有路径时，它的身份是一个不与任何磁盘路径相等的占位值；此时无法识别"import 了根文件自己"，由此产生的重复节点由同级重名（1.6.6 节）报错兜住。
- 身份只用于 5.2.3 的循环与重复判定；错误与输出里的 `file` 字段用宿主给出的可显示路径（1.8 节）。

```s3d
import "spaceport.s3d"               // 同目录
import "../lib/semantics.s3d"        // 上一级目录下的库
import "/srv/site/base.s3d"          // 绝对路径
```

### 5.2.3 加载算法

编译器维护两个集合：**加载链** $C$（正在加载、尚未处理完的文件身份，有序，第一项是根文件）与**已加载集** $L$（开始加载过的全部文件身份，含链上的）。编译开始时 $C = L = [\text{根文件}]$。处理文件 F 里的一条 `import "p"` 时，按下面的顺序判定，遇到第一个成立的分支即停止：

1. 路径不合法（1.8 节：含 `\`、越出根目录）→ 报错，不导入。
2. 解析得到身份 $I$。$I \in C$ → 报错"import 形成了循环：$I \to \cdots \to F \to I$"（写出链上从 $I$ 第一次出现到 F 的全部文件的可显示路径，再接 $I$），不导入。自己 import 自己是长度为 1 的循环（`a → a`）；从任何文件 import 根文件都是循环（根文件始终在链上）。
3. $I \in L$ 且 $I \notin C$ → 报错"文件 $I$ 已经 import 过"（D19），不导入。本规范**不做** include-once：同一文件的第二次 import 是错误，不是静默跳过——再次内联会让它的节点同级重名、让它的定义覆盖写在两次 import 之间的定义。要让多个层共用一个库，由序列里更早的某一层（通常是根文件）import 一次，后面的层直接使用它定义的名字（5.3）。
4. 读不到文件（不存在、不是普通文件、不可读、不是合法的 UTF-8）→ 报错"import 找不到文件 $I$"，不导入。
5. 否则：把 $I$ 加入 $L$ 与 $C$ 的末尾，给它分配文件序号（1.1.5 节：按加入 $L$ 的先后从 1 起编号，根文件是 0）；对文件 G 独立做词法与语法分析（错误归属于 G）；检查文件头（5.1.4；版本错误时 $\mathrm{seq}(G) = [\,]$）；按 5.1.2 递归得到 $\mathrm{seq}(G)$（其中的 import 以 G 为"写这条 import 的文件"）；把 $I$ 从 $C$ 末尾移除（仍留在 $L$）；用 $\mathrm{seq}(G)$ 替换这条 import。

规则：

- 第 1–4 条的错误归属于写这条 import 的文件 F、这条 import 所在行。
- 没有导入深度上限：有了第 2、3 条，链的长度不超过参与编译的文件数。
- 一条 import 出错不影响同一文件里其他 import 与其他语句（1.1.4 节第 4 条）；出错的 import 之后的语句照常进入 $P$。
- 第 2 条先于第 3 条：根文件与链上的文件再次出现报"循环"，不在链上的已加载文件再次出现报"已经 import 过"。两者都不导入、都不重复内联。原型的链不含根文件，a → b → a 时 a 的语句被读入两次才报错；本版在第一次重复出现时就报错，不重复任何语句。
- 经两条不同路径到达同一文件（A import B 与 C，B 与 C 都 import D）：第二次到达 D 时报第 3 条的错误，D 只内联一次（在第一次到达的位置）。

### 5.2.4 先后关系

- 两条语句的**先后** = 它们在 $P$ 里的位置先后。来自不同文件的语句之间，以及一条语句与它 import 进来的语句之间，都按此比较：F 里写在 `import "a.s3d"` 之前的语句先于 a.s3d 的全部语句，写在之后的语句后于它们。
- 本规范里所有依赖先后的规则在多文件下都按 $P$ 里的先后：后写的覆盖先写的（5.3）、根的子节点顺序与节点顺序（1.6.1 节）、几何时机的 over / drop 的应用顺序、外观时机的 style / variant / over 的应用顺序（5.3.6）、check 的输出顺序。
- **时机与位置无关**：一条语句属于几何时机还是外观时机，由它的种类与形态决定（04-derivation.md；5.4.1），与它来自哪个文件、在 $P$ 的哪个位置无关。几何时机的全部修改在求解前按 $P$ 的顺序应用；外观时机的全部语句在求解后按 $P$ 的顺序应用。所以把风格层 import 在修改层之前或之后，几何结果相同；差别只在同类语句之间的覆盖先后、节点顺序与错误顺序。
- 模板体内的 over / drop 的位置视为**实例语句**所在的位置（04-derivation.md）；因此后面层里最外层的 over 总是晚于前面层里实例的模板体内修改。就地扩展 `def X : X { over … }` 里的 over 同样随实例定位。
- `copy` 复制的是原件的**声明**（原语句及其块），不含 $P$ 里早于或晚于它的 over / drop 对原件的修改（04-derivation.md）。语料 spaceport_edit.s3d 依赖这一点：`over hangar dw=16` 在前、`copy hangar2 of=hangar` 在后，参考输出里 hangar2 的开口仍是模板默认的 12 宽。
- 定义（def、material、concept、pattern、最外层 let）的**引用**与位置无关：引用处可以早于定义处（可以在前面的层里），引用都用最终定义（5.3）。

### 5.2.5 错误的归属与排序

每条错误与警告都带文件与行（1.10.1 节）；**不允许**没有文件归属的错误。归属规则：

| 错误来自 | 归属的文件与行 |
|---|---|
| 词法、语法、文件头 | 正在解析的那个文件、出错记号所在行 |
| import 的路径、循环、重复、找不到文件 | 写这条 import 的文件、import 所在行 |
| 节点的属性、求解、几何参数、同级重名 | 生成该节点的语句的文件与行：模板体里的语句归 def 所在文件（实例写在别的文件也一样）；实例语句自己的错误（缺少参数、模板不存在、模板没有的参数）归实例语句；被 copy 复制的语句仍归原语句，copy 语句自己的属性归 copy 语句；皮肤子树里的语句归变体模板的 def 所在文件 |
| over / drop 的选择器与属性 | 该 over / drop 语句 |
| concept / pattern / check / style / variant 的选择器与表达式 | 该语句 |
| let 的表达式（在被读取时才求值） | 该 let 语句 |
| material 的属性 | 该 material 语句；`mat=` 引用未定义的材质归写 `mat=` 的语句（style 的 `mat=` 归 style 语句） |
| 事实提供者、变体挂载 | 06-facts.md、07-semantics.md 规定；必须带文件与行 |

原型里根文件的解析错误、style / variant / 几何 over 的选择器错误、事实提供者错误、皮肤节点的 `file` 都是空的；本版一律带文件（完整清单见第 9 章）。

排序：按 1.1.5 节（文件序号、行号、发现先后）。文件序号在 5.2.3 第 5 条分配，根文件为 0；没有加载成功的文件没有序号（它的错误归属于导入它的文件）。

节点输出的 `file` / `line` 与上表第三行相同（1.3.16 节）；皮肤节点 `skin` 本身的 `file` / `line` 是那条 variant（或外观时机的 `over … use=`）语句的（07-semantics.md）。错误若归属于某个节点，还带节点路径（1.10.1 节），由此能区分同一模板体语句在不同实例里的错误。

## 5.3 同名与冲突

### 5.3.1 名字空间

展开后序列上的名字分五类，每类都是**全场景一张表**，不按文件划分、没有限定写法：

| 名字空间 | 来源 | 同名规则 | 定义在 |
|---|---|---|---|
| 节点名 | 节点语句的名字 | 同一父节点下报错（5.3.2） | 1.6.6 节 |
| 模板名 | `def` | 后写替换；`def X : X` 就地扩展（5.3.3） | 本章、04-derivation.md |
| 材质名 | `material` | 后写替换（5.3.4） | 10-materials.md |
| 语义名与词法名 | `concept`、`pattern`、最外层 `let` | 同种后写替换；异种报错（5.3.5） | 本章、1.5.8 节 |
| 标签 | `#tag` | 多对多，无冲突 | 1.6.7 节 |

- 跨名字空间的同名不是冲突：模板名、材质名、标签只在各自的位置（种类词、`use=`、`: T`、`kind()`；`mat=`；`#tag`）被当作字面量查各自的表（D24）。语义名 / 词法名与节点名同名时按 1.6.5 节的解析顺序，词法环境遮蔽对象（D26）。模板名不得与内置种类词同名（1.3.4 节）；任何名字都不得是保留名（1.6.9 节）。
- 模板参数、块内 `let`、阵列索引、`it` 是局部的词法名（1.5.8 节），不进上表，不与别的文件交互。
- 上表"后写替换"的语义都是：$P$ 里最后一条定义是**最终定义**，所有引用（不论写在 $P$ 的哪个位置）都用最终定义；作废的定义不留下任何效果。

### 5.3.2 节点

- 全部文件的最外层节点语句的节点都是根的直接子节点，按 $P$ 的顺序排列（copy 占它自己语句的位置，1.6.1 节）。
- 来自不同文件的两个最外层同名节点是同级重名：报错"同级重名 X"，报在 $P$ 里后出现的语句上，该语句（连同块）不生成节点；引用该名字得到先出现的节点（1.6.6 节，D18）。原型里同名节点既不报错也不覆盖，产生两个同路径的节点；本版报错。
- 节点没有"覆盖"：要替换前面层里的一个节点，写 `drop X` 再声明新的 X（两条都在后面的层里，`drop` 在前），或用 `over X : 种类` 保名换形（04-derivation.md）。`drop` 之后再声明同名节点不是同级重名（被 drop 的节点已不在树里；它仍占用匿名段的计数，1.6.1 节）。
- 同一父节点下的匿名段编号（`box#3`）按该父节点的创建顺序计数（1.6.1 节）；最外层的匿名节点按 $P$ 的顺序在根下编号，所以在前面插入一层会改变后面层里匿名节点的编号——匿名节点不能被路径寻址（1.6.1 节），这不影响任何引用。

```s3d
// base.s3d
box pad size=26,2,26 on=ground
```

```s3d
// edits.s3d（import 在 base.s3d 之后）
drop pad
box pad size=30,2,30 on=ground          // 合法：pad 已被 drop
```

### 5.3.3 模板（def）

模板表由 $P$ 里的 def 语句按顺序**折叠**而成：每个模板名 X 有一个随序列推进而变化的**当前定义**；序列处理完后的当前定义是 X 的**最终定义**。折叠规则：

1. `def X(...) { … }` 或 `def X(...) : B(...) { … }`（$B \ne X$）：把 X 的当前定义**整体替换**为这条语句。X 此前的定义与它的扩展链全部作废——不合并参数、不合并体、不保留之前的扩展。$B$ 只是一个名字，在实例化时按 $B$ 的最终定义解析（04-derivation.md）。
2. `def X : X { … }`（就地扩展，1.3.4 节）：要求此刻 X **已有当前定义**（在 $P$ 里更早、且没有被后来的替换作废）；否则报错"要扩展的类型 X 还没有定义"，该语句无效、不登记（原型把它登记为只有扩展体的定义，本版不登记）。成立时，X 的当前定义变为"原当前定义 + 这条扩展"组成的链；多次扩展依次接在链尾。扩展的体在派生链上的位置、扩展体里语句的求值环境与 over / drop 的作用范围见 04-derivation.md。
3. def 语句自身出错（签名不合法、参数名不合法、与内置种类同名等，1.3.4 节）→ 该语句不登记，不改变当前定义。

引用一律用**最终定义**：实例语句、`copy` 的原件所属模板、`over … : T` 的目标 T、派生 `def Y : X` 的基类型 X、变体的 `use=T`，都与引用在 $P$ 里的位置无关——实例写在 def 之前、写在被 import 的文件里而 def 在后面的层里，都成立。因此后面的层可以用 `def X : X { … }` 给前面所有层里 X 的实例加部件，也可以用新的 `def X` 整体换掉它们的定义；派生类型 `def Y : X` 的实例同样得到 X 的最终定义（含扩展链）。

```s3d
// base.s3d
def hut(w=4) {
  box body size=w,3,w
  wedge roof size=w,1.5,w on=body
}
hut h1 at=0,0,0
hut h2 at=10,0,0
```

```s3d
// edits.s3d（import 在 base.s3d 之后）
def hut : hut { box flag size=0.2,2,0.2 on=roof }   // h1、h2 都多出 flag
```

若 edits.s3d 改写 `def hut(w=4) { cyl body r=w/2 h=3 }`，则 h1、h2 都变成只有一个圆柱体的实例（整体替换）。若把 `def hut : hut` 写在 base.s3d 之前（先 import edits.s3d 再 import base.s3d），该扩展报错并失效，h1、h2 没有 flag。

### 5.3.4 材质

- `material X` 的**有效定义**是 $P$ 里最后一条名为 X 的 material 语句；之前的定义整体作废（不逐键合并：后一条没写 `rough`，有效定义就没有 `rough`）。所有 `mat=X`、`style … mat=X`、`where mat == X` 都按有效定义，与引用的位置无关。
- 出错的 material 语句（属性不合法、位置不合法，1.3.7 与 1.4.6 节）不登记、不改变有效定义。块内、模板体内的 `material` 报错"material 只能写在最外层"（D6；原型静默忽略）。
- 作废的定义上的 `default=true` 不算数；有效定义之间 `default=true` 的唯一性与裁决、材质表的输出顺序，见 10-materials.md。
- 材质属性的表达式在写它的语句的上下文里求值（可以引用最外层 let，1.4.6 节）；因此后面层里的 `let` 覆盖会影响前面层里材质的属性值——这不改几何。
- 语料 spaceport_blueprint.s3d 用这条规则换掉 spaceport.s3d 的 7 种材质（参考输出里 `ground` 的颜色是 `#14365e`，`steel` 是 `#9fc4ea`）。

### 5.3.5 概念、模式与最外层 let

- 同名 `concept`：后写的替换先写的；所有引用（包括写在前面的 concept、pattern、check、style、variant 与外观时机的 over）都用最终定义（惰性求值，07-semantics.md）；输出里每个名字只出现一次，位置与成员由 07-semantics.md 规定。
- 同名 `pattern`：同上。原型把两条都输出、匹配都取最后一条；本版只保留最后一条。
- 最外层同名 `let`：后写的替换先写的，所有引用都用最终定义（1.5.8 节）；最终定义的表达式在它自己的语句的上下文里求值（它所在文件的帧、根作为搜索起点）。块内 `let` 的作用域是块（同块重名报错，1.5.8 节），不与别的文件交互。
- `concept`、`pattern`、最外层 `let` 三者之间同名：报错"名字 X 已经用作 concept / pattern / let"，报在 $P$ 里后出现的那条语句上，该语句无效（1.3.9 节；原型里 pattern 静默压过同名 concept）。
- 出错的 concept / pattern / let 语句不改变当前定义（1.1.4 节第 4 条）。
- 语料 lib/semantics.s3d 的注释写明它的概念是"默认的理解"，场景在 import 之后用同名 concept 覆盖——这就是本节第一条；覆盖后，库里按旧定义写的派生概念（`concept platform : slab = …`）也用新的 `slab`。

```s3d
import "../lib/semantics.s3d"
concept column = all() where top - bottom > 5   // 覆盖库里的 column；库里引用 column 的地方都用这条
```

### 5.3.6 修改语句的先后

| 语句 | 多条之间的规则 |
|---|---|
| 几何时机的 over / drop | 按 $P$ 的顺序依次应用；同一节点的同一属性被多条 over 改时，靠后的生效；`drop` 之后该名字不在树里，再 over / drop 它报"找不到对象"；over 之后 drop 先改再删。重建型修改（改模板参数、阵列 `n`、换形）与就地修改的先后效果见 04-derivation.md |
| 外观时机的 over、style | 求解后按 $P$ 的顺序依次应用；同一节点被多条选中时，靠后的那条决定它的外观（07-semantics.md 规定是整体替换还是逐键覆盖） |
| variant、外观时机的 `over … use=` | 同一节点被多条选中时靠后的生效；祖先与后代同时被选中时的规则见 07-semantics.md |
| check | 全部保留，按 $P$ 的顺序输出，不去重 |
| concept / pattern | 5.3.5 |

两条修改来自不同文件时规则不变。所以"修改层"能改"基础描述"、"风格层"能改"修改层"里新建节点的外观，都不需要动前面层的文本；反过来，前面的层不能撤销后面的层的修改。

### 5.3.7 冲突规则总表

| 情形 | 规则 | 出错时 | 引用是否依赖位置 |
|---|---|---|---|
| 同一父节点下同名节点（含跨文件的最外层） | 报错"同级重名" | 后出现的语句无效 | — |
| 同名 `def X`（非扩展） | 后写整体替换 | 出错的 def 不登记 | 否：用最终定义 |
| `def X : X` | 接在当前定义之后形成链 | X 尚无定义 → 报错、不登记 | 否：用最终链 |
| 同名 `material` | 后写整体替换 | 出错的不登记 | 否 |
| 同名 `concept` / 同名 `pattern` | 后写替换，输出一次 | 出错的不登记 | 否（惰性） |
| concept / pattern / 最外层 let 异种同名 | 报错 | 后出现的语句无效 | — |
| 最外层同名 `let` | 后写替换 | 出错的 let 在被读到时报错 | 否 |
| 块内同名 `let` | 报错"重复定义" | 后出现的无效 | — |
| 几何时机 over / drop 多条 | 按 $P$ 顺序应用，后者覆盖 | 出错的那条无效 | 是：只按 $P$ 的顺序 |
| 外观时机 over / style / variant 多条 | 按 $P$ 顺序应用，后者生效 | 出错的那条无效 | 是 |
| `check` 多条 | 全部保留 | 出错的输出带 error | 是（输出顺序） |
| 同一文件 import 两次 | 报错"已经 import 过" | 第二次不导入 | — |
| import 循环 | 报错"形成了循环" | 不导入 | — |

"引用是否依赖位置"一列回答"把引用移到定义之前（例如移到更早的层）结果是否改变"。
