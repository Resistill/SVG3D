# 5 层

**范围。** 本章定义"层"：一个文件就是一层；`import` 把另一个文件的语句按出现位置内联；一个场景是根文件与它（递归）import 的文件展开后的**一条语句序列**。本章定义展开的精确过程（顺序、文件身份、循环与重复的判定、缺失与版本错误、错误的归属与排序）、展开后序列上的同名与冲突规则（按名字种类分别定义：节点、模板、材质、概念 / 模式 / let、修改语句）、几何层与外观层的区分（按语句的时机，不按文件声明），以及"外观层不改变空间事实与包围盒"这一保证的精确表述与依据。最后给出典型的层组合作为示例（只是示例，不规定工程布局）。

本章**不**定义：`import` 的词法与路径字符串的解析（01-syntax.md 的 1.3.6 与 1.8 节）；节点同级重名的判定（1.6.6 节）；名字解析顺序（1.6.5 节）；over / drop 两个时机的判定条件与效果、def 的展开（04-derivation.md）；concept / pattern / check / style / variant 的求值与变体的挂载（07-semantics.md）；材质的解析顺序与 `default` 的裁决（10-materials.md）；元数据的记录与输出（08-metadata.md）。本章只规定这些机制在"多个文件"下如何组合。

**依赖的章。** 01-syntax.md（语句形态、位置限制、路径解析、名字解析、求值环境、错误恢复与错误顺序）、04-derivation.md（两个时机、def 的折叠与展开、copy）、07-semantics.md（两阶段求值、变体与皮肤的可见性）、10-materials.md（材质的有效定义）。被依赖：07、08、09、10。

**记法。** 文件用大写字母 $A, B, F, G$ 表示；$\mathrm{seq}(F)$ 是文件 $F$ 展开后的语句序列；$P$ 是场景，即根文件的展开序列。"来自 F 的语句"指在 F 的源码里写下的语句，含它的块里的子语句与 def 体里的语句。

## 5.1 层与场景

### 5.1.1 定义

- **层**（layer）= 参与一次编译的一个 `.s3d` 文件。**根文件**是宿主交给编译器的那个文件；其他层经 `import` 进入。一个文件单独编译时它就是根文件（库文件也可以单独编译）。
- **场景** = 根文件的展开序列 $P = \mathrm{seq}(\text{根文件})$（5.1.2）。编译的全部后续步骤（模板表、材质表、节点树、求解、事实、语义层、外观）都只看 $P$，不再区分语句来自哪个文件。文件只决定三件事：语句在 $P$ 里的位置、相对路径的解析基准（5.2.2）、错误与输出里的 `file` 字段（5.2.5）。
- 每条语句记录它来自的文件与在该文件里的行号（1.3.16 节）；这两项不随内联改变。
- 层**不是作用域**：所有文件共享同一棵场景树（全部最外层节点语句的节点都是根的直接子节点）、同一个全局帧（全部最外层 `let`，1.5.8 节）、同一张模板表、同一张材质表、同一个语义名字空间（5.3.1）。本规范没有"按文件限定"的名字写法，也没有导出 / 隐藏的概念。
- 场景单位与内置常量 `metre` 对整个场景唯一（由宿主给出，1.5.8 节）；文件不能声明自己的单位。

### 5.1.2 展开后序列

$\mathrm{seq}(F)$ 由 F 的最外层语句按源码顺序定义。设 F 的最外层语句依次是 $s_1, \dots, s_n$（文件头不是语句，不在其中），则

$$\mathrm{seq}(F) = s_1' \,\Vert\, s_2' \,\Vert\, \cdots \,\Vert\, s_n'$$

其中 $\Vert$ 是序列连接，并且

- 若 $s_i$ 不是 `import`：$s_i' = [\,s_i\,]$（一条语句，连同它的块）；
- 若 $s_i$ 是 `import "p"` 且按 5.2.3 成功加载为文件 $G$：$s_i' = \mathrm{seq}(G)$（`import` 语句本身不进序列）；
- 若 $s_i$ 是 `import` 且加载失败（5.2.3 的任一错误）：$s_i' = [\,]$（报错，什么都不插入）。

规则：

- 内联是**语句级**的，不是文本级的：每个文件独立做词法与语法分析（自己的行号、自己的文件头、自己的块配对），然后把解析好的语句插进序列。一个块不能跨文件；F 里没有闭合的块（报错"缺少 }"，1.3.2 节）不会吞掉它 import 的文件的语句，被 import 的文件里多余的 `}` 也不会关闭 F 的块。
- 展开是深度优先的：`import` 所在位置被 $\mathrm{seq}(G)$ 整体替换，$G$ 自己的 `import` 在 $\mathrm{seq}(G)$ 内部已经展开。
- 展开不做任何合并、去重、重排或过滤：同名定义、同名节点、重复的修改都原样进入 $P$，由 5.3 节的规则处理。
- $P$ 里语句的**位置**是全部后续规则里"先后"的唯一依据（5.2.4）。

### 5.1.3 等价原则

场景 $P$ 的编译结果**必须**与"把 $P$ 里的语句按同样顺序写在一个文件里"的编译结果相同，只有下面四处例外：

1. 错误、警告与节点输出里的 `file` 与行号按语句来自的文件（5.2.5）；
2. `import` 路径字符串的解析基准是写它的文件所在目录（5.2.2）；
3. 文件头元数据属于各自的文件（5.1.4）；
4. 错误的排序用文件序号作第一键（1.1.5 节）。

因此本规范里凡是"先后"（后写的覆盖先写的、节点顺序、修改的应用顺序）在多文件下都指 **$P$ 里的先后**（5.2.4），而"跨文件覆盖"与"同一文件里后写覆盖先写"是同一条规则。实现**不得**给来自不同文件的语句任何额外的优先级（例如"根文件优先"或"后 import 的文件优先"）。

### 5.1.4 文件头与文件级信息

- 每个文件可以有自己的文件头（1.3.1 节：第一个非空、非注释行只由元数据项组成）。文件头不是语句，不进 $\mathrm{seq}(F)$，不随内联传给别的文件，也不与根文件的文件头合并；它按文件记录，随 08-metadata.md 的 8.4.3 规定的按文件输出给出（输出形状由该节定义，本章不定义）。
- `lang` 按文件独立判定（D7）：被 import 的文件 G 的 `lang` 不是 2 时，报错"不支持的语言版本"（归属于 G、文件头所在行），G 不编译，$\mathrm{seq}(G) = [\,]$；导入它的文件与其他文件不受影响。G 仍算"已加载"（5.2.3），再次 import 它报"已经 import 过"而不是再报一次版本错误。
- `import` 语句自己的元数据（`import "x.s3d" ~k=v`，D2）随该语句记录（08-metadata.md），不参与加载，不传给被导入的文件，不写到任何节点上。
- 文件的编码与换行按 1.2.1 节，各文件独立。

## 5.2 import 规则

### 5.2.1 位置与形态

- 形态 `import string { meta }`（1.3.6 节）。只能写在文件的最外层：写在容器块、模板体、repeat 体、over 块、copy 块里报错"import 只能写在最外层"，该语句无效，不导入（1.3.15 节；原型报"未知的类型 import"）。
- `import` 可以出现在最外层的任何位置、任意多条，也可以写在节点语句之后；语句写在哪里，被导入的语句就展开在哪里。
- 带块的 `import`、路径不是双引号字符串、缺少路径：语法错误，整条语句丢弃（1.10.2 节）。路径字符串为空或只含 `.`、`..`、分隔符（规范化后没有文件名）按 5.2.3 第 4 条报"找不到文件"。

```s3d
~lang=2
import "spaceport.s3d"
over tower lv=10
import "style.s3d" ~why="评审稿"
```

### 5.2.2 路径与文件身份

路径字符串的解析规则在 1.8 节；本节只规定展开所依赖的结论：

- 相对路径相对**写这条 import 的文件所在目录**解析——不是相对根文件，也不是相对宿主的当前目录。根文件没有路径时（宿主从字符串编译）相对宿主的当前目录。`/` 是唯一的分隔符；`.` 与空段丢弃；`..` 弹出前一段，已到开头时报错"import 路径越出根目录"；`\` 报错"import 路径用 / 分隔"。以 `/` 或 `字母:/` 开头的是绝对路径。
- 解析并规范化后的**绝对路径是文件的身份**。同一个文件无论经哪条 import、用什么写法（`lib/a.s3d`、`./lib/../lib/a.s3d`、绝对路径）到达，身份相同；宿主必须保证"同一文件 ⇒ 同一身份"（符号链接、大小写由宿主决定，1.8 节）。
- 根文件的身份按同样规则得到。根文件没有路径时，它的身份是一个不与任何磁盘路径相等的占位值；此时无法识别"import 了根文件自己"，由此产生的重复节点由同级重名（1.6.6 节）报错兜住。
- 身份只用于 5.2.3 的循环与重复判定；错误与输出里的 `file` 字段用宿主给出的可显示路径（1.8 节）。

```s3d
import "spaceport.s3d"               // 同目录
import "../lib/semantics.s3d"        // 上一级目录下的库
import "/srv/site/base.s3d"          // 绝对路径
```

### 5.2.3 加载算法

编译器维护两个集合：**加载链** $C$（正在加载、尚未处理完的文件身份，有序，第一项是根文件）与**已加载集** $L$（开始加载过的全部文件身份，含链上的）。编译开始时 $C = L = [\text{根文件}]$。处理文件 F 里的一条 `import "p"` 时，按下面的顺序判定，遇到第一个成立的分支即停止：

1. 路径不合法（1.8 节：含 `\`、越出根目录）→ 报错，不导入。
2. 解析得到身份 $I$。$I \in C$ → 报错"import 形成了循环：$I \to \cdots \to F \to I$"（写出链上从 $I$ 第一次出现到 F 的全部文件的可显示路径，再接 $I$），不导入。自己 import 自己是长度为 1 的循环（`a → a`）；从任何文件 import 根文件都是循环（根文件始终在链上）。
3. $I \in L$ 且 $I \notin C$ → 报错"文件 $I$ 已经 import 过"（D19），不导入。本规范**不做** include-once：同一文件的第二次 import 是错误，不是静默跳过——再次内联会让它的节点同级重名、让它的定义覆盖写在两次 import 之间的定义。要让多个层共用一个库，由序列里更早的某一层（通常是根文件）import 一次，后面的层直接使用它定义的名字（5.3）。
4. 读不到文件（不存在、不是普通文件、不可读）→ 报错"import 找不到文件 $I$"，不导入。读到的字节里无法解码的序列不属于本条：按 1.2.1 节作为 G 的语法错误报（归属于 G、该行丢弃），文件照常加载。
5. 否则：把 $I$ 加入 $L$ 与 $C$ 的末尾，给它分配文件序号（1.1.5 节：按加入 $L$ 的先后从 1 起编号，根文件是 0）；对文件 G 独立做词法与语法分析（错误归属于 G）；检查文件头（5.1.4；版本错误时 $\mathrm{seq}(G) = [\,]$）；按 5.1.2 递归得到 $\mathrm{seq}(G)$（其中的 import 以 G 为"写这条 import 的文件"）；把 $I$ 从 $C$ 末尾移除（仍留在 $L$）；用 $\mathrm{seq}(G)$ 替换这条 import。

规则：

- 第 1–4 条的错误归属于写这条 import 的文件 F、这条 import 所在行。
- 没有导入深度上限：有了第 2、3 条，链的长度不超过参与编译的文件数。
- 一条 import 出错不影响同一文件里其他 import 与其他语句（1.1.4 节第 4 条）；出错的 import 之后的语句照常进入 $P$。
- 第 2 条先于第 3 条：根文件与链上的文件再次出现报"循环"，不在链上的已加载文件再次出现报"已经 import 过"。两者都不导入、都不重复内联。原型的链不含根文件，a → b → a 时 a 的语句被读入两次才报错；本版在第一次重复出现时就报错，不重复任何语句。
- 经两条不同路径到达同一文件（A import B 与 C，B 与 C 都 import D）：第二次到达 D 时报第 3 条的错误，D 只内联一次（在第一次到达的位置）。

### 5.2.4 先后关系

- 两条语句的**先后** = 它们在 $P$ 里的位置先后。来自不同文件的语句之间，以及一条语句与它 import 进来的语句之间，都按此比较：F 里写在 `import "a.s3d"` 之前的语句先于 a.s3d 的全部语句，写在之后的语句后于它们。
- 本规范里所有依赖先后的规则在多文件下都按 $P$ 里的先后：后写的覆盖先写的（5.3）、根的子节点顺序与节点顺序（1.6.1 节）、几何时机的 over / drop 的应用顺序、外观时机的 style / variant / over 的应用顺序（5.3.6）、check 的输出顺序。
- **时机与位置无关**：一条语句属于几何时机还是外观时机，由它的种类与形态决定（04-derivation.md；5.4.1），与它来自哪个文件、在 $P$ 的哪个位置无关。几何时机的全部修改在求解前按 $P$ 的顺序应用；外观时机的全部语句在求解后按 $P$ 的顺序应用。所以把风格层 import 在修改层之前或之后，几何结果相同；差别只在同类语句之间的覆盖先后、节点顺序与错误顺序。
- 模板体内的 over / drop 的位置视为**实例语句**所在的位置（04-derivation.md）；因此后面层里最外层的 over 总是晚于前面层里实例的模板体内修改。就地扩展 `def X : X { over … }` 里的 over 同样随实例定位。
- `copy` 复制的是原件的**声明**（原语句及其块），不含 $P$ 里早于或晚于它的 over / drop 对原件的修改：全部 copy 在任何几何时机的修改之前展开（阶段 4 先于阶段 5，4.1.1、4.3.5），所以不论书写先后，普通 copy 复制的都是**未修改的**源语句。语料 spaceport_edit.s3d 依赖这一点：`over hangar dw=16` 在前、`copy hangar2 of=hangar` 在后，参考输出里 hangar2 的开口仍是模板默认的 12 宽。唯一的例外是 over 块里的 copy：它在阶段 5 展开该块时立即展开，复制的是那一刻的有效语句（重建过的节点是重建时的语句，4.3.5 末段、8.3.5）。
- 定义（def、material、concept、pattern、最外层 let）的**引用**与位置无关：引用处可以早于定义处（可以在前面的层里），引用都用最终定义（5.3）。

### 5.2.5 错误的归属与排序

每条错误与警告都带文件与行（1.10.1 节）；**不允许**没有文件归属的错误。归属规则：

| 错误来自 | 归属的文件与行 |
|---|---|
| 词法、语法、文件头 | 正在解析的那个文件、出错记号所在行 |
| import 的路径、循环、重复、找不到文件 | 写这条 import 的文件、import 所在行 |
| 节点的属性、求解、几何参数、同级重名 | 生成该节点的语句的文件与行：模板体里的语句归 def 所在文件（实例写在别的文件也一样）；实例语句自己的错误（缺少参数、模板不存在、模板没有的参数）归实例语句；被 copy 复制的语句仍归原语句，copy 语句自己的属性归 copy 语句；皮肤子树里的语句归变体模板的 def 所在文件 |
| over / drop 的选择器与属性 | 该 over / drop 语句 |
| concept / pattern / check / style / variant 的选择器与表达式 | 该语句 |
| let 的表达式（在被读取时才求值） | 该 let 语句 |
| material 的属性 | 该 material 语句；`mat=` 引用未定义的材质归写 `mat=` 的语句（style 的 `mat=` 归 style 语句） |
| 事实提供者（6.3.2、6.9：提供者名不存在、提供者推导时抛出） | 没有对应的语句：归根文件（文件序号 0）、行 0、不带节点路径——上表里唯一不对应某条语句的错误 |
| 变体的挂载（参数值求值失败、布尔容器的操作数、皮肤的求解错误） | 那条 variant（或外观时机 `over … use=`）语句，带宿主或皮肤节点的路径（7.8.8）；皮肤体内语句自己的错误按上面第三行归 def 所在文件 |

原型里根文件的解析错误、style / variant / 几何 over 的选择器错误、事实提供者错误、皮肤节点的 `file` 都是空的；本版一律带文件。完整清单见 9.3.3（"错误的 `file`"、"copy 节点的 `file` / `line`"、"皮肤节点 `skin` 的 `file`"三行）；对参考输出比较时按 9.4.5 的 N1、N5、N6 规范化。

排序：按 1.1.5 节（文件序号、行号、发现先后）。文件序号在 5.2.3 第 5 条分配，根文件为 0；没有加载成功的文件没有序号（它的错误归属于导入它的文件）。

节点输出的 `file` / `line` 与上表第三行相同（1.3.16 节）；皮肤节点 `skin` 本身的 `file` / `line` 是那条 variant（或外观时机的 `over … use=`）语句的（07-semantics.md）。错误若归属于某个节点，还带节点路径（1.10.1 节），由此能区分同一模板体语句在不同实例里的错误。

## 5.3 同名与冲突

### 5.3.1 名字空间

展开后序列上的名字分五类，每类都是**全场景一张表**，不按文件划分、没有限定写法：

| 名字空间 | 来源 | 同名规则 | 定义在 |
|---|---|---|---|
| 节点名 | 节点语句的名字 | 同一父节点下报错（5.3.2） | 1.6.6 节 |
| 模板名 | `def` | 后写替换；`def X : X` 就地扩展（5.3.3） | 本章、04-derivation.md |
| 材质名 | `material` | 后写替换（5.3.4） | 10-materials.md |
| 语义名与词法名 | `concept`、`pattern`、最外层 `let` | 同种后写替换；异种报错（5.3.5） | 本章、1.5.8 节 |
| 标签 | `#tag` | 多对多，无冲突 | 1.6.7 节 |

- 跨名字空间的同名不是冲突：模板名、材质名、标签只在各自的位置（种类词、`use=`、`: T`、`kind()`；`mat=`；`#tag`）被当作字面量查各自的表（D24）。语义名 / 词法名与节点名同名时按 1.6.5 节的解析顺序，词法环境遮蔽对象（D26）。模板名不得与内置种类词同名（1.3.4 节）；任何名字都不得是保留名（1.6.9 节）。
- 模板参数、块内 `let`、阵列索引、`it` 是局部的词法名（1.5.8 节），不进上表，不与别的文件交互。
- 上表"后写替换"的语义都是：$P$ 里最后一条定义是**最终定义**，所有引用（不论写在 $P$ 的哪个位置）都用最终定义；作废的定义不留下任何效果。

### 5.3.2 节点

- 全部文件的最外层节点语句的节点都是根的直接子节点，按 $P$ 的顺序排列（copy 占它自己语句的位置，1.6.1 节）。
- 来自不同文件的两个最外层同名节点是同级重名：报错"同级重名 X"，报在 $P$ 里后出现的语句上，该语句（连同块）不生成节点；引用该名字得到先出现的节点（1.6.6 节，D18）。原型里同名节点既不报错也不覆盖，产生两个同路径的节点；本版报错。
- 节点没有"覆盖"：要替换前面层里的一个节点，写 `drop X` 再声明新的 X（两条都在后面的层里，`drop` 在前），或用 `over X : 种类` 保名换形（04-derivation.md）。`drop` 之后再声明同名节点不是同级重名（被 drop 的节点已不在树里；它仍占用匿名段的计数，1.6.1 节）。
- 同一父节点下的匿名段编号（`box#3`）按该父节点的创建顺序计数（1.6.1 节）；最外层的匿名节点按 $P$ 的顺序在根下编号，所以在前面插入一层会改变后面层里匿名节点的编号——匿名节点不能被路径寻址（1.6.1 节），这不影响任何引用。

```s3d
// base.s3d
box pad size=26,2,26 on=ground
```

```s3d
// edits.s3d（import 在 base.s3d 之后）
drop pad
box pad size=30,2,30 on=ground          // 合法：pad 已被 drop
```

### 5.3.3 模板（def）

模板表由 $P$ 里的 def 语句按顺序**折叠**而成：每个模板名 X 有一个随序列推进而变化的**当前定义**；序列处理完后的当前定义是 X 的**最终定义**。折叠规则：

1. `def X(...) { … }` 或 `def X(...) : B(...) { … }`（$B \ne X$）：把 X 的当前定义**整体替换**为这条语句。X 此前的定义与它的扩展链全部作废——不合并参数、不合并体、不保留之前的扩展。$B$ 只是一个名字，在实例化时按 $B$ 的最终定义解析（04-derivation.md）。
2. `def X : X { … }`（就地扩展，1.3.4 节）：要求此刻 X **已有当前定义**（在 $P$ 里更早、且没有被后来的替换作废）；否则报错"要扩展的类型 X 还没有定义"，该语句无效、不登记（原型把它登记为只有扩展体的定义，本版不登记）。成立时，X 的当前定义变为"原当前定义 + 这条扩展"组成的链；多次扩展依次接在链尾。扩展的体在派生链上的位置、扩展体里语句的求值环境与 over / drop 的作用范围见 04-derivation.md。
3. def 语句自身出错（签名不合法、参数名不合法、与内置种类同名等，1.3.4 节）→ 该语句不登记，不改变当前定义。

引用一律用**最终定义**：实例语句、`copy` 的原件所属模板、`over … : T` 的目标 T、派生 `def Y : X` 的基类型 X、变体的 `use=T`，都与引用在 $P$ 里的位置无关——实例写在 def 之前、写在被 import 的文件里而 def 在后面的层里，都成立。因此后面的层可以用 `def X : X { … }` 给前面所有层里 X 的实例加部件，也可以用新的 `def X` 整体换掉它们的定义；派生类型 `def Y : X` 的实例同样得到 X 的最终定义（含扩展链）。

```s3d
// base.s3d
def hut(w=4) {
  box body size=w,3,w
  wedge roof size=w,1.5,w on=body
}
hut h1 at=0,0,0
hut h2 at=10,0,0
```

```s3d
// edits.s3d（import 在 base.s3d 之后）
def hut : hut { box flag size=0.2,2,0.2 on=roof }   // h1、h2 都多出 flag
```

若 edits.s3d 改写 `def hut(w=4) { cyl body r=w/2 h=3 }`，则 h1、h2 都变成只有一个圆柱体的实例（整体替换）。若把 `def hut : hut` 写在 base.s3d 之前（先 import edits.s3d 再 import base.s3d），该扩展报错并失效，h1、h2 没有 flag。

### 5.3.4 材质

- `material X` 的**有效定义**是 $P$ 里最后一条名为 X 的 material 语句；之前的定义整体作废（不逐键合并：后一条没写 `rough`，有效定义就没有 `rough`）。所有 `mat=X`、`style … mat=X`、`where mat == X` 都按有效定义，与引用的位置无关。
- 位置不合法或缺名字的 material 语句整条无效：不登记、不改变有效定义（10.1.1）；块内、模板体内的 `material` 报错"material 只能写在最外层"（D6；原型静默忽略）。属性级的错误（未知键、类型 / 范围错误、常量求值失败，1.4.6 节）只使出错的那个属性视为没写，该语句**仍登记**并照常替换同名的先前定义（10.1.2）。
- 作废的定义上的 `default=true` 不算数；有效定义之间 `default=true` 的唯一性与裁决、材质表的输出顺序，见 10-materials.md。
- 材质属性的表达式在写它的语句的上下文里求值（可以引用最外层 let，1.4.6 节）；因此后面层里的 `let` 覆盖会影响前面层里材质的属性值——这不改几何。
- 语料 spaceport_blueprint.s3d 用这条规则换掉 spaceport.s3d 的 7 种材质（参考输出里 `ground` 的颜色是 `#14365e`，`steel` 是 `#9fc4ea`）。

### 5.3.5 概念、模式与最外层 let

- 同名 `concept`：后写的替换先写的；所有引用（包括写在前面的 concept、pattern、check、style、variant 与外观时机的 over）都用最终定义（惰性求值，07-semantics.md）；输出里每个名字只出现一次，条目在 `concepts[]` / `patterns[]` 里的位置是最终定义在 $P$ 里相对其他最终定义的先后，`line` / `file` / `src` / `meta` 也是最终定义的（7.2.2）；成员由 07-semantics.md 规定。
- 同名 `pattern`：同上。原型把两条都输出、匹配都取最后一条；本版只保留最后一条。
- 最外层同名 `let`：后写的替换先写的，所有引用都用最终定义（1.5.8 节）；最终定义的表达式在它自己的语句的上下文里求值（全局帧、根作为搜索起点，1.5.8 节）。块内 `let` 的作用域是块（同块重名报错，1.5.8 节），不与别的文件交互。
- `concept`、`pattern`、最外层 `let` 三者之间同名：报错"名字 X 已经用作 concept / pattern / let"，报在 $P$ 里后出现的那条语句上，该语句无效（1.3.9 节；原型里 pattern 静默压过同名 concept）。
- 出错的 concept / pattern / let 语句不改变当前定义（1.1.4 节第 4 条）。
- 语料 lib/semantics.s3d 的注释写明它的概念是"默认的理解"，场景在 import 之后用同名 concept 覆盖——这就是本节第一条；覆盖后，库里按旧定义写的派生概念（`concept platform : slab = …`）也用新的 `slab`。

```s3d
import "../lib/semantics.s3d"
concept column = all() where top - bottom > 5   // 覆盖库里的 column；库里引用 column 的地方都用这条
```

### 5.3.6 修改语句的先后

| 语句 | 多条之间的规则 |
|---|---|
| 几何时机的 over / drop | 按 $P$ 的顺序依次应用；同一节点的同一属性被多条 over 改时，靠后的生效；`drop` 之后该名字不在树里，再 over / drop 它报"找不到对象"；over 之后 drop 先改再删。重建型修改（改模板参数、阵列 `n`、换形）与就地修改的先后效果见 04-derivation.md |
| 外观时机的 over、style | 求解后按 $P$ 的顺序依次应用；同一节点被多条选中时，靠后的那条决定它的外观（10.3.3：`mat` 整体替换基础材质、`color` 只换颜色与 opacity，逐条应用、后者覆盖前者） |
| variant、外观时机的 `over … use=` | 按 7.8.2：同一节点被多条选中时归 $P$ 里**最后**一条（后写的赢；前面各条的 `members` 不含它）；被选中的节点若有某个真祖先也被选中（归哪条不论）则**不挂载**、不进任何 `members`、不报错（祖先裁决） |
| check | 全部保留，按 $P$ 的顺序输出，不去重 |
| concept / pattern | 5.3.5 |

两条修改来自不同文件时规则不变。所以"修改层"能改"基础描述"、"风格层"能改"修改层"里新建节点的外观，都不需要动前面层的文本；反过来，前面的层不能撤销后面的层的修改。

### 5.3.7 冲突规则总表

| 情形 | 规则 | 出错时 | 引用是否依赖位置 |
|---|---|---|---|
| 同一父节点下同名节点（含跨文件的最外层） | 报错"同级重名" | 后出现的语句无效 | — |
| 同名 `def X`（非扩展） | 后写整体替换 | 出错的 def 不登记 | 否：用最终定义 |
| `def X : X` | 接在当前定义之后形成链 | X 尚无定义 → 报错、不登记 | 否：用最终链 |
| 同名 `material` | 后写整体替换 | 位置错误 / 缺名字的不登记；属性级错误的仍登记（10.1.2） | 否 |
| 同名 `concept` / 同名 `pattern` | 后写替换，输出一次 | 出错的不登记 | 否（惰性） |
| concept / pattern / 最外层 let 异种同名 | 报错 | 后出现的语句无效 | — |
| 最外层同名 `let` | 后写替换 | 出错的 let 在被读到时报错 | 否 |
| 块内同名 `let` | 报错"重复定义" | 后出现的无效 | — |
| 几何时机 over / drop 多条 | 按 $P$ 顺序应用，后者覆盖 | 出错的那条无效 | 是：只按 $P$ 的顺序 |
| 外观时机 over / style / variant 多条 | 按 $P$ 顺序应用，后者生效 | 出错的那条无效 | 是 |
| `check` 多条 | 全部保留 | 出错的输出带 error | 是（输出顺序） |
| 同一文件 import 两次 | 报错"已经 import 过" | 第二次不导入 | — |
| import 循环 | 报错"形成了循环" | 不导入 | — |

"引用是否依赖位置"一列回答"把引用移到定义之前（例如移到更早的层）结果是否改变"。

## 5.4 几何层与外观层

本节把 $P$ 里的语句按**时机**分组，并由此定义几何层与外观层。层的区分是**语句级**的：一条语句属于哪一层由它的种类与形态决定（4.5.1），与它写在哪个文件、在 $P$ 的哪个位置无关（5.2.4）。文件不需要、也不能声明自己是哪一层（5.4.5）。

### 5.4.1 语句的分类

| 组 | 语句 | 生效的阶段（4.1.1） | 能改变什么 |
|---|---|---|---|
| **几何时机**（几何层） | 节点语句（实体、曲线、group / union / subtract / intersect、repeat、容器式与副本式 mirror / rotate、mesh、模板实例）；`copy`；几何时机的 `over`（4.5.1：带块、带换形 `: T`、没有 `use` 而含 `{mat, color}` 之外的键，或写在任何块里的）；`drop` | 3–6（展开与修改），结果进入 7 | 节点的存在、路径、顺序、有效属性、变换、包围盒、事实，以及由此得到的概念 / 模式 / 检查结果与样式、变体的选择集 |
| **外观时机**（外观层） | `style`；`variant`；外观时机的 `over`（最外层、无块、无换形、至少一个属性；没有 `use` 时每个键都属于 `{mat, color}`，有 `use` 时其余键是 `mat` / `color` 或传给模板的参数——4.5.1 第 4 条；`over roof use=ribbed w=10` 也是外观时机的） | 8 | 节点的外观时机有效材质 $E$（10.3.3）；挂载表（7.8.2 裁决后）里节点的 `hidden` 标记与它下面的皮肤子树（4.7） |
| **只读的语义语句** | `concept`、`pattern`、`check` | 7（语义阶段一，07-semantics.md 的 7.1.2） | 不改任何节点；只产生输出条目（`concepts[]`、`patterns[]`、`checks[]`）与节点上的 `concepts` 标注 |
| **定义与结构语句** | `def`、`let`、`material`、`import` | 1–2（内联与登记） | 本身不作用于任何节点；效果经引用它们的语句体现，归到引用者的时机（下文第 5–8 条） |

规则：

1. **只看形态。** 一条 `over` 是外观时机的，当且仅当 4.5.1 的四个条件同时成立；判定在阶段 2 按语句逐条做，在建任何节点之前，**不得**按被选中节点或属性值的实际效果判定：`over a size=1,3,1` 即使 a 本来就是 1 × 3 × 1 也是几何时机；`over a mat=steel` 即使 a 本来就是 steel 也是外观时机；`over a use=T w=3` 是外观时机（`w` 是传给 T 的参数），`w` 不是 T 的参数时仍是外观时机、在登记时报错"模板 T 没有参数 w"（4.5.1 第 4 条、7.8.8）。实现**不得**把"几何没变"的几何时机修改当作外观语句，也不得把选不中任何东西的外观语句当作无效的几何修改。
2. **块里的 over 都是几何时机的**，即使只写了 `mat` / `color`（4.5.1）。块里的 over 作用于该块的节点的后代（4.5.2），它和块一起构成那个节点的描述，随 copy 与模板实例化一起被带走（4.3.4、4.2.4）；它的 `mat` / `color` 成为被选中节点的自有外观属性，参与 $E_g$（10.5.2）。语料 spaceport_edit.s3d 的 `copy hangar2 of=hangar … { over roof color=#4a5560 }` 就是这种情况：参考输出里 `hangar2.roof` 的条目带这个颜色，而 `hangar.roof` 不带。
3. **出错不改变归属。** 几何时机的语句出错（选择器错误、属性错误、1.1.4 第 5 条）时整条无效，错误归该语句（5.2.5）；它不会因此"退化"成外观语句：`over a size=1,1,1 color=#f00` 的选择器出错时 `color` 也不生效。外观时机的语句出错同理（1.1.4 第 4 条：style / variant 不作用）。
4. **元数据不改变分类**（8.2.1）：`over a color=#f00 ~why="评审"` 仍是外观时机；`over a size=2,2,2 ~layer="style"` 仍是几何时机。
5. **def** 的归属随引用：被几何时机的语句引用（模板实例语句、派生模板 `def Y : X` 的实例、`over … : T` 的换形目标、被 copy 复制的实例语句）→ 它决定几何；只被 `variant … use=T` 与外观时机的 `over … use=T` 引用 → 它只决定皮肤，属于外观层（spaceport_blueprint.s3d 的 `ribbed`）；没有引用 → 没有效果（只有 `defs` 输出条目）。**重定义或就地扩展**一个已有几何实例的模板（5.3.3）是几何层的修改，不论写在哪个文件；给变体模板加部件（`def ribbed : ribbed { … }`）只改皮肤，属于外观层。
6. **let** 是惰性的，在读它的语句的时机求值并按时机分别缓存（1.5.8）。同一个 let 可以被两个时机读；它在几何时机被选择器读到时，表达式受 5.4.2 的限制；被外观时机或语义语句读到时不受限。最外层 `let` 的名字遮蔽同名对象（1.5.8），所以**新增**一个最外层 let 可能让几何时机的表达式（`on=pad`）改变含义——这是几何层的修改，即使它写在风格文件里。
7. **material** 的属性值（`color` `metal` `rough` `opacity` `default`）只被 $E_g$ / $E$ 读（10.3），不影响阶段 1–7 的任何量，所以 material 属于外观层。但材质**名字的集合**对几何时机可见：`mat=X` 引用未定义的材质报错并按没写处理（1.10.2 材质错误），`where mat == X` 读的是 $E_g$ 的 name（10.5.3，静态量）。因此**新增或删除**一个材质名可以改变几何时机选择器的真值与错误列表；**重定义已有名字**（spaceport_blueprint.s3d 的 7 条 `material`）不改变阶段 1–7 的任何量。5.4.4 的保证按此表述。
8. **import** 是结构语句，不属于任何时机；它内联进来的每条语句各按本表分类。
9. **concept / pattern / check** 不改任何节点，既不属于几何层也不属于外观层。它们在阶段 7 求值，读到的是全部几何时机修改施加之后、外观时机之前的场景（概念成员不因样式而变、不含皮肤）；它们的名字可以作外观层的选择器（5.4.2），不能作几何层的。
10. **几何层** := $P$ 里几何时机的全部语句（含它们的块）∪ 按第 5–7 条归入几何的定义；**外观层** := 外观时机的全部语句 ∪ 按第 5–7 条归入外观的定义。每条语句至多属于一层；只读的语义语句、没有引用的定义、import 不属于任何层。

```s3d
box crate size=2,2,2 on=pad mat=plain          // 几何层：节点语句
over crate size=2,3,2                          // 几何层：就地修改
over crate mat=steel                           // 外观层：等价于 style crate mat=steel
over crate mat=steel size=2,3,2                // 几何层：mat 与别的键混写（mat 成为 crate 的自有属性）
group g { box a size=1,1,1; over a color=#f00 } // 几何层：块里的 over
over #cargo use=crate_skin                     // 外观层：等价于 variant #cargo use=crate_skin
over #cargo use=crate_skin w=2                 // 外观层：use 之外的键是模板参数（4.5.1 第 4 条）
def crate_skin(w=1,h=1,d=1) { … }              // 外观层：只被上一行引用
def crate_skin : crate_skin { sphere k r=0.1 } // 外观层：扩展只被变体引用的模板
material plain color=#cfcabe                   // 外观层：重定义已有名字；若 plain 此前不存在则新增了名字（第 7 条）
```

### 5.4.2 时机与选择器限制

几何时机的选择器在阶段 5（或推迟到阶段 6，4.4.4）求值，此时**没有任何节点被求解**：没有世界变换、没有包围盒与紧包围盒、没有事实、概念不可求。外观时机与语义层的选择器在阶段 7–8 求值：全部几何时机修改已施加、全部非皮肤节点已求解、事实已推导、概念与模式已可求。因此两个时机能用的选择器构件不同（1.7.4、07-semantics.md 的 7.2.5；PLAN 的原则"外观层可以用事实与概念做选择器，几何层不能"）。下表按 1.7.1 的选择器文法逐一列出：

| 构件（1.7.1、1.7.3、1.5.6） | 几何时机（over / drop） | 外观时机与语义层（style、variant、外观时机的 over、concept、pattern、check） |
|---|---|---|
| 路径 `a.b.c`（含阵列段、副本段）、通配 `a.*` | 可以（按那一刻的树） | 可以（按阶段 6 定稿的树，皮肤尚不存在，7.2.5 第 3 条；`skin` 段只在皮肤模板体内的表达式与工具查询里有意义，1.6.4、7.8.4） |
| `#tag`、`kind()`、`all()`、`children()`、`descendants()` | 可以（按那一刻的树，4.5.2） | 可以（按阶段 6 定稿的树，不含皮肤，7.2.5） |
| 列表 `[a; b]`、`|`、`&`、`-` | 可以 | 可以 |
| `where` 里的 `kind`、`name`（含 `== 名字字面量`、`~ /re/`） | 可以 | 可以 |
| `where` 里的元数据键与它的谓词（8.2.2） | 可以 | 可以 |
| `where` 里的 `mat`（`==`、`!=`、`~`） | 可以：按那一刻的自有外观属性求 $E_g$（10.5.3） | 可以：按最终的 $E_g$，不计样式（10.5.3） |
| `where` 里的 `it`，只用于取路径 / 名字 / 种类、作集合或引用比较（`it == a`） | 可以 | 可以 |
| `where` 里的 `w h d x y z top bottom` | **不可以** | 可以 |
| `it` 或任何对象的锚点、度量、分量、坐标后缀（`it.top.y`、`it.w`、`a.top`、`b[0,1,0].x`） | **不可以** | 可以 |
| 关系谓词 `on supports against inside contains touching intersects`（1.5.6；06-facts.md） | **不可以** | 可以 |
| 概念名、模式名、`模式名.角色` | **不可以**（语义帧不在几何时机的环境里，1.5.8） | 可以 |
| `count(S)`：$S$ 由上面"可以"的构件组成 | 可以 | 可以 |
| 读到了上面任何"不可以"构件的 `let` | **不可以** | 可以 |

规则：

1. **判定是静态的。** 对几何时机 over / drop 的选择器表达式树在求值前做检查：出现任一"不可以"的构件即报错，整条语句无效（1.1.4 第 5 条、4.5.2），错误归该 over / drop 语句（5.2.5）；每条语句至多报一条此类错误（表达式树先序遍历遇到的第一个构件）。判定不依赖成员集合：`over kind(nothing) where h > 1 size=1,1,1` 报时机错误，不报"没有选中任何对象"；`over all() where false and h > 1 …` 也报（`and` 不短路，1.5.5，并且检查在求值前）。检查顺序：时机错误 → 选择器的名字解析错误（"找不到对象 X" 等，1.10.2）→ 空选择（1.7.1）。
2. **裸标识符的判定。** 几何时机选择器里的单段名字按 1.6.5 在几何时机的环境里解析（词法环境、场景树、全局索引；没有语义帧）。解析失败时：该名字是 $P$ 里某条 `concept` 或 `pattern` 的名字（5.3.1 的语义名字空间，不论定义在前还是在后）→ 报本节的时机错误；否则报"找不到对象 X"（1.10.2）。原型 applyOpinions 对两者都报"需要集合（对象、#标签、kind(…)、列表…），得到 X"（把未解析的名字当字符串），本版分别报时机错误与找不到对象。
3. **文案**（1.10.1：必须含引号里的关键信息）：
   - `where` 的尺寸 / 位置字段、锚点 / 度量 / 分量、概念名、模式名、读了它们的 let → "几何时机的选择器只能用静态量（路径、#标签、kind()、name / 元数据 / mat）"（1.7.4）；
   - 关系谓词 → "X() 依赖求解后的空间事实，不能用来决定位置 / 几何"（1.5.6，X 是谓词名）。
   实现**可以**在文案后附加触发的构件（如"（用了 h）"）。原型 applyOpinions 对关系谓词报"over 改的是几何，在求解之前生效，不能按空间事实选择（只改外观的 over 可以）"；对 `where` 里的 `w h d x y z top bottom` **不报错**——它在求解器上按需求盒并缓存，之后的修改对已缓存的盒不再生效（`box a size=1,3,1` 后 `over all() where h > 2 size=2,2,2`：原型不报错、a 仍是 1 × 3 × 1）。本版把它定为错误，理由是 1.7.4 已定、且这类选择器的结果依赖修改队列里已求过哪些盒，没有可判定的定义。
4. **静态字段的取值时刻。** 几何时机的 `kind`、`name` 按那一刻的树（换形后的节点 `kind` 是新种类，4.5.4；重建后的节点同名）；`mat` 按那一刻的自有外观属性与材质表（10.5.3：队列里排在前面的修改已生效）；元数据按 8.3（重建后重新求值）。外观时机与语义层按最终的树，`mat` 不计样式（10.5.3）。
5. **集合构件的范围。** 几何时机：`all()`、`kind()`、`#tag`、`children()`、`descendants()`、通配按那一刻的树求值（4.5.2）——已被 drop 的不在，此前 over 块新增的在，重建后的是新节点，影子与副本组不存在（推迟到阶段 6 的例外见 4.4.4），皮肤不存在。外观时机与语义层：按阶段 6 定稿的树，含影子、副本组、被变体隐藏的原物体（10.5.1、7.8.4）；皮肤在这些选择器求值时还不存在，所以任何选择集都不含皮肤（7.2.5 第 3 条）——`children()`、`descendants()`、通配与直接路径对皮肤的可见性只在皮肤模板体内的表达式与编译后的工具查询里有意义（1.6.4）；皮肤对各种机制可见与不可见的精确清单在 7.8.4。
6. **let。** 几何时机的选择器读到的最外层或块内 `let`，它的表达式视为该选择器的一部分，受同一张表的限制（可以用 `all()`、`kind()`、静态的 `where`；不能用字段、谓词、概念）。违反时报一条时机错误，归属该 `let` 语句（5.2.5：let 的表达式在被读取时才求值），读它的 over / drop 整条无效（不再另报）。同一个 let 被外观时机或语义层读时不受限；两个时机的缓存分开（1.5.8）。
7. **外观时机的 over** 的选择器与 style / variant 的完全相同（4.5.1：它在阶段 2 就被登记为一条 style 或 variant）：语义帧可见、搜索起点是根（1.5.8），可以用全部字段、关系谓词、概念与模式。它与 style / variant 的差别只在**空选择**（以及错误携带的语句种类，7.7.4 第 2 条）：选择集为空时，`over` 按 1.7.1 报错"X 没有选中任何对象"（语句无效——它本来也没有效果；7.7.4 第 1 条、7.1.4），`style` / `variant` 不报。几何时机的 over / drop 空选择同样按 1.7.1 报这条错误（第 1 条检查顺序的末项），所以 over / drop 在**两个时机**都报、style / variant 在任何情形都不报。原型 compileOnce 对三者都不报；本版按 1.7.1。
8. **时机错误不跨语句传染。** 一条几何时机 over 的选择器出错只使该语句无效（5.2.5、4.1.4），不影响同一文件里其他语句，也不影响任何外观层语句；反过来，外观层语句的错误不影响几何层。

```s3d
over kind(box) where name ~ /^tank/ : cyl r=1 h=3    // 几何时机：name 与 ~ 是静态量，合法
drop all() where fit < 0.3                            // 几何时机：元数据是静态量，合法
over kind(box) where mat == plain size=1,1,1          // 几何时机：mat 是静态量，合法
over all() where h > 2 size=2,2,2                     // 报错：几何时机的选择器只能用静态量（…）
over on(pad) size=2,2,2                               // 报错：on() 依赖求解后的空间事实，不能用来决定位置 / 几何
over tank size=1,1,1                                  // tank 是概念、不是对象 → 报时机错误；若也不是概念 → 找不到对象 tank
over tank mat=steel                                   // 外观时机：概念可用
style on(pad) & kind(box) color=#ffcc00               // 外观时机：关系谓词可用
variant slab where w > 20 use=planks                  // 外观时机：尺寸字段可用
```

### 5.4.3 外观层的定义

- **外观层**（appearance layer）= $P$ 里外观时机的全部语句：`style`、`variant`、外观时机的 `over`（5.4.1 第 10 条）；连同只为它们服务的定义——只被 `use=` 引用的 `def`、只被它们读的 `let`、重定义已有名字的 `material`（5.4.1 第 5–7 条）。
- 外观层的效果**只有阶段 8 的两件事**：
  1. **样式动作**（10.3.3）：`style` 与没有 `use` 的外观时机 `over` 得到选择集 $S$，把 $S$ 的成员及其全部后代（皮肤子树除外）的外观时机有效材质 $E$ 按 `mat`（整体替换）/ `color`（只换颜色与 alpha 给出的 opacity）更新。它不写任何节点的属性表，不触发任何重新展开。
  2. **变体挂载**（4.7、07-semantics.md 的 7.8）：`variant` 与带 `use` 的外观时机 `over` 得到选择集，经 7.8.2 的裁决（后写的赢、祖先裁决）得到挂载表，对表里每个节点 $N$ 及其当时的全部后代打 `hidden` 标记（4.7 第 1 条），在 $N$ 的子节点末尾挂一个段为 `skin` 的子树并求解它。$N$ 仍在树里、仍进 `all()`、仍有变换、包围盒与事实；皮肤不计入 $N$ 与它任何祖先的包围盒、不参与事实、不进 `all()` / `kind()` / `#tag`、不被样式直接作用（精确清单 7.8.4）。
- 外观层语句之间按 $P$ 的顺序（5.2.4、5.3.6）：样式逐条应用、后者覆盖前者（10.3.3）；同一节点被多条变体选中时后者生效，祖先与后代同时被选中时的裁决见 07-semantics.md 的 7.8.2。外观层与几何层之间**没有**顺序关系：全部几何时机修改在求解前施加，全部外观时机语句在求解后施加，不论它们在 $P$ 里如何交错（5.2.4）。
- 外观层的输入是阶段 7 的输出：选择器可以读全部 `where` 字段、事实（经关系谓词）、概念与模式（5.4.2）；`where mat` 读的是 $E_g$，所以一条样式的结果不会成为另一条样式（或变体）选择器的输入（10.5.3）——外观层内部也没有依赖关系要排序，只有 $P$ 的顺序。
- 外观层**不能**：新建非皮肤节点、删除节点、改任何属性、换形、改模板参数、改阵列数量、改定位、改元数据、改标签、改名字、改材质表之外的任何定义。要做这些，写几何层语句（它们的选择器只能用静态量——这是两层划分的代价与理由，D10 / D12 的落地）。

### 5.4.4 外观层不改变空间事实

**保证。** 设 $P$ 是一个场景，$P'$ 由 $P$ 经下列任意多次操作得到：

- 删除、新增、改写或移动（改变在 $P$ 里的位置）任何外观时机的语句（`style`、`variant`、外观时机的 `over`）；
- 改写 `material` 语句的属性，但不新增、不删除材质名（5.4.1 第 7 条）；
- 新增或改写只被外观时机语句的 `use=` 引用、且名字不与 $P$ 里任何其他模板同名的 `def`（含它的就地扩展）；
- 新增或改写只被外观时机语句读到、且名字不出现在任何几何时机求值的表达式里的最外层 `let`；
- 改动上述语句的元数据（8.2.1）。

则 $P$ 与 $P'$ 的编译结果在下列各项上**逐位相同**：

1. **节点集合与顺序**：去掉 `skin: true` 的条目后，`nodes[]` 的序列相同（皮肤只追加在被选中节点全部子节点之后，1.6.1 第 5 条，不改变其他节点的相对顺序）；每个非皮肤节点的 `path` `kind` `id` `tags` `concepts` `line` `file` `types` `meta` `depth` `late` `ghost` `of` `curve` 相同。
2. **变换与包围盒**：每个非皮肤节点的 `world`（$R$、$t$）、`box`、`tight` 相同。
3. **事实**：`facts[]` 的条数、顺序与每条的全部字段（6.6.1；参考输出里是 `rel` `a` `b` `text` `gap` `eps` `provider`）相同；`factsSkipped`、`factProviders` 相同。
4. **语义**：`concepts[]`、`patterns[]`、`checks[]` 的条目、成员、匹配、通过与否、顺序相同。
5. **几何层与语义语句的诊断**：归属于几何层语句、只读语义语句、以及节点路径不在皮肤子树里的全部错误与警告（文案、文件、行、节点路径）相同。

允许不同的只有：`items[]` 的 `material` 字段（10.6）与条目集合（被隐藏的节点没有条目、皮肤有）；`nodes[]` 的 `hidden` 标记；皮肤节点（`skin: true`）及其一切；`variants[]`、`materials`、`defs` 输出；归属于外观层语句的错误与警告、节点路径在皮肤子树里的错误与警告；因上述增删而变化的错误**排序**（1.1.5）；以及 1.5.6 的警告"kind() 不认识 X"（新增的 def 使 X 成为已知模板名）；8.4.3 的按文件输出只在参与编译的文件集合或各文件的文件头改变时不同。

**依据。** 这不是一条独立的规则，而是下面已定规则的推论；实现满足了它们就自动满足本保证：

- 4.1.1 的阶段表：外观时机是阶段 8，输入是阶段 7 的输出，"不改阶段 7 的任何变换、包围盒与事实"；07-semantics.md 的 7.1.1 两阶段求值：阶段一（几何 + 事实 + 语义）算出样式与变体的选择集，阶段二只替换外观。
- 样式只改 $E$（10.3.3、10.5.1），不写属性；`where mat` 读 $E_g$ 不读 $E$（10.5.3），所以样式不影响任何选择器（包括外观层自己的）。
- 事实：6.1.2——事实在阶段一末推导**一次**（全部几何时机修改已施加、求解已完成、变体的选择集已确定但皮肤不参与），阶段二的样式、只改外观的 over、皮肤挂载都不改变它；事实的集合与顺序只由阶段 7 之前的量决定，不读 `hidden`、不读样式、不读材质属性。6.2.1 第 3 条——段为 `skin` 的节点及其后代不是事实的对象；被变体隐藏的原物体照常是对象，事实按原来的几何算。
- 变体：4.7 "不改变阶段 7 的量"——皮肤不计入宿主与祖先的盒（2.6 的求并不含 `skin` 段）、不参与事实（6.2.1）、不进 `all()` / `kind()` / `#tag`（7.8.4）；被隐藏的原物体仍参与一切（4.7 第 1 条、7.8.4、10.4.3）。皮肤可以引用非皮肤节点，非皮肤节点引用不到皮肤（1.6.4：皮肤不进全局索引），所以依赖图里没有从皮肤指向非皮肤的边。
- 5.2.4：时机与位置无关，所以移动外观语句不改几何；5.3.4：material 的属性只进材质表，被 $E_g$ / $E$ 读；5.3.3：不与任何模板同名的 def 不改变任何已有定义；1.5.8：不被几何时机读到的 let 不进入任何几何时机的求值。
- 8.2.1：元数据不参与几何与语义求值。

**可检验的表述。** 对任何场景 $P$，令 $P^\circ$ 是把 $P$ 里全部外观时机语句删掉（其余不动）得到的场景；两份实现各编译 $P$ 与 $P^\circ$，按上面 1–5 项比较必须逐位相同。语料给出了一个实例：spaceport_blueprint.s3d 相对 spaceport.s3d 恰好只做了保证允许的操作（5.5.3），参考输出里两者的 193 个非皮肤节点的 `world` / `box` / `tight` / `kind` / `types` / `line` / `file` 逐一相同，203 条事实的 `text` 与 (`rel`, `a`, `b`, `gap`, `eps`, `provider`) 逐条相同（6.1.2 与 7.8.4 以此为例证），`errors` 都为空；不同的只有 `hangar.roof` 的 `hidden`、47 个 `skin: true` 的节点、条目的材质、`materials`、`variants` 与 `defs` 输出。

本保证是 PLAN 原则"语义层只读几何、非破坏分层"在层上的落地，也是逆向与评分能把风格文件排除在描述长度之外的依据（工具约定，不属于本规范）。

### 5.4.5 不需要声明

- 本规范**没有层声明**。文件头元数据（例如 `~layer=style`）、`import` 语句的元数据（`import "style.s3d" ~layer="style"`）、文件名、目录名都不被编译器读来决定任何行为（8.2.1 保证一、8.5 不保留键名）；它们只被记录与输出（5.1.4、8.4.3）。宿主与工具可以用它们标注文件用途，编译器不解释。
- 一个文件可以混写几何层与外观层语句，分类逐语句进行（5.4.1）。spaceport_blueprint.s3d 里有 `material`、`def`、外观时机的 `over`——按 5.4.1 第 5、7 条与表的第二行，全部属于外观层；若在同一文件末尾加一行 `over tower lv=10`，这一行是几何层的，其余不变，5.4.4 的保证对这一行不成立、对其余各行仍成立。
- **"外观层文件"**（风格文件、风格层）只是约定，含义是：文件里每条语句都属于外观层（5.4.1 第 10 条）。可判定的充分条件——文件（连同它 import 的文件）只含：注释与文件头；`style`；`variant`；外观时机的 `over`；重定义 $P$ 里更早已有名字的 `material`；名字不与 $P$ 里任何其他模板同名、且只被 `use=` 引用的 `def`（含对这样的模板的 `def X : X`）；名字不出现在任何几何时机求值的表达式里的最外层 `let`；以及满足同样条件的文件的 `import`。满足它的文件享有 5.4.4 的保证：把它从场景里去掉、换成别的这样的文件、或移动它的 `import` 的位置，阶段 1–7 的量不变。
- 工具可以按 5.4.4 的清单编译两次（带 / 不带该文件）来**验证**一个文件是不是外观层；本规范不要求编译器输出每条语句的分类。
- 同样没有"几何层"、"修改层"、"语义层文件"的声明：base / edits / semantics 的划分（5.5.1）是工程约定。编译器只看 $P$。

## 5.5 典型组合（示例）

本节的布局与文件名只是**示例**，用来说明前面各节的规则在多文件下如何组合；它们不是规范的一部分，工程布局由工具约定（工具手册）。

### 5.5.1 四层的组合

```s3d
// scene.s3d：组合根，只有 import
~lang=2
import "base.s3d"        // 基础描述：节点语句、def、material；可以是逆向工具生成的，不手改
import "edits.s3d"       // 修改层：over / drop / copy / def X : X / 新节点
import "semantics.s3d"   // 语义层：import 通用语义库，再写本场景的 concept / pattern / check
import "style.s3d"       // 风格层：style / variant / 外观时机的 over / 重定义 material / 变体模板
```

| 层 | 典型语句 | 属于（5.4.1） | 依赖前面层的什么 |
|---|---|---|---|
| base.s3d | 节点语句、`def`、`material`、最外层 `let` | 几何层（material 属外观层） | 无；可以单独编译 |
| edits.s3d | `over` / `drop`（几何时机）、`copy`、`def X : X`、新节点 | 几何层 | 节点名、模板名（经选择器与 `of=` 引用；位置无关，4.1.1） |
| semantics.s3d | `import "../lib/semantics.s3d"`、`concept`、`pattern`、`check` | 只读的语义语句 | 节点（经选择器）、事实；概念名的引用与位置无关（5.3.5） |
| style.s3d | `style`、`variant`、`over … mat= / color= / use=`、`material`（重定义）、变体用的 `def` | 外观层 | 概念名、事实（选择器）、材质名、模板名 |

- 四个文件都共享同一棵树、同一张模板表与材质表、同一个语义名字空间（5.1.1）；没有导出 / 隐藏。
- base 单独编译是一个合法场景；加上 edits 是另一个场景（它的 `errors` 与节点集合都可能不同）；再加 semantics 只多出 `concepts[]` / `patterns[]` / `checks[]` 与节点上的 `concepts` 标注；再加 style 按 5.4.4 只改外观。
- 评审稿、季节变化之类的多个风格可以是多个文件，由 scene 选择 import 哪一个；两个风格文件同时 import 时按 $P$ 的顺序后者覆盖前者（5.3.6）。
- 一个工程可以有更多或更少的层（没有语义层、把 edits 拆成多个文件、工具自动生成的局部修改文件再被 edits import），规则不变：只有 $P$。

### 5.5.2 顺序的后果

下面各条都是 5.2.4、5.3、5.4 的推论，用上面的四层说明：

1. **引用不要求顺序，覆盖才要求。** `over` / `drop` / `copy` 的选择器与 `of=` 在全部节点建好之后才解析（4.1.1），模板、材质、概念、最外层 let 的引用都用最终定义（5.3）；所以把 edits.s3d import 在 base.s3d **之前**，几何时机的修改照样找到目标。顺序决定的是：同名定义谁赢（material、def、concept、let：后写的赢，5.3.3–5.3.5）、`def X : X` 是否已有可扩展的定义（在 base 之前写就报错失效，5.3.3）、根下子节点与匿名段的顺序（edits 新建的节点排在 base 的之前还是之后，5.3.2）、同类修改之间的先后（5.3.6）、错误的排序（1.1.5）。所以"修改层在基础描述之后"是为了让 edits 的 `material` / `def` / `let` 压过 base 的，而不是为了让它能引用 base。
2. **edits 与 style 的相对顺序不影响几何**（5.2.4：时机与位置无关；5.4.4）。两种顺序的差别只在同名定义（style 重定义的 `material` 与 edits 里新写的同名 `material`，后写的赢）与节点顺序（style 里若有新节点——那它就不再是外观层文件）。
3. **semantics 的位置**。概念名的引用与位置无关（5.3.5），所以 style 可以 import 在 semantics 之前仍用它的概念；通用库必须在覆盖它的 `concept` **之前**进入 $P$（后写的替换先写的），所以 semantics.s3d 自己先 `import "../lib/semantics.s3d"` 再写覆盖。
4. **库只 import 一次**（5.2.3 第 3 条）。semantics.s3d 与 style.s3d 都想用通用库时，由序列里更早的那一层 import，后一层直接用名字。两个层各自 `import "base.s3d"` 的情形见下面的例子。
5. **前面的层不能撤销后面的层**（5.3.6）：style 能改 edits 新建节点的外观，edits 不能阻止 style 改某个节点——只能再写一个更晚的 style。几何层想"保护"某节点不被修改，没有写法；这是 $P$ 的顺序作为唯一依据的代价。
6. **插入一层会移动后面层的匿名编号与节点顺序**（5.3.2）：匿名节点不能按路径寻址，所以不影响引用；但集合顺序、事实顺序、输出顺序会变。要稳定这些，让新层 import 在末尾。

**两个层各自 import 同一个基础描述。** base.s3d 声明 `ground`、`hut h1`、`hut h2`、`lamp`（8 个节点）；style.s3d 与 edits.s3d 各写 `import "base.s3d"`；scene.s3d 写 `import "style.s3d"` 再 `import "edits.s3d"`。按 5.2.3：处理 style.s3d 的 import 时 base.s3d 加入 $L$ 并内联；处理 edits.s3d 的 import 时 base.s3d ∈ $L$ 且 ∉ $C$ → 报错"文件 base.s3d 已经 import 过"（归 edits.s3d 第 1 行），不导入；edits.s3d 自己的 `over h1 w=8`、`drop h2` 照常进入 $P$ 并作用于 style.s3d 带进来的那份 base。结果：5 个节点（h2 被 drop），h1 按 w=8 重建，style.s3d 的样式作用于重建后的 h1，`errors` 恰有这一条。原型 loadProgram 没有 $L$（只有链 `stack`），第二次 import 把 base.s3d 再内联一遍，得到 13 个节点（除被 `drop h2` 删掉的那一份 h2 外，每个路径出现两次）、没有任何错误；本版报错且只内联一次。要让两个层都能单独编译又能合在一起，由 scene.s3d 先 `import "base.s3d"`，style.s3d 与 edits.s3d 不再 import 它（单独编译它们时各自加一行 import 的工作由工具做，不属于本规范）。

### 5.5.4 因本章定义而预期不同的项

本章各节里以"原型 …；本版 …"标出的差异汇总如下（供第 9 章引用）：

| 节 | 项 | 原型行为（函数） | 本版 | 理由 |
|---|---|---|---|---|
| 5.2.3 | 同一文件被 import 两次 | loadProgram 只有加载链 `stack`，不在链上的已加载文件再次 import 时静默重复内联 | 报错"文件 X 已经 import 过"，不导入 | 重复内联必然造成同级重名并压掉中间的定义；1.8 节、1.6.6 已定（D19） |
| 5.2.3 | 循环 import | loadProgram 的链不含根文件；a → b → a 时 a 的语句被读入两次才报错 | 根文件始终在链上，第一次重复出现即报错，不重复任何语句 | 5.1.3 等价原则：不得有语句被内联两次 |
| 5.2.2 | import 路径 | joinPath 保留开头多出的 `..`、接受 `\` | `..` 越出根目录报错；`\` 报错 | 1.8 节已定 |
| 5.1.4 | 被 import 文件的 `lang` | loadProgram 不检查 `lang`；文件头行本身在原型里报"未知的类型 “~lang=2”"（makeStmt，9.1.2），不论在哪个文件 | 不是 2 时报"不支持的语言版本"，该文件不编译 | 8.1.5（D7） |
| 5.2.5 | 错误与节点的 `file` | 根文件的解析错误、style / variant / 几何 over 的选择器错误、事实提供者错误、皮肤节点 `skin` 的 `file` 为 `null` | 一律带文件 | 1.10.1：不允许没有文件归属的错误与输出 |
| 5.2.5 | copy 节点的 `file` / `line` | expandCopies 用源语句的（`hangar2` → spaceport.s3d:68） | copy 语句的（spaceport_edit.s3d:13） | 4.3.2 第 7 条 |
| 5.3.2 | 跨文件的最外层同名节点 | elaborate 不检查，产生两个同路径的节点 | 报错"同级重名 X"，后出现的语句无效 | 1.6.6（D18） |
| 5.3.3 | `def X : X` 而 X 尚无定义 | elaborate 报错但仍登记为只有扩展体的定义 | 报错且不登记 | 1.1.4 第 4 条：出错的定义不产生效果 |
| 5.3.4 | 块内、模板体内的 `material` | elaborate 的 `one` 静默忽略 | 报错"material 只能写在最外层" | 10.1.1（D6） |
| 5.3.5 | 同名 `pattern` | 两条都输出、匹配取最后一条 | 只保留最后一条 | 与 concept 一致（5.3.1） |
| 5.3.5 | concept / pattern / 最外层 let 异种同名 | pattern 静默压过同名 concept（semantic.setLazy 覆盖） | 报错"名字 X 已经用作 …"，后出现的语句无效 | 1.3.9 |
| 5.4.2 | 几何时机的选择器读 `w h d x y z top bottom` | applyOpinions 不报错；evalAst 的 `where` 分支在求解器上按需求盒并缓存，之后的修改对已缓存的盒不再生效（`over all() where h > 2 size=2,2,2` 无效果且无错误） | 报错"几何时机的选择器只能用静态量（…）"，语句无效 | 1.7.4 已定（D10）；原型的结果依赖缓存状态，没有可判定的定义 |
