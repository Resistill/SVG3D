# 4 派生与修改

**范围。** 本章定义从语句树到场景树的**展开模型**（模板实例化、阵列展开、copy、副本生成、修改的先后与时机），以及四种派生与修改机制的语义：`def`（模板、派生、就地扩展、实例化）、`copy`（结构派生）、`mirror` / `rotate` 的副本（跟随原件的影子）、`over` / `drop`（几何时机与外观时机的修改），再加上保名换形的可判定表与变体皮肤的挂载接口。本章只定义"树长什么样、每个节点带什么属性、哪些修改在什么时候生效"；节点的几何（第 2 章）、定位与朝向的求解（第 3 章）、材质的解析顺序（第 10 章）、变体与样式的选择（第 7 章）、元数据的传播（第 8 章）由各自的章定义，本章引用。

**依赖的章。** 01-syntax.md（术语、文法、属性表、路径与命名、求值环境、选择器、错误恢复）；02-geometry.md（局部包围盒、容器的包围盒）；03-solving.md（定位、朝向、副本的变换矩阵）。被依赖：05-layers.md、07-semantics.md、08-metadata.md、09-compat.md、10-materials.md。

**本章术语。** 在第 1 章术语之上补充：

| 术语 | 含义 |
|---|---|
| 源语句 | 生成某个节点的那条语句，含它的块；copy 生成的节点的源语句是被复制的语句（4.3.2） |
| 有效属性 | 节点当前的属性表：源语句的属性经过就地修改之后的结果（4.1.3） |
| 有效语句 | 源语句，但属性表换成有效属性（重建型修改按它重新展开，4.5.4） |
| 展开位置 | 一条语句被展开时所"视为写在"的位置，决定修改的先后（4.1.2） |
| 原件 original / 影子 shadow | 副本里对应原件子树里某个节点的节点叫影子；副本式节点 `R` 与副本组 `mirrored` / `r<k>` 叫**副本根** |
| 副本树 | 副本根及其下全部影子（含影子上新增的真实子节点）；它是原件子树的函数（4.4.2） |
| 影子覆盖 | 路径经过副本的 over 写在某个影子上的属性（4.4.4） |
| 孪生体 | 求解带影子覆盖的影子时所用的虚拟节点：原件的有效属性被影子覆盖替换、挂在原件的位置（4.4.4）；它不在场景树里 |
| 就地修改 / 重建型修改 | 只改节点属性表的修改 / 使节点按有效语句重新展开的修改（4.5.3、4.5.4） |

## 4.1 展开模型

### 4.1.1 阶段与顺序

编译把源码变成场景树与输出，经过下面的阶段。每个阶段的输入是上一阶段的输出；阶段内部的顺序在各节定义。实现**可以**合并或重排阶段，只要对任何输入得到相同的结果（节点、属性、错误、警告）。

| # | 阶段 | 输入 → 输出 | 顺序 |
|---|---|---|---|
| 1 | 解析与 import 内联 | 文件 → **程序**：全部语句的序列，每条带文件序号与行（1.1.5、1.8 节、05-layers.md） | 源码顺序；import 处展开为被引文件的语句 |
| 2 | 登记 | 程序 → 模板表（4.2.1）、材质表（10-materials.md）、全局帧的 let（1.5.8）、语义层语句表与外观时机的 over（4.5.1、07-semantics.md） | 按程序顺序；同名定义的覆盖规则见各节（模板：后定义覆盖先定义） |
| 3 | 展开 | 程序 → **场景树**（节点）、copy 表、**修改序列** | 深度优先按程序顺序：每条生成节点的语句按出现顺序建节点（1.6.1）；模板实例语句展开模板体（4.2.4）；`repeat` 展开实例（03-solving.md）；`copy` 语句只记入 copy 表并占住位置；几何时机的 `over` / `drop` 记入修改序列并带展开位置（4.1.2） |
| 4 | copy 展开 | copy 表 → copy 节点加入场景树；copy 块内的修改加入修改序列 | 4.3.5；与书写位置无关，只按 `of` 的依赖解析 |
| 5 | 修改 | 修改序列 → 修改后的场景树 | 按展开位置（4.1.2）逐条施加 4.5、4.6 的规则；副本树随原件而变（4.4.2） |
| 6 | 副本树定稿 | 场景树 → 带全部影子的场景树 | 4.4.2：按原件的最终状态生成副本树，再施加影子覆盖 |
| 7 | 求解、事实、语义阶段一 | 场景树 → 每个节点的变换与包围盒（03-solving.md）、空间事实（06-facts.md）、概念 / 模式 / 检查、样式与变体的选择集（07-semantics.md） | 各章定义 |
| 8 | 外观时机 | 选择集 → 变体皮肤挂载（4.7）并求解皮肤子树；样式（07-semantics.md）；材质解析（10-materials.md） | 不改阶段 7 的任何变换、包围盒与事实（D9） |

**与书写顺序的关系。** 下面这些按书写顺序（更准确地说，按程序顺序与展开位置）：节点顺序（1.6.1）；定义类语句的同名覆盖（模板 4.2.1、材质与 let 见各章）；修改的先后（4.1.2）；样式的先后（07-semantics.md）。下面这些**不**按书写顺序：

- `copy` 总在任何几何时机的修改之前展开，写在修改之后也一样（4.3.5）；
- 副本树总在全部修改之后定稿（4.4.2），所以副本跟随原件被修改后的状态；
- `def` 对程序里所有实例有效，写在实例语句之后也一样；`def A : A` 同理（4.2.6）；
- `over` / `drop` / `copy` 可以写在它们引用的对象的声明之前（阶段 3 建好全部节点之后才解析选择器与 `of`）；
- 外观时机的修改在求解之后生效，无论写在哪里（4.5.1）。

### 4.1.2 展开位置与修改的先后

每条语句 $s$ 有**展开位置** $\mathrm{pos}(s)$：

1. 最外层的语句，以及最外层语句的块（任意深度）里的语句：$\mathrm{pos}(s)$ = 它自己在程序里的位置（文件序号，行，同行内的先后）。
2. 模板体里的语句（含派生链与扩展体，含体内的块）：$\mathrm{pos}(s) = \mathrm{pos}(\text{实例语句})$，其中实例语句是这次展开它的那条模板实例语句；实例语句自己又在模板体或 copy 里时递归适用。
3. 被 `copy` 复制而展开的语句，以及 copy 块里的语句：$\mathrm{pos}(s) = \mathrm{pos}(\text{copy 语句})$。
4. `over` 块里的语句：$\mathrm{pos}(s) = \mathrm{pos}(\text{over 语句})$。
5. 变体皮肤里的语句：不进修改序列（皮肤在外观时机挂载，4.7）。

**修改序列**里两条几何时机的修改 $m_1$、$m_2$ 的先后：先比较 $\mathrm{pos}$；相同时（同一实例语句、同一 copy 语句或同一 over 块展开出来的）按它们在被展开的那段源码里的先后——模板体按派生链从基到派生依次、每个体内按源码顺序（4.2.5），copy 块按块内顺序，over 块按块内顺序。这个顺序是**全序**，所以"后写的覆盖先写的"有精确含义：$\mathrm{pos}$ 大的后施加。

后果（都是定义，不是实现细节）：

- 最外层的 `over x.base size=3` 写在实例语句 `t x` 之前时，它在 `t` 体内的 `over base size=2` 之前施加，体内的赢；写在 `t x` 之后则最外层的赢。
- copy 块里的 `drop cap` 的位置是 copy 语句的位置，所以它在 copy 语句之前的最外层修改之后、之后的最外层修改之前施加。
- 同一 over 块里的嵌套 `over` / `drop` 在块内按顺序施加，并且在该 over 语句自己的属性修改之后（4.5.5）。

```s3d
over watch.cabin size=5,2.5,5                    // pos = 141 行
copy watch2 of=watch on=ground[-0.3,1,-0.62] {   // 块内两条语句的 pos 都是 143 行
  drop cap
  repeat rail n=(2,1,2) step=3.8,0,3.8 center=true on=cabin { cyl post r=0.06 h=1 }
}
```

### 4.1.3 有效属性与有效语句

- 每个由语句生成的节点有一张**有效属性**表，初值 = 源语句的属性（模板实例：实例语句上的参数与定位 / 外观属性；阵列实例节点与副本组没有源语句，表为空且不接受属性，4.5.3）。就地修改（4.5.3）按键更新这张表；表达式在写下它的地方求值（1.5.8）。
- 节点的**有效语句** = 源语句，但属性表换成有效属性表、块换成源语句的块（over 块新增的语句**不**计入）。重建型修改（4.5.4）与保名换形（4.6）按有效语句重新展开，所以之前对该节点自身的就地修改在重建后仍然有效（原型 applyOpinions 在重建时从 `m.stmt.props` 重新取属性，丢弃它们；本版不丢弃）。重建得到的新节点的源语句就是这条有效语句。
- 影子的有效属性 = 原件的有效属性（在全部修改结束后的值）逐键被该影子的覆盖替换（4.4.4）。
- `copy` 复制的是**源语句**，不是有效语句（4.3.2）。

### 4.1.4 展开深度与错误局部化

- **展开深度**：最外层语句的深度为 0；模板体里的语句深度 = 实例语句深度 + 1；被 copy 复制而展开的语句深度 = copy 语句深度 + 1；块里的语句与所在语句同深度。深度大于 32 的语句报错"展开层数超过 32（模板 X 递归？）"，该语句不展开（节点退化，1.1.4）。
- **递归模板**：模板 $T$ 的体（含派生链、扩展体、体内任意深度的块与 over 块）里出现模板 $U$ 的实例语句记作 $T \to U$；这张图里有环时，环上每个模板的 `def` 报错"模板 X 递归地包含了自己（X → Y → X）"，这些模板的实例不展开体（节点退化）。这条在阶段 2 静态判定；深度限制只用来兜住经由 copy 形成的递归。
- 错误局部化（1.1.4）在本章的落实：一个模板实例缺参数只影响该实例；一个 copy 失败只影响该 copy；一个副本根出错只影响它的副本树；一条 over 对某个成员出错只影响该成员（其他成员照常）；一条 over / drop 的选择器出错只使该语句无效。本章各节的"报错"都按此恢复。

## 4.2 def：模板

### 4.2.1 登记

语法见 1.3.4。`def` 只能写在最外层（块内、模板体内报错，1.3.15）。阶段 2 按程序顺序把每条 `def` 登记进**模板表**（名字 → 定义）：

- 普通定义 `def A(…) { … }` 与派生定义 `def B : A(…) { … }`：登记为 A / B 的**当前定义**；同名已有定义时**后定义的覆盖先定义的**（这是层的覆盖机制，05-layers.md 规定是否给警告）。
- 就地扩展 `def A : A(…) { … }`：登记时捕获 A 在**此刻**的当前定义作为它的基定义，然后把自己登记为 A 的当前定义（4.2.6）；此刻 A 没有定义时报错"要扩展的类型 A 还没有定义"，这条 `def` 无效（不登记；原型里仍登记成只有扩展体的类型，本版不允许）。
- 模板名不得是内置种类词、关键字或其他保留名（1.6.9；`def box` 报错"模板不能与内置种类同名"，D27），不得与同一程序里的 concept / pattern 名相同（1.6.9）。
- 实例语句、`over … : T`、`use=T` 引用的都是 T 在阶段 2 结束后的**最终**当前定义；派生定义里的基类型名 `: A` 同样在实例化时解析为 A 的最终定义（4.2.5）。因此 `def` 与 `def A : A` 对程序里所有实例有效，不论写在实例之前还是之后，也不论在哪个文件里。

### 4.2.2 参数表

- 参数 `p=默认值` 是**可选参数**，`p`（没有 `=`）是**必填参数**。参数名的限制见 1.3.4：不得是关键字或保留名（`w h d x y z` 允许）、不得与 P 组属性名（1.4.4）或 `use` 相同、同一签名里不得重复。因此实例语句上的每个键要么是参数、要么是 P 组属性，不会二义。
- 一个模板的**参数表**是有序表（名字 → 默认值表达式或"必填"），顺序 = 首次声明的顺序。派生与扩展对参数表的影响见 4.2.5、4.2.6。
- 默认值是表达式，在**模板体帧**里求值（1.5.8）：可以引用同一模板（含派生链）的其他参数与全局帧的 let、`metre`；对象名从实例节点的父节点起解析。参数之间循环引用报错"X 循环引用了自己"（读到它的实例的该参数视为缺失，见 4.2.8）。

```s3d
def truss(w=6, h=48, lv=8) { … }            // 三个可选参数
def shed(w=34, h=22, d=26, t=0.8, dw=12) { … }
def f(a=1, b=a*2, c=house_w) { … }           // 默认值可以引用别的参数与全局 let
def g(n) { … }                               // n 必填
```

### 4.2.3 实例语句

形态见 1.3.3（`模板名 [名字] { #tag | k=v | ~k=v }`，不接受块）。展开一条实例语句：

1. 查模板表；没有这个名字（也不是内置种类）报错"未知的语句种类"，整条语句丢弃（1.1.4 第 1 条）。
2. 解析**派生链**：从最派生到最基础的定义序列（4.2.5）；链上出现循环报错"类型 X 的派生链形成了循环"，基类型不存在报错"X 的基类型 Y 没有定义"（都报在 `def` 的行），实例节点退化、体不展开。
3. 建**实例节点**：种类 = 实例语句的种类词（最派生的模板名；`kind(T)` 对链上每个 T 为真，1.6.7）；名字、标签、元数据按语句；有效属性 = 实例语句上的 P 组属性；另记**参数绑定表**：对参数表里的每个参数，值 = 实例语句写明的 `k=v`（在实例语句的上下文里求值，1.5.8）或默认值（在模板体帧里求值）；必填参数没写报错"模板 X 缺少参数 p"，节点退化、体不展开。实例语句上既不是参数也不是 P 组的键报错"模板 X 没有参数 k"，节点退化（1.4.7），体照常展开。
4. 展开体（4.2.4）。

实例节点是一个容器：它的包围盒按第 2 章 2.6 节由子节点求并（没有 envelope），定位按第 3 章（容器按包围盒定位，D13）。实例节点的子节点就是体展开出来的节点。

```s3d
truss tower on=pad[-0.7,1,-0.7] mat=steel    // 全用默认参数；on / mat 是 P 组属性
house h4 floors=3 at=7,0,8                   // floors 是参数，at 是定位
shed hangar on=ground[-0.45,1,-0.2]
turbine t turn=-35 phase=idx*40              // 写在 repeat 体里：phase 在实例语句处求值，idx 可见
```

### 4.2.4 体的展开与求值环境

- 体的语句以实例节点为父节点展开，允许的语句见 1.3.15（实体、曲线、容器、模板实例、copy、over、drop、let；`def` / `material` / `import` / 语义层语句报错"X 只能写在最外层"）。
- 展开顺序：派生链反转，**先最基础的体，再逐层派生 / 扩展的体**，每个体内按源码顺序。子节点顺序 = 这个顺序（1.6.1）。体内的 `over` / `drop` 进修改序列，展开位置 = 实例语句的位置（4.1.2），作用范围限于该实例的子树（4.5.2）。体内的 `copy` 进 copy 表，每个实例各复制一份。
- 求值环境（D26，1.5.8）：体内语句的词法环境是**模板体帧**（参数、体内最外层的 let、全局帧），看不见实例语句所在块的 let 与实例所在阵列的 `i j k idx`；对象名从各语句自己的父节点（实例节点或体内更深的容器）起向上解析，所以同一模板放在不同位置可以绑定到不同的对象（`on=body` 先找实例自己的 `body`，再找实例所在容器里的）。实例语句**写明的**参数值在实例语句的上下文里求值（块内 let、`i j k idx` 可见）。
- 参数是惰性的：第一次被读取时求值，求值结果在同一时机内缓存（1.5.8）。
- 模板体帧里的参数名遮蔽同名对象（`blade` 参数遮蔽体内名为 `blade` 的节点；该节点仍可从外部按路径引用，例如 `farm.1.t.rotor.blade`）。

```s3d
let house_w = 7
def house(w=house_w, floors=1) {
  box body size=w,3*floors,w*0.8 mat=plain
  wedge half size=w/2,2.2,w*0.8 on=body align=left mat=plain
  mirror half2 of=half across=body axis=x
  box door size=1.2,2.2,0.2 against=body.front align=bottom mat=plain
}
group street on=ground[0.6,1,0] {
  let w = 99                 // 对 house 的体不可见：h1.body 仍按 house_w = 7
  house h1 at=-7,0,-8
}
```

### 4.2.5 派生 `def B : A`

语法见 1.3.4：`def B(新参数…) : A(覆盖…) { 体 }`，$B \ne A$（$B = A$ 是就地扩展，4.2.6）。

**派生链。** 实例化 B 时，从 B 的最终定义出发，沿 `: 基类型` 逐级取基类型的**最终**定义（4.2.1；基类型是就地扩展链时取整条链，4.2.6），直到一个没有基类型的定义，得到序列 $B = D_0, D_1, \dots, D_m$（最派生在前）。规则：

- 某个 $D_i$ 的基类型名不在模板表里：报错"X 的基类型 Y 没有定义"（报在 $D_i$ 的 `def` 行）；该实例节点退化、体不展开。
- 某个定义在链上出现第二次（`def A : B {}` 与 `def B : A {}`）：报错"类型 X 的派生链形成了循环"（报在实例所属模板的 `def` 行），实例节点退化、体不展开。
- 链上的定义个数超过 32 按循环处理（兜底；正常文件达不到）。
- 基类型名在**实例化时**解析，所以 `def B : A` 写在 `def A` 之前合法，也取 A 在阶段 2 结束后的最终定义（含之后对 A 的就地扩展与整体替换，05-layers.md 的 5.3.3）。

**参数表。** 从链尾（最基础）到链头（最派生），对每个定义 $D$ 依次：

1. 施加 $D$ 的**覆盖表** `: A(k=v, …)`：每个键 $k$ 必须已在当前参数表里（由更基础的定义声明），否则报错"X 覆盖了基类型没有的参数 k"（报在 $D$ 的 `def` 行；该实例节点退化、体不展开）。成立时把 $k$ 的默认值换成 $v$（$k$ 原来是必填参数时变成可选参数）；$k$ 在表里的位置不变。
2. 加入 $D$ 自己的参数表 `def X(…)`：新名字追加在表尾；名字已在表里时**重新声明**它：默认值换成这次写的（没写 `=` 则变成必填参数），位置不变。同一个 $D$ 里一个名字既出现在覆盖表又出现在参数表报错"参数 k 既被覆盖又被重新声明"（报在 `def` 行，该 `def` 无效，4.2.1 第 3 条的恢复：不登记）。

覆盖表与默认值一样是表达式，在模板体帧里求值（可以引用其他参数与全局 let），每个实例各求一次（惰性）。

**体。** 展开顺序 4.2.4：$D_m$ 的体最先、$D_0$ 的体最后，每个体内按源码顺序。全部体共用**一个**模板体帧：参数表里全部参数、每个体内最外层的 `let`（不同体里同名 `let` 报错"重复定义 X"，报在后展开的那条）。派生体里的语句可以引用基类型体里的节点（`on=body`），基类型体里的语句也可以引用派生体里的（前向引用合法，1.6.5 在求解时解析）。派生体里的 `over` / `drop` 的作用范围是该实例的子树（4.5.2），它们的展开位置是实例语句的位置（4.1.2），并按"基的体先、派生的体后"的顺序排在同一位置的修改里——所以派生体里的 `drop roof` 删掉的是基类型体建出来的 `roof`，`over roof color=…` 改的也是它。

**种类。** 实例的种类是 B（最派生的模板名）；`kind(T)` 对链上每个名字为真（4.2.7）。

```s3d
def house(w=house_w, floors=1) { box body size=w,3*floors,w*0.8 … }
def chimney_house : house(floors=2) {          // 覆盖 floors 的默认值；没有新参数
  box chimney size=0.8,3,0.8 on=body[0.55,1,0.3] mat=plain   // 引用基类型体里的 body
}
chimney_house h2 at=7,0,-8                     // 子节点：body half half2 door chimney；body 高 6
chimney_house h5 floors=3 at=…                 // 实例写明的值压过覆盖表：body 高 9

def tower(floors=1) { box base size=4,3*floors,4; wedge roof size=4,1.5,4 on=base }
def tall : tower(floors=3) { drop roof; cone spire r=2 h=4 on=base }   // 派生体可以删基的部件
def flat(parapet=0.3) : tower(floors=2) { box rim size=4.4,parapet,4.4 on=base }   // 新参数
def strict(floors) : tower { }                 // 重新声明：floors 变成必填
```

### 4.2.6 就地扩展 `def A : A`

语法同 4.2.5，但基类型名等于自己的名字。它**不**建立新类型，而是给 A **追加**一段体（可以带新参数与覆盖表）。

- **登记**（4.2.1）：这条 `def` 捕获登记时 A 的当前定义 $D$ 作为基定义，并成为 A 的新当前定义。多次扩展依次接成链 $D, E_1, E_2, \dots$（每个 $E_i$ 的基定义是 $E_{i-1}$）。之后再出现 `def A(…) { … }` 或 `def A : B { … }`（$B \ne A$）时整条链作废（05-layers.md 的 5.3.3）。此刻 A 没有定义时报错"要扩展的类型 A 还没有定义"，这条 `def` 无效。
- **派生链**：实例化 A 时链是 $E_k, \dots, E_1, D$（最后的扩展在前），再接 $D$ 自己的基类型链（$D$ 若是 `def A : C`，则 $C$ 的最终定义及其链接在其后）。参数表与体的规则同 4.2.5：参数表从 $D$（及其基）起依次施加各 $E_i$ 的覆盖表与新参数；体先展开 $D$（及其基）的，再依次展开 $E_1, E_2, \dots$ 的。因此扩展体里可以用 `over` / `drop` 修改原体建出的部件，也可以引用它们。
- **传播**：所有 A 的实例（不论写在哪个文件、扩展之前还是之后）与所有以 A 为基类型的派生类型的实例都得到扩展后的 A（4.2.1：引用用最终定义）。`over x : A` 换形到 A、变体 `use=A` 同样用扩展后的定义。
- **种类**：`kind(A)` 不变；`types`（4.2.7）里 A 只出现一次（链上同名的定义去重）。
- 扩展体里的语句的展开位置是实例语句的位置（4.1.2）；它们排在 $D$ 的体内修改之后。05-layers.md 的 5.2.4 说明的"后面层里最外层的 over 总是晚于前面层里实例的模板体内修改"也适用于扩展体里的修改。

```s3d
def tower(floors=1) { box base size=4,3*floors,4; wedge roof size=4,1.5,4 on=base }
tower a
def tower : tower { box flag size=0.1,2,0.1 on=base[0.8,1,0.8] }   // a 多出 flag
def turbine : turbine { over rotor n=3 }                           // 所有风车从 3 片变 4 片（rotate 的 n 是就地修改，4.5.3）
```

### 4.2.7 类型：`kind()` 的 is-a 与输出

- 一个节点的**类型链** $\mathrm{types}(n)$：实例节点的类型链 = 派生链上各定义的名字按链的顺序去重（最派生在前；就地扩展的各段同名，只留一个）。副本式节点 R（`of=A`）、影子的类型链 = 原件的（1.6.7）；copy 节点的类型链按它重新展开出的语句算（与原件相同；参数不改类型链）；保名换形到模板 T 的节点的类型链 = T 的派生链；皮肤节点 `skin` 的类型链 = 变体模板的派生链。种类不是模板名的节点类型链为空。
- `kind(T₁, T₂, …)`（1.5.6、1.6.7）选中满足"种类 ∈ 参数"或"类型链 ∩ 参数 ≠ ∅"的节点（不含皮肤子树，1.7.2）。所以 `kind(house)` 选中 `chimney_house` 的实例（is-a），`kind(chimney_house)` 不选中 `house` 的普通实例；`kind(truss)` 也选中 `mirror tower2 of=tower` 生成的 R 节点。
- `where` 里的 `kind` 字段是节点的种类（最派生的模板名），不是链（1.6.7）；要按 is-a 判断用 `kind()`。
- **输出**：`nodes[]` 的每个条目带 `types`：类型链非空时是名字数组（最派生在前，例如 `["chimney_house","house"]`）；为空时是 `null`。`kind` 字段是 1.6.7 的种类（模板实例写最派生的模板名）。原型对 R 节点与影子输出 `types: null`、对 R 节点输出 `kind: "mirror→group"` 这样的组合串；本版按 1.6.7 输出原件的种类与类型链（4.8 列出受影响的条目）。

### 4.2.8 错误

| 文案 | 触发 | 恢复（1.1.4） |
|---|---|---|
| def 只能写在最外层 | `def` 出现在任何块里（1.3.15） | 该 `def` 无效 |
| 模板不能与内置种类同名 / X 是保留名，不能用作模板名 | 模板名是内置种类词、关键字或保留名（1.6.9） | 该 `def` 无效 |
| 参数名与属性名重名 / X 是保留名 / 重复的参数 | 1.3.4 | 该 `def` 无效 |
| 参数 k 既被覆盖又被重新声明 | 4.2.5 | 该 `def` 无效 |
| 要扩展的类型 A 还没有定义 | `def A : A` 时 A 无当前定义（4.2.1） | 该 `def` 无效 |
| 模板 X 递归地包含了自己（X → Y → X） | 4.1.4 的静态环 | 环上模板的实例节点退化、体不展开 |
| 展开层数超过 32（模板 X 递归？） | 4.1.4 | 该语句不展开（节点退化） |
| 未知的语句种类 | 种类词既不是内置种类也不是模板（4.2.3） | 整条语句丢弃 |
| X 的基类型 Y 没有定义 | 4.2.5 | 实例节点退化、体不展开 |
| 类型 X 的派生链形成了循环 | 4.2.5 | 实例节点退化、体不展开 |
| X 覆盖了基类型没有的参数 k | 4.2.5 | 实例节点退化、体不展开 |
| 模板 X 缺少参数 p | 必填参数没写（4.2.3） | 实例节点退化、体不展开 |
| 模板 X 没有参数 k | 实例语句上的未知键（4.2.3、1.4.7） | 实例节点退化；体照常展开 |
| X 循环引用了自己 | 参数默认值 / 覆盖表互相引用（1.5.8） | 读到该参数的属性报错，持有该属性的节点退化 |
| X 只能写在最外层 | 体内出现 def / material / import / 语义层语句（4.2.4） | 该语句无效 |
| 模板实例不能有子语句 | 实例语句带块（1.3.3） | 位置错误：整条语句无效 |

同一条 `def` 的多个错误各报一条。派生链上的错误报在出错的那条 `def` 的文件与行，并带实例节点的路径（1.10.1），所以同一模板的多个实例各报一次。

## 4.3 copy：结构派生

### 4.3.1 语句与 `of` 的允许对象

语法见 1.3.14：`copy R of=A { #tag | k=v | ~k=v } [ { 块 } ]`。`R` 是新节点的名字（必填），`of=A` 是**对象路径**（1.4.1：单个对象的路径，不带坐标后缀，不是集合、不是锚点；写了别的报错"copy 的 of 写一个对象名"，该 copy 无效）。路径按 1.6.5 解析，搜索起点是 copy 语句所在块的节点（1.5.8：拷贝节点的父节点），在阶段 4 对当时的树求值（4.3.5）。

解析得到的节点 $A$ 按下表处理：

| $A$ 是 | 处理 |
|---|---|
| 有源语句的节点：实体、曲线、group / union / subtract / intersect、repeat 节点、容器式 mirror / rotate 节点、模板实例、另一个 copy 节点、副本式节点 R₀（`mirror R₀ of=…`） | 复制 $A$ 的源语句（4.3.2） |
| 阵列实例（`row.2`） | 没有源语句：生成一个 `group` 节点 R，子语句 = 该阵列的体（每条按 4.3.2 在该实例的阵列实例帧里展开，`i j k idx` 取该实例的值）；copy 自己的属性落在这个 group 上 |
| 自己的父节点或任何祖先（`group g { copy c of=g }`） | 报错"copy 不能复制包含自己的对象 X"，该 copy 无效 |
| 影子、副本组、皮肤子树里的节点 | 在阶段 4 还不存在（副本树在阶段 6、皮肤在阶段 8 生成），路径解析报错"找不到对象 X"，该 copy 无效（原型 expandCopies 同样报"copy 找不到原对象"） |
| 退化节点 | 照常复制源语句；新节点因同样的原因退化，错误按 05-layers.md 的 5.2.5 归属 |

复制副本式节点 R₀ 得到的是另一条 `mirror R of=… across=…`（R₀ 的源语句换名），即原件的又一个副本；因为副本式节点不接受定位属性（1.4.4），这种 copy 上写定位属性按 4.3.3 报错。要得到一个可以独立定位的拷贝，copy 原件而不是副本。

### 4.3.2 复制的内容是定义

`copy R of=A` 把 $A$ 的**源语句**（1.1.2 的"语句"：种类词、名字、标签、属性、元数据、块里的全部子语句，含嵌套任意深度）在 R 的位置重新展开一次，等价于在 copy 语句的位置写下那条语句，但：

1. 名字换成 R；标签 = $A$ 的源语句的标签 ∪ copy 语句的标签（1.6.7）；元数据按 08-metadata.md 的 8.3.5 合并；属性按 4.3.3 替换。
2. 词法环境 $E$ 是**原语句的**：原语句所在块的帧（块内 `let`）、原语句所在模板体的帧（参数绑定取 $A$ 所属实例的绑定——所以 `copy b of=h1.body` 里 `size=w` 的 `w` 是 h1 的 w）、原语句所在阵列实例的帧（`i j k idx` 取 $A$ 所属实例的值）、全局帧。原语句是模板实例语句时它重新实例化：参数按 4.2.3 重新绑定（写明的值在原语句的环境里求值，默认值在**新**实例的模板体帧里求值），体按 4.2.4 重新展开，所以体内语句用的是新实例自己的参数与对象名。
3. 场景位置 $P$ 是**新位置**：被复制的那条语句自己的属性从 R 的父节点起解析对象名；块里的语句从 R（或拷贝子树里对应的容器）起解析。因此 `on=legs`、`against=body.front` 这类相对引用在拷贝里绑定到拷贝自己的部件（语料 semantics.s3d 的 `copy watch2 of=watch`：`watch2.cabin` 的 `on=legs` 绑定到 `watch2.legs`）。1.5.8 表里"被 copy 复制的语句"一行按本条理解：$E$ 取原语句的，$P$ 取新位置。
4. 复制的是源语句，**不含**任何 over / drop 对 $A$ 的修改（就地的与重建型的都不含，因为 copy 在全部几何时机的修改之前展开，4.1.1、4.3.5），也不含 over 块给 $A$ 加的子节点、不含 $A$ 的影子覆盖。语料 spaceport_edit.s3d 依赖这一点：`over hangar dw=16` 写在 `copy hangar2 of=hangar` 之前，参考输出里 `hangar2.body.opening` 仍是 12 宽（4.8）。要让拷贝带上修改，把修改写进 copy 块（4.3.4）。
5. 源语句块里的 `copy` 一并复制（成为新的 copy，4.3.5）；块里的 `over` / `drop` 进修改序列，展开位置是这条 copy 语句的位置（4.1.2），作用范围是拷贝子树（4.5.2）。
6. 新节点的种类 = 源语句的种类词（模板实例 → 该模板，类型链同原件，4.2.7）；节点顺序上它占 copy 语句的位置（1.6.1）。拷贝是**独立节点**：进全局索引，可以被任何选择器选中、被再次 copy、被 mirror / rotate 复制；之后对 $A$ 的任何修改都不影响 R，反之亦然。
7. 输出里 R 的 `file` / `line` 是 **copy 语句**的（它是 R 的名字与位置所在的语句；05-layers.md 的 5.2.5：copy 语句自己的属性归 copy 语句）；R 的子节点的 `file` / `line` 是各自源语句的。原型给 R 输出原语句的 `line`（spaceport_edit 的 `hangar2` 带 68 行、spaceport.s3d），本版输出 copy 语句的（13 行、spaceport_edit.s3d）。R 的 `of` 字段为 `null`（它不跟随任何节点，4.4.5）。

```s3d
def hut(w=4) { box body size=w,3,w; wedge roof size=w,1.5,w on=body }
hut h1 on=ground[-0.5,1,0]
over h1 w=8                                  // 只改 h1
copy h2 of=h1 on=ground[0.5,1,0]             // h2 是 hut 的新实例，w 仍是 4（复制的是定义）
copy h3 of=h1 w=8 on=ground[0,1,0.5]         // 要 8 宽就自己写参数
```

### 4.3.3 copy 自己的属性

copy 语句接受（1.3.14、1.4.4）：P 组全部属性，以及 $A$ 的源语句是模板实例语句时该模板（最终定义）的参数。属性值在 copy 语句的上下文里求值（1.5.8：写 copy 处的帧，搜索起点是 R 的父节点），**不是**在原语句的环境里。

设 $S_A$ 是源语句的属性表、$S_C$ 是 copy 语句的属性表（去掉 `of`）。新语句的属性表按下面的顺序得到：

1. 从 $S_A$ 出发。
2. 若 $S_C$ 含任何定位关系键（`at` `on` `under` `against` `inside` 之一），从表里删除全部**定位键**：五个关系键与 `pin` `gap` `offset` `align` `alignto`（新的定位关系从头描述位置；原来配合旧关系写的对齐与间隙不再有意义）。朝向键（`turn` `tilt` `roll` `rot` `aim` `aimwith`）与外观键（`mat` `color`）保留。
3. 对 $S_C$ 的每个键 $k$：表里已有则替换其值，否则追加。参数键替换的是原语句写明的参数值（或补上默认值没有的显式值）。

结果表里的键按 1.4.8 的方式对新节点的种类检查：新节点不接受的键（例如对曲线写 `at`、对 span 写 `turn`、对副本式节点写定位键）报错"copy 没有属性 k"（报在 copy 语句上），新节点退化。$S_C$ 里既不是 P 组也不是 $A$ 所属模板参数的键（例如 `size`）按 1.3.14 报错"copy 没有属性 k"，该 copy 无效（要改专有属性写进块：`copy b of=a { over it size=2,2,2 }`，或直接 `over b size=…`）。

原型 expandCopies 的规则与本节相同（替换定位关系时删除关系键与 `align` `alignto` `gap` `offset` `pin`，其余逐键覆盖）。

```s3d
box a size=1,1,1 on=ground align=left gap=0.5 turn=30 mat=steel
copy b of=a at=5,0,0           // b：size 1,1,1；at=5,0,0；没有 align / gap；turn=30、mat=steel 保留
copy c of=a mat=rust           // c：定位与 a 相同（on=ground align=left gap=0.5），材质换成 rust
copy d of=a                    // d 与 a 完全同样的属性 → 同一位置的两个盒子（合法）
```

### 4.3.4 块

copy 可以带块（1.3.15：实体、曲线、容器、模板实例、copy、over、drop、let）。块的语义**等于**对 R 施加一条 over 块（4.5.5）：

- 展开位置 = copy 语句的位置（4.1.2）；块内语句按源码顺序。
- 词法环境是块帧（`it` = R；R 是 repeat 节点时每个实例另有 `i j k idx`），父帧是写 copy 处的帧（1.5.8）；搜索起点是 R。
- 块里生成节点的语句成为 R 的新子节点，追加在 R 现有子节点之后（1.6.1 第 3 条）；R 是 repeat 节点时按 4.5.5 对每个阵列实例各展开一份。
- 块里的 `over` / `drop` 进修改序列，位置同上，作用范围是 R 的子树（4.5.2）；它们的选择器从 R 起解析（`drop cap` 删的是 `R.cap`）。
- 块里的 `copy` 按 4.3.5 展开（它的 `of` 从 R 起解析，所以 `copy x of=body` 复制的是 `R.body`）。

块里的修改在阶段 5 按位置施加，所以它们能看到 R 的全部子节点（含 R 自己块里的 copy 展开出来的）。原型 expandCopies 直接把块里的语句展开在 R 之下而不区分 R 是不是阵列（`copy row2 of=row { cyl post on=tank }` 把 post 挂在 repeat 节点下，不属于任何实例）；本版按 4.5.5 对每个实例展开。语料里 copy 块的目标都不是阵列。

```s3d
copy watch2 of=watch on=ground[-0.3,1,-0.62] {   // semantics.s3d:143
  drop cap                                        // 删 watch2.cap（watch.cap 不受影响）
  repeat rail n=(2,1,2) step=3.8,0,3.8 center=true on=cabin { cyl post r=0.06 h=1 }   // on=cabin → watch2.cabin
}
```

### 4.3.5 时机与顺序

**占位。** 阶段 3 遇到 copy 语句时不建节点，只在 copy 表里登记（语句、词法环境、父节点、深度），并在父节点的子节点列表里**占住一个位置**：这个位置计入父节点的匿名段计数（1.6.1：`i` 是此前已创建的子节点总数，copy 的占位算一个），所以 copy 语句前后的匿名兄弟的编号与它是不是 copy 无关。原型把 copy 节点追加在兄弟之后、也不计入匿名计数（`group g { box p; copy q of=p; box }` 里匿名盒子是 `box#2`，本版是 `box#3`，且 `q` 排在 `p` 之后、匿名盒子之前）。语料里 copy 语句都是所在块的最后一条，节点顺序不受影响。

**展开算法**（阶段 4）。待展开集合 $Q$ 初值 = copy 表（按展开位置排序，位置相同按源码顺序）。重复下面的**一轮**直到 $Q$ 为空或一轮没有展开任何项：

1. 按顺序取 $Q$ 的每一项 $c$，解析它的 `of`（4.3.1）。
2. 解析成功：按 4.3.2 展开，R 放进占住的位置；展开里出现的 copy 语句（源语句块里的、copy 块里的）作为新项加入 $Q$（位置 = $c$ 的位置，深度 = $c$ 的深度 + 1，父节点 = 拷贝子树里对应的节点）；$c$ 从 $Q$ 移除。
3. 解析失败且失败原因是"找不到对象"或"名字不唯一"：$c$ 留在 $Q$ 里（它的原件可能是还没展开的另一个 copy，或在另一个 copy 的子树里）。其他失败（不是对象路径、复制祖先）：报错，$c$ 从 $Q$ 移除、不展开。

一轮结束后 $Q$ 非空且这一轮没有展开任何项：$Q$ 里每一项报错"copy X 的原对象无法确定（复制关系形成了循环？）"，这些 copy 无效（占位的位置留空，不生成节点）。这个过程是确定的（每轮按固定顺序扫描）；展开时机不影响结果，因为 R 的位置由占位决定，R 的属性与子语句由源语句决定。两个互相引用的 copy（`copy a of=b` 与 `copy b of=a`）与自引用（`copy a of=a`，a 不存在）都在这里报错。深度超过 32 的展开按 4.1.4 报错（经由 copy 的递归：模板体里 copy 它自己所在的实例的祖先已被 4.3.1 拒绝，所以只剩人为构造的链）。

**与修改的关系。** 阶段 4 在阶段 5 之前：所有 copy 都在任何几何时机的修改之前展开，不论书写先后。所以：

- copy 看到的树是阶段 3 的树加上已展开的 copy：模板实例的体、阵列实例都在，over 块新增的节点、换形后的节点、被 drop 的节点都**还没发生**——`copy x of=g.q`（q 由 over 块加入）报"找不到对象"；`copy x of=junk` 后 `drop junk`，x 照常生成。
- 对原件的修改不进拷贝（4.3.2 第 4 条）；对拷贝的修改（copy 块里的，或之后按路径 `R.…` 写的）不进原件。
- 修改序列里凡是选择器能选中 R 或其后代的 over / drop（写在 copy 之前或之后都一样）都按位置正常施加于拷贝。

**over 块里的 copy** 是例外：它在阶段 5 展开该 over 块时**立即**展开（4.5.5），`of` 对那一刻的树解析（能看到此前的修改、看不到影子）；它复制的仍是源语句（重建过的节点的源语句是重建时的有效语句，4.1.3）。原型把 over 块里的 copy 登记进已经处理完的 copy 表而静默丢失，本版展开它。

### 4.3.6 材质与元数据

- **材质**（10-materials.md 的 10.4.2）：R 按自身位置解析材质链：$\mathrm{chain}(R) = (R) \mathbin{+\!\!+} \mathrm{chain}(\mathrm{parent}(R))$；R 的自有外观属性是 4.3.3 得到的 `mat` / `color`；R 的子节点各带自己语句的外观属性。$A$ 的祖先的材质不跟过来（`copy b of=g.a` 放到根下时 b 不再继承 g 的 `mat`）。copy 块里几何时机的 `over … mat= color=` 设置的是普通属性（10.5.2）。
- **元数据**（08-metadata.md 的 8.3.5）：R 的元数据 = $A$ 的源语句的元数据（在原语句环境里重新求值）逐键被 copy 语句自己的元数据覆盖，键顺序按 8.3.5；拷贝子树里的节点各带自己语句的元数据，每次复制重新求值。原型 expandCopies 在 copy 语句有任何元数据时**整体替换**而不合并（`meta: s.meta?.size ? s.meta : A.stmt.meta`），本版按 8.3.5 合并；语料里的 copy 语句都没有元数据。
- **标签**：1.6.7（并集）。

### 4.3.7 错误

| 文案 | 触发 | 恢复 |
|---|---|---|
| copy 需要名字 | 没有名字（1.3.14） | 整条语句无效 |
| copy 需要 of=原对象 | 没有 `of` | 整条语句无效 |
| copy 的 of 写一个对象名 | `of` 不是对象路径（带坐标后缀、集合、锚点、数…） | 整条语句无效 |
| 找不到对象 X / 名字 X 不唯一 | 4.3.5 全部轮次之后仍解析不到；或路径下降失败 | 报在 copy 语句；该 copy 无效 |
| copy X 的原对象无法确定（复制关系形成了循环？） | 4.3.5 | 该 copy 无效 |
| copy 不能复制包含自己的对象 X | $A$ 是 R 的父节点或祖先（4.3.1） | 该 copy 无效 |
| copy 没有属性 k | copy 语句的键不是 P 组或 $A$ 所属模板的参数；或新节点的种类不接受该键（4.3.3） | 前者该 copy 无效；后者新节点退化 |
| 模板 X 没有参数 k / 模板 X 缺少参数 p | 重新实例化时的参数错误（4.2.3） | 新节点退化 |
| 展开层数超过 32（模板 X 递归？） | 4.1.4 | 不展开 |
| 同级重名 X | R 与同一父节点下另一个具名节点同名（1.6.6） | 后出现的语句无效 |
| 被复制语句自己的错误（属性、求解、几何） | 重新展开时照常发生 | 按原错误；归属原语句的文件与行，带拷贝里的节点路径（05-layers.md 的 5.2.5） |

一个 copy 失败只影响它自己（占位留空、块不展开、块内修改不进序列）；引用 R 的语句按"找不到对象"报错。

## 4.4 mirror / rotate 副本

### 4.4.1 两种形式与节点

语法见 1.3.3、1.4.5；变换矩阵见 03-solving.md 的 3.9。两种形式：

**容器式** `mirror C [across=… axis=…] { 原件… }`、`rotate C [n=k about=… axis=… angle=…] { 原件… }`：

- C 是一个容器节点（种类 `mirror` / `rotate`），接受 P 组全部属性（1.4.4）与专有属性（1.4.5）。它的块按普通容器展开：块里的语句生成 C 的子节点，这些子节点（连同之后 copy、over 块加进来的）叫**原件**。
- 阶段 6 在 C 下追加**副本组**：mirror 一个，段 `mirrored`，种类 `mirror`；rotate $k$ 个，段 `r1` … `rk`，种类 `rotate`（1.6.3），排在 C 的全部原件之后、按 $k$ 递增（1.6.1）。每个副本组里是**全部原件的影子**（4.4.2）。副本组没有源语句：没有属性（不接受属性，4.5.3）、没有标签、元数据为空（8.3.4）、不进全局索引（1.6.5）。
- rotate 的 `n`（副本组个数）在阶段 6 求值：值必须是与某个整数 $m$ 相差不超过 $\varepsilon_{\text{int}}$（03-solving.md 的 3.1.7）且 $1 \le m \le 360$ 的数，否则报错"`<路径>`：rotate 的 n 需要 1..360 的整数"，C 退化（原件保留，不生成副本组）；默认 1。它只能引用词法环境（像常量，1.4.1；引用对象报错"rotate 的 n 必须是常量"）。`n` 可以被几何时机的 over 就地修改（4.5.3）。
- 副本组 $k$ 的局部变换是 C 自身框架里的镜像 / 第 $k$ 次旋转 $M_k$（3.9.2）。

**副本式** `mirror R of=A [across=… axis=…]`、`rotate R of=A [about=… axis=… angle=…]`：

- R 是一个节点，种类 = $A$ 的种类（含类型链，1.6.7、4.2.7），名字 = R，标签 = $A$ 的标签 ∪ R 自己写的，元数据 = R 语句自己的（8.3.4）。R 不接受块（1.3.15），不接受定位与朝向属性（1.4.4："副本跟随原物体，不接受定位属性"，节点退化），接受 `mat` / `color`、专有属性 `across` / `axis`（mirror）或 `about` / `axis` / `angle`（rotate；`n` 报错）。
- `of=A` 是对象路径（1.4.1），在阶段 6 解析（搜索起点 R 的父节点，1.6.5）。允许的 $A$：任何在阶段 6 存在的节点——实体、曲线、容器、repeat 节点、阵列实例、模板实例、copy 节点、容器式 mirror / rotate 节点、另一个副本式节点、副本组、影子（后两者要求它们所属的副本树已定稿，见 4.4.2 的顺序）。不允许：R 自己、R 的祖先（报错"X 不能复制包含自己的对象"）；皮肤子树（阶段 6 不存在，"找不到对象"）。
- R 的子节点是 $A$ 的子节点的影子（4.4.2）；R 的局部变换 $= M \circ T_{A \to P}$（3.9.1，$P$ 是 R 的父节点）；R 的局部包围盒 = $A$ 的局部包围盒（02-geometry.md 的 2.6），几何 = $A$ 的几何（实体原件时 R 本身就是那个实体的副本）。

两种形式都生成**影子**；影子的段、种类、名字见 1.6.3、1.6.7。

```s3d
mirror wings across=hangar.body axis=x {       // 容器式：wings.annex … 与 wings.mirrored.annex …
  box annex size=12,8,14 against=hangar.body.right align=back,bottom mat=concrete
  span stair1 from=annex.bottom-front+(0,0,12) to=annex.top-front steps=16 section=2.4,0.25 mat=steel
}
rotate fins n=3 about=stage1 { wedge fin … }   // fins.fin 与 fins.r1.fin fins.r2.fin fins.r3.fin
mirror tower2 of=tower across=rocket axis=x    // 副本式：tower2 的种类是 truss，子节点 legs / decks 是影子
rotate gate2 of=gate about=garage angle=180    // 原件里的 mirror 容器连同它的副本组一起成为影子
```

### 4.4.2 副本树是原件的函数

**生成规则。** 设 $o$ 是一个节点，$\mathrm{shadow}(o, p)$ 在父节点 $p$ 下生成 $o$ 的影子 $s$：

1. $s$ 的段：$o$ 具名时同名；$o$ 匿名时 `种类词#i`，$i$ 是 $p$ 此前已创建的子节点数（1.6.3：按副本组 / R 自己的计数器重新编号）。
2. $s$ 的种类与类型链 = $o$ 的（$o$ 是阵列实例则 `instance`，是副本组则 `mirror` / `rotate`，是影子则取 $o$ 的）；标签 = $o$ 的标签；元数据 = $o$ 的元数据（同一映射，8.3.4）；$s$ 没有源语句，有效属性 = $o$ 的有效属性（4.1.3），影子覆盖另记（4.4.4）。
3. $s$ 的子节点 = 对 $o$ 的每个子节点 $c$（按 $o$ 的子节点顺序，含 $o$ 的副本组与影子、含 over 块加入的真实子节点、含 4.4.4 加在影子上的真实子节点）依次 $\mathrm{shadow}(c, s)$。
4. $s$ 的局部变换 = $o$ 的局部变换（或 $o$ 的孪生体的，4.4.4；03-solving.md 的 3.9.7）；局部包围盒、紧包围盒、几何 = $o$ 的（或孪生体的）。影子不参与求解顺序之外的任何依赖：引用影子的锚点就是引用它的世界变换下的原件盒。

容器式 C 的副本组 $G_k$ 的子节点 = 对 C 的每个原件 $c$ 依次 $\mathrm{shadow}(c, G_k)$；副本式 R 的子节点 = 对 $A$ 的每个子节点 $c$ 依次 $\mathrm{shadow}(c, R)$。

**原件的最终状态。** 副本树在阶段 6 生成，输入是阶段 5 结束时的树：原件被 over 改过、被重建过、被 drop 过、被 over 块加了子节点、被 copy 块改过，影子都反映这些；原件被变体隐藏（阶段 8）**不**反映到副本（10.4.3；变体不传播到副本，07-semantics.md）。所以"副本树是原件的函数"的精确含义：$\mathrm{shadow}$ 只读原件子树的最终状态与影子覆盖，任何别的东西（R 所在的位置、R 的祖先的属性、书写顺序）都不影响副本树的结构。

**顺序与循环。** 副本根之间有依赖：R 依赖 $A$ 的子树里的每个副本根（它们的副本组 / 影子要先生成，才能被 $\mathrm{shadow}$ 复制）；容器式 C 依赖它原件子树里的每个副本根；`of=` 指向影子或副本组时依赖该影子所属的副本根。按这个依赖关系的拓扑序生成（无依赖时按节点顺序，结果与顺序无关，因为 $\mathrm{shadow}$ 只读已定稿的子树）。依赖成环（`mirror a of=b` 与 `mirror b of=a`；`group g { mirror m of=g }` 已被 4.4.1 拒绝）：环上每个副本根报错"复制关系形成循环：X"，这些副本根退化（R：没有子节点、零盒；C：不生成副本组，原件保留），不在环上的副本根照常生成（原型 buildCopies 遇环后停止全部后续副本，本版按 1.1.4 第 6 条局部化）。

**皮肤里的副本**（07-semantics.md 的 7.8.5）：皮肤子树在阶段 8 挂载后，其中的 mirror / rotate 按本节同样的规则生成副本树（原件是皮肤里的节点；`of=` 可以指向皮肤外已存在的节点）。

```s3d
def house(…) { box body …; wedge half … on=body align=left; mirror half2 of=half across=body axis=x; … }
def chimney_house : house(floors=2) { box chimney … }
chimney_house h2 at=7,0,-8        // h2.half2 的种类是 wedge，of = h2.half；h2 被 over 改 floors 后 half2 跟着变
over h2.half size=4,2.2,5.6       // 原件变 → h2.half2 同样变（无需再写）
```

### 4.4.3 副本节点上能写什么

| 节点 | 能写的 | 不能写的（报错） |
|---|---|---|
| 容器式 C | 名字、标签、元数据、P 组全部、`across` `axis`（mirror）/ `n` `about` `axis` `angle`（rotate）、块 | — |
| 副本式 R | 名字、标签、元数据、`of`（必填）、`mat` `color`、`across` `axis` / `about` `axis` `angle` | 定位与朝向属性（"副本跟随原物体，不接受定位属性"，节点退化）；块（"写了 of= 就是复制已有对象，不能再有子语句"）；rotate 的 `n`（"rotate 副本不接受 n"） |
| 副本组 `mirrored` / `r<k>` | （没有语句） | 任何属性（4.5.3）；可以被 over 块加子节点、被 drop（4.4.4） |
| 影子 | （没有语句） | 换形、模板参数、repeat 的 `n`（4.4.4）；其余属性可经 over 覆盖 |

副本式 R 的 `across` / `about` / `axis` / `angle` 的求值框架是 R 的父节点 $P$（3.9.1：`axis=x` 按参照物自己的轴理解时见 3.9.5）。R 的 `mat` / `color` 的效果见 10.4.1（插在原件 $A$ 之前）。

### 4.4.4 对副本的修改：影子覆盖

一条几何时机的 `over` / `drop`（4.5）的选择器若经过副本段（`tower2.legs.0.leg`、`rocket.fins.r1.fin`、`farm.1.t.rotor.r2.blade`、`wings.mirrored.annex`），它选中的是影子（或副本组）。规则：

**时机。** 阶段 5 施加修改时副本树还不存在。一条修改的选择器在阶段 5 求值失败（"找不到对象"、"名字不唯一"、"X 中没有子对象或锚点 Y"）或求得空集时，这条修改**推迟**到阶段 6：副本树生成之后，按同样的方式再求一次；仍失败或仍为空则报那时的错误（"没有选中任何对象"或名字错误），该语句无效。推迟的修改之间仍按展开位置（4.1.2）排序，都在非推迟的修改之后施加。阶段 5 求值成功的修改不会选中影子（影子还不存在），所以 `kind(box)`、`#tag`、`all()` 这类选择器只改原件，影子跟随——这正是"副本跟随原件"的实现方式；只有显式写出副本路径才改单个副本。原型 applyOpinions 的两轮（pass 1 / pass 2）与此相同。

**over 选中影子 $s$（原件 $o$）。** 对该成员：

- 属性键的检查按 $o$ 的种类（1.4.8）。不允许：换形 `: T`（报错"X 是副本，不能单独换类型：请对原物体换类型，或改用 copy"）；$o$ 是模板实例时它的参数键（报错"X 是副本，不能单独改模板参数：请改用 copy"）；$o$ 是 repeat 节点时的 `n`（报错"X 是副本，不能单独改阵列数量：请改用 copy"）；`use`（4.5.1）。违反时该成员不被修改（其他成员照常）。
- 其余键是**影子覆盖**：记入 $s$ 的覆盖表（按键替换；写了定位关系键时先删掉覆盖表与原件有效属性里的其他四个关系键，与 4.5.3 相同），表达式的上下文是写 over 处的帧与 **$o$ 的父节点**（1.5.8 表里"被修改节点的父节点"对影子按孪生体理解：对象名从原件所在处解析）。
- 块：块里的语句成为 $s$ 的**真实**子节点（不是影子），追加在 $s$ 现有子节点之后；它们只存在于这一个副本里，词法环境是块帧（`it` = $s$），搜索起点是 $s$（所以 `on=it` 贴在这个影子上）。它们属于副本树（4.4.2 第 3 条：再被复制时它们也有影子）。块里的嵌套 over / drop 作用于 $s$ 的子树。
- 多条 over 选中同一个影子时覆盖表按位置顺序累积（后写的键覆盖先写的）。

**孪生体。** 有覆盖的影子 $s$ 的求解依据是它的**孪生体** $\tilde o$：一个不在场景树里的节点，父节点 = $o$ 的父节点，种类、源语句、参数绑定、子节点 = $o$ 的，有效属性 = $o$ 的有效属性逐键被 $s$ 的覆盖替换。03-solving.md 的 3.9.7 规定 $T_s = T_{\tilde o}$——在 $o$ 的父框架里按 $\tilde o$ 的属性求局部变换，再由副本根的变换带过去，所以关系的含义不变（`over tower2.legs.0.leg on=other` 里的 `other` 从 tower 所在处解析，得到的位置再被镜像）。$s$ 的局部包围盒与几何按 $\tilde o$ 算（覆盖了 `size` 的影子有自己的盒）；$\tilde o$ 是容器时它的盒按 $o$ 的子节点算（子节点没有被覆盖）。$s$ 的子节点仍是 $o$ 的子节点的影子，相对 $s$ 的变换 = 相对 $o$ 的变换。没有覆盖的影子 $\tilde o = o$。孪生体不输出、不进任何集合、不参与事实；输出里 $s$ 的 `of` 仍是 $o$ 的路径（4.4.5）。

**over 选中副本组 $G$。** 属性：报错"X 是副本组，不接受属性"（4.5.3）；块：块里的语句成为 $G$ 的真实子节点（只在这一个副本里）；换形：报错（同影子）。

**over 选中副本式节点 R。** R 有自己的语句，按 4.5.3 就地修改它自己的键：`across` `axis` / `about` `axis` `angle`、`mat` `color`；定位与朝向键报错"X 是 mirror / rotate 生成的副本，副本跟随原物体：请覆盖原物体、覆盖副本里的某个部件，或改用 copy"；模板参数与换形报错同影子（请对原物体做）。块：成为 R 的真实子节点。原型 applyOpinions 对 R 上的任何几何时机 over 都报错（含 `across=`），本版允许改 R 自己的键；语料里没有这种 over。

**drop。** `drop` 选中影子、副本组或副本式节点时把它（连同子树）从树里删除：只影响这一个副本（`drop g2.b` 后 g 的 b 还在；`drop fins.r2` 删掉第二个副本组）。被 drop 的影子的原件若之后再被复制（嵌套副本），新副本里仍有它——drop 作用于节点，不作用于原件。

```s3d
def turbine(h=20) { cyl tower …; sphere hub … on=tower; rotate rotor n=2 axis=z at=hub.center pin=origin { box blade size=1,9,0.3 … } }
repeat farm n=3 step=20,0,0 on=ground { turbine t }
over farm.1.t.rotor.r1.blade size=1,5,0.3     // 推迟到阶段 6：只有这一片变短；它的位置仍从 rotor.blade 的孪生体算
over farm.1.t.rotor.r2.blade mat=rust         // 外观时机（4.5.1：最外层、只有 mat → 它是一条 style，直接选中这一个影子，10.3.3）
def turbine : turbine { over rotor n=3 }      // 父类型加一片：三台都变 4 片，farm.1 的两处修改仍在
over farm.1.t.rotor.r1.blade { sphere tip r=0.2 on=it }   // 只给这一片加个球
drop farm.2.t.rotor.r3.blade                  // 只删这一片
```

### 4.4.5 副本的包围盒、标签、元数据、材质、样式与变体

- **包围盒**：影子的局部包围盒 = 原件（或孪生体）的局部包围盒，世界包围盒按自己的世界变换求（3.1.6）；副本式 R 的局部包围盒 = $A$ 的（2.6）；副本组的局部包围盒 = 它的子节点（影子与真实子节点）之并（2.6 容器规则，在副本组自己的框架里）；容器式 C 的包围盒 = 原件与副本组之并（2.6），所以 `mirror wings …` 的盒跨过两翼（4.8）。C 的 `envelope` 不接受（只有 group 接受，1.4.5）。
- **紧包围盒与事实**：影子是实体时有紧包围盒（原件的紧包围盒按影子的世界变换重算，02-geometry.md 的 2.1.8）；影子、R、副本组按 06-facts.md 的规则参与空间事实，与普通节点相同（镜像翻转手性，事实的定义不依赖手性）。
- **标签**：1.6.7（影子 = 原件的；R = $A$ 的 ∪ 自己的；副本组无）。`#tag` 因此同时选中原件与影子；要只选原件，用路径或 `where name`…结合排除。
- **元数据**：8.3.4（影子读原件的，含 `where` 里的读取；R 自己的；副本组空）。
- **材质**：10.4.1（R 的材质链插在 $A$ 之前；影子走原件的链；影子覆盖里的 `mat` / `color` 是影子的自有外观属性）。
- **样式**：10.3.3（副本跟随原件的样式，并接受直接选中它的样式）。
- **变体**：原件被变体替换时影子**不**跟随（07-semantics.md、10.4.3）：影子照常显示原件的几何（它跟随的是阶段 7 的几何，皮肤是阶段 8 的外观）；要替换副本须另写一条变体选中副本。被变体隐藏的只是 $N$ 的子树（含 $N$ 下面的副本式节点与影子，例如 `street.h4.half2` 随 h4 隐藏），$N$ 之外的副本不隐藏。
- **输出**：`nodes[]` 里影子带 `ghost: true`、`of: <原件路径>`（有覆盖的影子也写原件的路径）；副本式 R 带 `ghost: false`、`of: <A 的路径>`；副本组与其他节点 `ghost: false`、`of: null`（copy 节点也是 `null`）。`kind`、`types` 按 4.2.7。

## 4.5 over 与 drop

### 4.5.1 两个时机的判定

语法见 1.3.8。每条 `over` 属于两个时机之一，由它的**形态**决定（与书写位置在程序里的先后、来自哪个文件无关，05-layers.md 的 5.2.4）：

一条 `over` 是**外观时机**的，当且仅当下面四条**同时**成立：

1. 它写在最外层（不在任何块、模板体、copy 块、over 块里）；
2. 它没有块；
3. 它没有换形 `: T`；
4. 它至少有一个属性，且每个属性键都属于 `{mat, color, use}`。

外观时机的 over 在阶段 2 被登记为语义层语句：有 `use` 时它是一条 `variant 选择器 use=T mat=… color=…`（07-semantics.md 的 7.8；`use` 之外的键必须是 `mat` / `color`——第 4 条已保证），没有 `use` 时它是一条 `style 选择器 mat=… color=…`（7.7、10.5.2）。它不进修改序列、不改任何属性，选择器可以用事实、概念与全部 where 字段（1.7.4）。

其他任何 `over` 都是**几何时机**的：写在块里的（即使只写 `mat` / `color`——块内的 over 作用于该块的后代，是几何层的一部分）、带块的、带换形的、含 `{mat, color, use}` 之外的键的、`mat` / `color` 与别的键混写的。几何时机的 over 在阶段 3 记入修改序列，按 4.1.2 的位置在阶段 5（或 4.4.4 的阶段 6）施加；它的 `mat` / `color` 是普通属性（10.5.2）。几何时机的 over 里出现 `use` 报错"use= 只能写在最外层、不带块与换形、只改外观的 over 里"（位置错误，1.10.2），整条语句无效。

没有属性也没有块的 `over 选择器` 报错"over 需要属性或块"，整条语句无效（原型静默接受为空操作）。

`drop` 总是几何时机的。

原型 elaborate 的判定条件相同（`!retype && !children.length && props.size && 每个键 ∈ APPEARANCE`，只对最外层语句判定）。

```s3d
over wings.annex color=#cfe3f7          // 外观时机 → style（spaceport_blueprint.s3d:20）
over hangar.roof use=ribbed             // 外观时机 → variant（:19）
over rocket.stage2 h=20                 // 几何时机：就地修改
over tower lv=10                        // 几何时机：重建型（模板参数）
copy hangar2 of=hangar … { over roof color=#4a5560 }   // 块里：几何时机，color 成为 hangar2.roof 的属性
def flat : tower { over roof color=#888 }              // 模板体里：几何时机
over kind(box) where mat == plain color=#e8f1fb        // 外观时机：where 读 mat 也可以在几何时机用（10.5.3）
```

### 4.5.2 几何时机的选择器与作用范围

- **求值**：选择器是集合类表达式（1.7.1）。几何时机的选择器在**施加这条修改的那一刻**求值（阶段 5 按位置轮到它时；推迟的在阶段 6，4.4.4），上下文是写它处的帧与写它的块的节点（1.5.8）。只能用静态量（1.7.4、D10）：路径、通配、`#tag`、`kind()`、`all()`、`children()`、`descendants()`、列表、集合运算，`where` 里的 `kind` `name` `mat`（10.5.3：按那一刻的自有外观属性）与元数据键（8.2.2）。用了 `w h d x y z top bottom`、关系谓词、概念或模式报错"几何时机的选择器只能用静态量（路径、#标签、kind()、name / 元数据 / mat）"，该语句无效。
- 它看到的树是那一刻的树：此前的修改已生效（新加的节点可选，被 drop 的不可选，重建后的是新节点），此后的还没有；copy 已全部展开；影子还不存在（4.4.4）。同一父节点下尚未被 1.6.6 判定的同名节点中，按名字命中的是节点顺序最先的那个（1.6.6："引用该名字得到先出现的节点"；1.6.6 的判定在阶段 6 之后对最终的树做）。这使 05-layers.md 的 5.3.2 的写法成立：`drop pad` 删掉先前的 pad，之后声明的新 pad 留下。
- **作用范围**：写在块里的 over / drop 只作用于**该块的节点的后代**（1.3.15）：容器块 → 该容器的子树；模板体 → 该实例的子树；copy 块 → R 的子树；over 块 → 该成员的子树（成员是阵列时为该实例的子树，4.5.5）；最外层 → 整棵树。选中的节点中不在范围内的**被排除**（不报错；原型 applyOpinions 相同），已被 drop 的也排除。排除之后为空集报错"X 没有选中任何对象"（1.7.1），该语句无效（阶段 5 为空的先推迟到阶段 6，4.4.4）。
- 成员集合按节点顺序（1.5.5）逐个处理；每个成员独立：对某个成员的错误（不接受的键、副本限制）只使该成员不被修改。
- 可选中的节点：实体、曲线、容器、repeat 节点、阵列实例、模板实例、copy 节点、副本式节点、容器式 mirror / rotate 节点、退化节点；阶段 6 还有影子与副本组（4.4.4）。皮肤子树不可能被几何时机的修改选中（阶段 8 才存在）。

### 4.5.3 就地修改：属性语义

对一个成员 $m$（不是影子、副本组；这两者见 4.4.4）与 over 的属性表 $S$，先分类：

1. 含换形 `: T` → 整条按 4.6 处理（重建型）。
2. $m$ 是模板实例且 $k$ 在它的参数表里 → $k$ 是**重建键**（4.5.4）。
3. $m$ 是 repeat 节点且 $k = $ `n` → 重建键。
4. 其余 $k$ 必须属于 $m$ 的合法集合（1.4.8：种类的专有属性 ∪ 它接受的 P 组），否则报错"X 没有属性 k"，该成员**整个不被修改**（含块；其他成员照常）。$m$ 是阵列实例或副本组（没有属性表）时任何键都报错"X 是阵列实例 / 副本组，不接受属性"。

没有重建键时这条 over 对 $m$ 是**就地修改**：按 $S$ 的键顺序更新 $m$ 的有效属性表（4.1.3）：

- $k \in \{$`at` `on` `under` `against` `inside`$\}$：先从表里删除这五个键，再写入 $k$。`pin` `gap` `offset` `align` `alignto` **保留**（原型 applyOpinions 相同；与 copy 的 4.3.3 不同——copy 换关系时连对齐也删，因为 copy 是重新描述位置，over 是在原描述上改一个键）。要去掉它们，没有"删除属性"的写法，改用 copy 或重写语句。
- 其他键：写入或替换。
- 值是表达式，记下它的上下文（写 over 处的帧，搜索起点 $m$ 的父节点，1.5.8），在求解时求值（常量类型的在重建 / 阶段 6 求值，如 rotate 的 `n`）。因此 `over crate on=pad size=2,lift,2` 里 `lift` 是写 over 处可见的 let，`pad` 从 crate 的父节点起找。

就地修改**不**改变：节点的位置与名字、子节点、标签、元数据（8.3.6）、源语句的块；也不触发任何重新展开。效果在求解时体现：改 `size` 改几何，改 `on=` 改定位，改 `mat` 改自有外观属性（10.5.2）。可以就地修改的键包括：实体与曲线的全部专有属性、group 的 `envelope`、容器式 mirror / rotate 的 `across` `axis` `about` `angle` 与 rotate 的 `n`（副本组在阶段 6 才生成，所以改 `n` 不需要重建——语料 rotation.s3d 的模式 `def turbine : turbine { over rotor n=3 }`）、repeat 的 `step` `center` `turn` `along` `orient`（实例数不变）、P 组。

```s3d
over rocket.stage2 h=20              // 二级加长；依赖它的 nose、arm 在求解时跟着动
over watch.cabin size=5,2.5,5
over crate on=pad size=2,lift,2      // 换定位关系：原来的 at 作废；lift 在写 over 处求值
over #cargo mat=steel                // 几何时机（如果写在块里）或外观时机（最外层）——结果都是 steel，差别见 10.5.2
```

### 4.5.4 重建型修改

重建键（模板参数、repeat 的 `n`）与换形（4.6）使成员 $m$ **重新展开**：

1. 取 $m$ 的**有效语句**（4.1.3：源语句 + 有效属性表，块 = 源语句的块）；把每个重建键写入它的属性表（值带写 over 处的上下文）；换形时按 4.6.3 改种类词并筛选属性表。
2. 从 $m$ 的父节点 $P$ 的子节点列表里拿掉 $m$ 与它的整个子树（含 over 块曾加入的子节点、曾被 drop 剩下的空洞、影子覆盖记录）。
3. 在**同一位置**（$m$ 原来的下标；匿名段保留原来的 $i$ 与新种类词，1.6.1）按有效语句新建节点 $m'$：词法环境 = 源语句原来的环境（模板体帧、块帧、阵列实例帧照旧），搜索起点 = $P$，深度 = $m$ 的深度。模板实例按 4.2.3 重新绑定参数、按 4.2.4 重新展开体（体内的 over / drop 作为新项进入修改序列，位置 = 原实例语句的位置——它们在当前这条 over 之前，所以**立即**在 $m'$ 上施加完，再继续）；repeat 按 03-solving.md 重新生成实例。
4. $m'$ 继承 $m$ 的名字、标签；元数据按源语句重新求值（8.3.6）；有效属性表 = 第 1 步的表（所以此前对 $m$ 自身的就地修改仍在，4.1.3）。
5. 这条 over 剩下的非重建键按 4.5.3 施加于 $m'$，再施加块（4.5.5）。

后果（都是定义）：

- $m$ 子树上**此前**的一切修改丢失：over 块加的子节点、对子节点的就地修改、对子节点的 drop（`drop tanks.1` 后 `over tanks n=5` 得到完整的 5 个）、copy 块里对 $m$ 后代的修改。要保留，把它们写在重建之后（位置更大）。
- 此后（位置更大）的修改按选择器在施加时重新解析，自然落到 $m'$ 的子树上：`over tower lv=10` 之后的 `over tower.decks.9.deck size=…` 成立。
- 此前已从 $m$ copy 出去的拷贝不受影响（它们是独立节点）；$m$ 的影子在阶段 6 按 $m'$ 生成（跟随重建后的状态：spaceport_edit 的 `tower2` 有 10 层）。
- 重建键的值在 over 处求值：`over s n=count_let`。模板参数的新值进参数绑定表，写明的值压过覆盖表与默认值（4.2.3）。
- 重建保留 $m$ 的 P 组有效属性（它们在有效语句里）：`over tower lv=10` 后 tower 仍 `on=pad[-0.7,1,-0.7] mat=steel`（4.8）。

原型 applyOpinions 用 `m.stmt.props`（源语句的原始属性）重建，所以重建前对 $m$ 自身的就地修改（`over x turn=45` 后 `over x n=2`）丢失；本版用有效属性，不丢失。语料里没有同一节点先就地再重建的情况。

```s3d
over tower lv=10        // 脐带塔按新参数重建：legs 不变，decks 变成 10 个实例，step h/lv 变成 4.8
over hangar dw=16       // 厂房开口加宽：body 重新展开，opening / arch 按新 dw
over tanks n=5          // 阵列重建：5 个实例，仍 center=true、step 10
```

### 4.5.5 块

`over` 的块（1.3.15 允许的语句）对每个被选中并通过属性检查的成员 $m$，在该成员的属性修改（含重建）之后展开：

- **成员是 repeat 节点**：块对它的**每个阵列实例**（按 $idx$ 递增；被 drop 的实例跳过）各展开一份：父节点 = 该实例，词法环境 = 块帧（`it` = 该实例，`i j k idx` = 该实例的下标），搜索起点 = 该实例。效果与把这些语句写在 repeat 体里相同，只是位置是 over 语句的位置。
- **成员是其他节点**（含阵列实例自身、模板实例、容器、实体、影子、副本组）：父节点 = $m$，块帧含 `it` = $m$（$m$ 是阵列实例时另有它的 `i j k idx`），搜索起点 = $m$。实体与曲线也可以这样得到子节点：它们相对该实体的局部系定位（可以写 `on=it`）、按路径寻址（`crate.tag`），但**不计入**该实体的局部包围盒与紧包围盒（第 2 章只对容器求并；实体的盒只由它自己的形状决定）。
- 块里**生成节点**的语句成为新子节点，追加在 $m$ 现有子节点之后，按块内顺序（1.6.1 第 3 条）；它们的展开位置是 over 语句的位置（4.1.2），深度与 $m$ 的子节点相同。
- 块里的 `over` / `drop` 作为新项进入修改序列，位置 = 这条 over 的位置、按块内顺序排在这条 over 自己的属性修改之后（4.1.2），作用范围 = $m$ 的子树（成员是 repeat 时每个实例各一份，范围是该实例的子树）。所以块内的 `drop tank` 删的是 `m.tank`（阵列时是每个实例的 tank）。
- 块里的 `copy` 立即展开（4.3.5 末段）；块里的 `let` 进块帧（整块可见，惰性）。
- 元数据按 8.3.6（新节点带自己语句的元数据，在块帧里求值，`it` 不能出现在元数据值里）。

原型 applyOpinions 对单个阵列实例成员的块不提供 `i j k idx`（只有 `it`），本版提供。

```s3d
over #cargo { sphere tag r=0.2 on=it }          // 每个带 #cargo 的盒子上放一个球
over row { drop tank; cyl tank r=0.5 h=3+idx }  // 改阵列的"模板"：每个实例换成高度递增的圆柱
over farm.1.t.rotor.r1.blade { sphere tip r=0.2 on=it }   // 只给一个副本加部件（阶段 6，4.4.4）
```

### 4.5.6 drop

`drop 选择器`（1.3.8：不接受属性与块，接受元数据）。选择器与作用范围按 4.5.2；对每个成员 $m$：

- 把 $m$ 连同它的整个子树从父节点的子节点列表里删除。$m$ 的名字从此在树里不存在：此后（位置更大）的 over / drop 选不到它（"没有选中任何对象"或"找不到对象"）；求解时任何引用它的属性报"找不到对象 X"（节点退化，1.1.4）。
- 兄弟不移动、不重编号：阵列实例留下空洞（`drop lights.3` 后剩 `lights.0 … lights.2`；`drop lights.1` 后剩 `0 2 3`，1.6.2）；匿名段的计数不回收（1.6.1）。
- 被 drop 的节点不参与此后的任何阶段（求解、事实、语义、输出、同级重名的判定）；它的元数据随它消失（8.3.1）。
- 可以 drop 任何在那一刻存在的节点：实体、曲线、容器（整棵）、repeat 节点（整个阵列）、单个阵列实例、模板实例、模板实例里的部件（派生体里的 `drop roof`）、copy 节点、副本式节点（整个副本）、容器式 mirror / rotate 节点（原件与副本一起）、以及阶段 6 的影子与副本组（4.4.4）。drop 一个节点不影响它的原件、拷贝或副本之外的任何东西；drop 原件则它的影子在阶段 6 不再生成（副本树是原件的函数），drop 容器式 C 的某个原件同理。
- drop 与重建（4.5.4）：对子树的 drop 在该子树的祖先被重建时丢失；重建之后再 drop 则有效。drop 之后的同名新声明合法（05-layers.md 的 5.3.2），因为同级重名在最终的树上判定。
- `drop` 的元数据属于该语句（8.3.8）。

```s3d
drop lights.3                  // 拆掉一根灯塔（spaceport_edit.s3d:10）
drop junk
drop all() where fit < 0.3     // 元数据是静态量
copy watch2 of=watch … { drop cap }   // 只删拷贝里的
```

### 4.5.7 先后、覆盖与错误

**先后**（4.1.2 的全序 + 本节）：

| 情形 | 结果 |
|---|---|
| 两条 over 改同一节点的同一键 | 位置大的生效（后写的覆盖先写的；模板体内的随实例定位，copy / over 块内的随块所属语句定位） |
| 就地修改后再重建（同一节点） | 就地修改保留在有效语句里，重建后仍有效（4.5.4） |
| 重建后再就地修改 | 施加于新节点 |
| 对子树的修改 / drop / over 块新增，再重建祖先 | 丢失（4.5.4） |
| over 后 drop | 先改再删：结果是删 |
| drop 后 over / drop 同一节点 | 选择器选不到：空集报错"没有选中任何对象"；写了路径且首段就不存在报"找不到对象"（都使该语句无效） |
| over 的块给节点加子节点，之后的 over 选它 | 可选（它已在树里） |
| 同一条 over 的属性与块 | 属性（含重建）先、块后；块内按顺序 |
| 几何时机 vs 外观时机 | 几何时机全部在求解前施加；外观时机全部在求解后按 07-semantics.md 施加（05-layers.md 的 5.3.6） |
| 推迟到阶段 6 的修改（4.4.4） | 在全部非推迟修改之后，彼此按位置 |

**错误**（恢复按 1.1.4 第 5 条与 4.5.2 的逐成员局部化）：

| 文案 | 触发 | 恢复 |
|---|---|---|
| over 需要选择器 / drop 需要选择器 | 1.3.8 | 整条语句无效 |
| over 需要属性或块 | 4.5.1 | 整条语句无效 |
| 属性之后不能再出现选择器 / 换类型写成 over 对象 : 类型 / drop 不能带 { } 或属性 | 1.3.8 | 整条语句无效 |
| use= 只能写在最外层、不带块与换形、只改外观的 over 里 | 几何时机的 over 含 `use`（4.5.1） | 整条语句无效 |
| 几何时机的选择器只能用静态量（…） | 4.5.2 | 整条语句无效 |
| 找不到对象 X / 名字 X 不唯一 / X 中没有子对象或锚点 Y | 选择器里的路径解析失败（阶段 5 推迟、阶段 6 报，4.4.4） | 整条语句无效 |
| X 没有选中任何对象 | 成员为空（含被作用范围排除后为空） | 整条语句无效 |
| X 没有属性 k | 成员不接受该键（1.4.8） | 该成员不被修改 |
| X 是阵列实例 / 副本组，不接受属性 | 4.5.3 | 该成员不被修改（块仍施加） |
| 副本限制的各条文案（4.4.4、4.4.6） | 对影子 / R 的换形、模板参数、阵列数量、定位 | 该成员不被修改 |
| 模板 X 缺少参数 p / 模板 X 没有参数 k 等重建时的错误 | 4.5.4 重新展开时 | 新节点退化（按 4.2.8） |
| 换形的错误（4.6.3） | 4.6 | 该成员不被修改 |
| 块内语句的错误 | 按各自语句的规则 | 只影响该语句（其他块内语句与成员照常） |
| 值的类型错误、找不到对象 | 属性值在求解时求值失败 | 该节点退化（1.1.4 第 2 条）；over 语句本身不报"无效" |

错误归属：over / drop 语句自己的错误（选择器、属性键、时机、副本限制）报在该语句的文件与行；重建时源语句的错误报在源语句的文件与行并带节点路径（05-layers.md 的 5.2.5）。

## 4.6 保名换形

### 4.6.1 可换的原种类与目标种类

`over 选择器 : T [属性…] [{ 块 }]`（1.3.8）把每个被选中的节点换成种类 T，**名字、路径、在父节点里的位置不变**，所以引用它的 `on=` / `at=` / `against=` / `of=` 都不用改；它是一种重建型修改（4.5.4）。

**原种类**（被选中的节点 $m$）按下面分三类；不在表里的不能换形：

| 原 | 节点 |
|---|---|
| 原子 | 实体（box wedge plate hull mesh cyl cone sphere revolve span sweep pipe）、曲线（line bezier spline arc helix） |
| 容器 | group、union、subtract、intersect |
| 模板实例 | 种类是模板名的节点（含 copy 出来的、换形出来的） |

不能换形的：repeat 节点与阵列实例（报错"不能对阵列 / 阵列实例换类型：改 n 或 drop 后重写"）、容器式 mirror / rotate 节点与副本组（报错"不能对 mirror / rotate 容器换类型"）、副本式节点与影子（4.4.4："X 是副本，不能单独换类型"）。

**目标种类** T 必须是实体种类词、容器种类词（group union subtract intersect）或模板名（阶段 2 的最终定义）。T 是 repeat、mirror、rotate、copy、曲线种类词时报错"不能把物体换成 T"；既不是种类也不是模板时报错"over … : T：没有这个类型或形状种类"。两者都使整条 over 无效（原型 applyOpinions 相同）。

**容器 → 原子被拒绝**：原种类是容器、目标是实体时报错"不能把容器 X 换成 T：它的子物体会丢失，先 drop 再新建"，该成员不被修改（元数据等自然不变，8.3.6）。原型 applyOpinions 把它交给重新展开，然后因"box 不能有子语句"失败而使节点消失；本版在换形前拒绝。

### 4.6.2 保留表

换形时从 $m$ 的**有效属性**（4.1.3）里保留哪些、丢弃哪些，由目标 × 原种类决定。属性分五组：

| 组 | 含义 |
|---|---|
| 定位与朝向 | P 组除 `mat` `color`：`at on under against inside pin gap offset align alignto turn tilt roll rot aim aimwith` |
| 外观 | `mat` `color` |
| 专有属性 | 原种类的专有属性（1.4.5：`size` `r` `h` `points` `profile` `path` `envelope` …） |
| 模板参数 | 原节点是模板实例时实例语句写明的参数值（有效属性里的参数键） |
| 标签与元数据 | `#tag`、`~k=v`（元数据按源语句重新求值，8.3.6） |

"子语句"指源语句的块（容器的内容）；模板实例的体来自定义，不是子语句。

| 目标 \ 原 | 原子 | 容器 | 模板实例 |
|---|---|---|---|
| **原子** | 定位朝向 ✓ · 外观 ✓ · 专有 ✗ · 标签元数据 ✓ · 子语句 —（无） | **拒绝**（4.6.1） | 定位朝向 ✓ · 外观 ✓ · 参数 ✗ · 标签元数据 ✓ · 体 ✗ |
| **容器** | 定位朝向 ✓ · 外观 ✓ · 专有 ✗ · 标签元数据 ✓ · 子语句 —（无；块给内容） | 定位朝向 ✓ · 外观 ✓ · 专有 ✗（`envelope` 也不保留） · 标签元数据 ✓ · **子语句 ✗**（丢弃；要保留须在块里重写） | 定位朝向 ✓ · 外观 ✓ · 参数 ✗ · 标签元数据 ✓ · 体 ✗ |
| **模板 T** | 定位朝向 ✓ · 外观 ✓ · 专有 ✗ · 标签元数据 ✓ · 参数：只来自 over | 定位朝向 ✓ · 外观 ✓ · 专有 ✗ · 标签元数据 ✓ · 子语句 ✗ · 参数：只来自 over | 定位朝向 ✓ · 外观 ✓ · 标签元数据 ✓ · 参数：**派生链上**保留 T 的参数表里有的全部写明值（T 是原模板的基或派生）；**否则按名字匹配**：写明值的名字在 T 的参数表里的保留，不在的报错"模板 T 没有参数 k（换形自 X）"，该成员不被修改 |

规则细节：

- "定位朝向 ✓"与"外观 ✓"的精确含义：保留该组里**目标种类接受的**键（1.4.4 的表）且类型相同的；目标不接受的键丢弃（不报错）：换成 span / sweep 时 `pin` 的类型变成枚举⟨bottom top center⟩，原来的定位点形式的 `pin` 丢弃；换成 pipe 时只剩 `mat` `color`；换成曲线不可能（目标不能是曲线）；原是 line / bezier / spline 时本来没有 P 组。
- "专有 ✗"：原种类的专有属性一律不带过去，即使目标有同名属性（box → wedge 的 `size`、cyl → cone 的 `r` `h`）；新形状的全部专有属性从这条 over 的属性区取（没写的用目标种类的默认值；目标的必填属性没写报错"`<路径>` 缺少 `<属性>`"，新节点退化）。原型 applyOpinions 相同（`keep = PLACEMENT ∪ {mat, color}`）。这样做的理由：同名属性在不同种类里含义不同（plate 的 `h` 是厚度、cyl 的 `h` 是高；revolve 与 sweep 的 `profile` 类型不同），写明比猜测可靠。
- 容器 → 容器丢弃子语句是 PLAN 第 3 节的决定；原型 applyOpinions 保留源语句的块（`over gg : group { box j }` 得到 inner 与 j 两个子节点），本版只有块里写的 j。语料里没有换形。
- 模板 → 模板"派生链上"的判定：T 在 $m$ 所属模板 X 的派生链上，或 X 在 T 的派生链上（4.2.5 的链，含就地扩展）。保留的是 $m$ 的有效属性里属于参数的键中 T 的参数表里有的；派生独有的参数换到基类型时静默丢弃。over 属性区里写的参数键再覆盖（4.6.3）。原型对模板 → 模板保留全部参数并在重新展开时对多余的报"模板 X 没有参数 k"（节点仍退化重建）；本版按名字匹配，报错且该成员不变。
- 标签与元数据对每一种组合都保留（8.3.6）；名字、位置、匿名段的 $i$ 保留（1.6.1）。

### 4.6.3 换形的过程

对一个被选中的成员 $m$（选择器与范围按 4.5.2，副本限制按 4.4.4）：

1. 检查原种类与目标（4.6.1）；不合法时报错，该成员不被修改。
2. 构造新语句：种类词 = T；名字、标签 = $m$ 的；元数据 = 源语句的元数据项（重新求值）；属性表 = 按 4.6.2 从 $m$ 的有效属性筛选得到的表，再按 4.5.3 的顺序写入 over 属性区里的全部键：每个键必须是 T 接受的（T 的专有属性 ∪ T 接受的 P 组 ∪（T 是模板）T 的参数；1.4.8"换形时按目标种类检查"），否则报错"T 没有属性 k"，该成员不被修改；定位关系键按 4.5.3 替换原有的关系键。块 = **空**（原子与模板目标本来没有块；容器目标的内容由 over 块给出，4.6.2）。
3. 按 4.5.4 第 2–4 步用这条新语句重建 $m$ 为 $m'$：同一位置、同一名字；词法环境 = 源语句原来的环境；T 是模板时按 4.2.3 实例化（参数绑定来自第 2 步的参数键；缺必填参数报错"模板 T 缺少参数 p"，$m'$ 退化、体不展开）。$m'$ 的源语句就是这条新语句，之后的 copy / 重建都从它出发。
4. 施加 over 的块（4.5.5）：块里生成节点的语句成为 $m'$ 的子节点（容器目标的内容、模板目标的追加部件、原子目标的附属物）；块里的 over / drop 作用于 $m'$ 的子树。
5. $m'$ 的种类与类型链按 1.6.7、4.2.7（`types` 输出 T 的派生链或 `null`）；它可以被此后的修改选中（`kind(T)` 也选中它）、被 copy、被复制为副本；它的影子在阶段 6 按它生成。

所有引用 $m$ 的属性（别的节点的 `on=m`、`at=m.top`、`of=m`）在求解时解析到 $m'$（同名同位置），锚点按 $m'$ 的新盒计算。$m$ 子树上此前的修改按 4.5.4 丢失。

### 4.6.4 示例

```s3d
box ground size=40,1,40 pin=top
box hall size=10,6,8 on=ground turn=30 mat=concrete
box sign size=1,1,0.1 against=hall.front
over hall : subtract { box outer size=10,6,8; box door size=4,4,2 at=0,0,4 }
// hall 变成布尔容器：on=ground turn=30 mat=concrete 保留，size 丢弃，内容来自块；sign 仍贴在 hall.front（新盒的前面）
over sign : cyl r=0.5 h=0.1
// 招牌变成圆片：against=hall.front 保留，size 丢弃，r / h 从 over 取

def shed(w=4) { box body size=w,3,w }
def big(h=5) : shed(w=6) { box top size=1,h,1 on=body }
def other(w=1, q=2) { box z size=w,q,1 }
box hut size=4,3,4 on=ground[0.4,1,0.4]
over hut : shed w=5                 // 原子 → 模板：on 保留；参数只来自 over
shed h1 w=5 at=0,0,20
over h1 : big                       // 派生链上：w=5 保留（压过 big 的覆盖 w=6）；types = [big, shed]
big h2 h=7 at=0,0,30
over h2 : shed                      // 派生 → 基：h 是 big 独有的，静默丢弃；h2 是 shed，w 用默认 4
shed h3 w=7 at=0,0,40
over h3 : other                     // 无关模板：按名字匹配，w=7 保留；若 h3 还写了 other 没有的参数则报错、h3 不变

repeat row n=3 step=4,0,0 { box tank size=1,2,1 }
over row { drop tank; cyl tank r=0.5 h=3+idx }   // 要"换"阵列里的部件，用块而不是换形
```

## 4.7 变体的挂载接口

07-semantics.md 的 7.8 定义变体的**选择**（阶段一求选择集、多条变体与祖先 / 后代之间的裁决、`use` 的模板、不可见性的保证）；本节定义给定一个要挂载的 (节点 $N$，模板 T，写明的参数与 `mat` / `color`) 时**展开侧**做什么。两章的接口如下。

**挂载。** 在阶段 8，对每个要挂载的 $N$（按节点顺序）：

1. **隐藏**：$N$ 与它当时的全部后代标记 `hidden`（不输出条目、不渲染；仍在树里、仍进 `all()`、仍有变换、包围盒、事实与有效材质，10.4.3）。$N$ 之外的节点不受影响，包括 $N$ 的影子与副本式节点（4.4.5）。
2. **皮肤语句**：构造一条模板实例语句 `T skin { 参数… }` 并以 $N$ 为父节点展开（4.2.3、4.2.4；T 用最终定义，T 不存在报错"variant 的模板 T 没有定义"，该 $N$ 不挂载也不隐藏）。皮肤节点 $K$：段 `skin`（1.6.4），种类 T，类型链 = T 的派生链，名字 `skin`，没有标签，元数据空（8.3.7），`file` / `line` = 那条 variant（或外观时机 `over … use=`）语句的（05-layers.md 的 5.2.5），追加在 $N$ 现有子节点之后（1.6.1）。$K$ 与它的全部后代标记 `skin`（输出字段，不隐藏）。
3. **参数绑定**：
   - 变体语句写明的参数（`variant S use=T k=v`：`k` 必须是 T 的参数，1.3.13）按写明的值绑定，值按 07-semantics.md 规定的上下文求值（1.5.8：语义帧、搜索起点根）。
   - **自动传参**：对 `w`、`h`、`d` 三个名字中 T 的参数表里有、而变体没有写明的，分别绑定为 $N$ 的**局部包围盒**（02-geometry.md：有 `envelope` 的 group 用 envelope；退化节点为 0）沿 $N$ 自己的 $x$、$y$、$z$ 的边长——与 `N.w` `N.h` `N.d`（3.2.6）相同的数，不随 $N$ 的朝向变。T 没有声明这些参数时不传（模板可以只接受其中一两个）。
   - 其余参数用默认值（4.2.3）；T 有必填参数而变体没写报错"模板 T 缺少参数 p"，$K$ 退化、体不展开（$N$ 已隐藏——实现**应**在这种情况下不隐藏 $N$，见 7.8.8）。
4. **外观**：变体语句的 `mat` / `color` 作为 $K$ 的自有外观属性（10.4.3：皮肤的材质链在 $K$ 处终止、终点是 $E(N)$）。
5. **定位**：$K$ 的局部变换由本节直接给出，不走 3.1.3 的一般规则（3.1.2 表的"变体皮肤"行）：
$$R_K = I,\qquad t_K = b_N - \pi_K,$$
其中 $b_N$ 是 $N$ 的局部包围盒（同第 3 条）的**底面中心** $(c_x, \min_y, c_z)$，$\pi_K$ 是 $K$ 自己的局部包围盒（2.6：体展开出的子节点之并，在 $K$ 的局部系里）的底面中心。即皮肤的盒底面中心落在宿主的盒底面中心，轴向与宿主相同；皮肤的尺寸由模板按 w / h / d 决定，不强制等于宿主的盒（可以大、可以小）。这等价于给皮肤语句写 `at=N.bottom pin=bottom` 并把 `at` 的参照解析为 $N$ 自身的局部系（原型 compileOnce 正是这样构造：`at=__self`（$N$ 的 bottom 锚点）、`pin=bottom`）；变体语句因此不接受 `at` / `pin`（1.3.13）。
6. **求解**：$K$ 的子树按第 3 章求解（它可以引用 $N$ 之外已求解的节点；$N$ 之外的节点引用不到皮肤——皮肤不进全局索引，1.6.4）；皮肤里的 mirror / rotate 按 4.4.2 生成副本树；皮肤里的 over / drop（模板体里的）按 4.5 在皮肤子树内施加（它们的位置是皮肤语句的位置，排在全部几何时机修改之后、只作用于皮肤子树）；模板体里的 copy 在皮肤展开时按 4.3.5 末段的规则立即展开（像 over 块里的 copy）。

**不改变阶段 7 的量**（D9）。皮肤节点 $K$ **不计入** $N$ 的局部包围盒（容器 $N$ 的 2.6 求并不含段为 `skin` 的子节点），也不计入 $N$ 任何祖先的盒；$K$ 子树不参与空间事实（06-facts.md）、不进 `all()` / `kind()` / `#tag`（1.7.2）、不被样式直接作用（10.4.3）。因此挂载前后每个非皮肤节点的 $W$、`box`、`tight`、事实、概念成员逐位相同（语料 spaceport_blueprint 与 spaceport 的事实列表相同，4.8）。

**语料里的三个皮肤**（数值见 4.8）：`over hangar.roof use=ribbed`（ribbed 声明 w h d → 得到 36、0.8、28；`base` 高 0.28 = 0.35h；rib 的 n = floor(36/1.6) = 22）；`variant deck use=planks`（slab：36、0.6、6 → 40 块 0.82 宽的板）；`variant tall_building use=townhouse`（h4：7、11.2、5.8 → core 高 10.6）。
