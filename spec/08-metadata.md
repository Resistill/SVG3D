# 8 元数据

**范围。** 本章定义元数据 `~k=v` 的语义：对哪些语句合法、值的类型与求值时机、键的规则、文件头元数据与 `lang`；两条保证（不参与几何与语义求值；可在 `where` 里读）的精确含义；每条元数据属于哪个节点（模板、阵列、副本、拷贝、修改、变体各自的规则）；编译输出里元数据的形状；不保留键名。语法（记号、文法、值的文法）在 01-syntax.md，本章只引用。本章不定义任何键的含义（8.5 节）。

**依赖的章。** 01-syntax.md（1.2.10、1.3.1、1.4.1、1.5.5、1.5.8、1.6.5、1.7.3、1.9）；04-derivation.md（模板展开、copy、副本、over / drop 与换形的过程）；07-semantics.md（语义层的求值时机）。被依赖：05-layers.md（文件头元数据的输出）、09-compat.md（行为变化清单）、10-materials.md（material 条目的 meta）。

## 8.1 定义

### 8.1.1 语法

元数据项的文法是 01-syntax.md 1.9 节的 `meta = "~" ident "=" value`：`~` 紧跟键（1.2.10），键是标识符（1.2.5），值是一个表达式（1.5.1），到第一个不能继续该表达式的记号为止。本章用**元数据项**指一个 `~k=v`，用一条语句的**元数据**指这条语句上全部元数据项构成的有序映射（键 → 值；顺序 = 各项在语句里的先后）。没有元数据项的语句的元数据是空映射。

### 8.1.2 合法的位置

- 元数据项对**所有语句**合法（D2）：通用形态语句（实体、曲线、容器、mesh、模板实例）、copy、mirror / rotate 的两种形式、def、let、import、material、over、drop、concept、pattern、check、style、variant，以及文件头（8.1.5）。每种语句里元数据项的位置由 01-syntax.md 1.3 节的文法规定：写在属性区，与属性、标签的先后任意；def 与 pattern 写在块之前；over 的元数据项写在选择器之后（`~k=` 结束选择器，1.3.8）。
- 块内语句（容器块、repeat 体、模板体、copy 块、over 块）上的元数据项与最外层语句的规则相同。
- 表达式里不能出现元数据项（1.2.10）；属性值、选择器、约束行里出现 `~k=` 时它结束前面的表达式并开始一个元数据项，若该语句的文法在此处不接受元数据项（例如 pattern 的约束行）报错"多余的内容"。

### 8.1.3 值的类型与求值

- 值是**常量**（01-syntax.md 1.4.1 的"常量"类型）：在**展开时**求值，上下文是写它的语句的词法环境帧（1.5.8 表最后一行），**不查对象**。可以引用 `let`、模板参数、阵列索引 `i j k idx`（在 repeat 体内）、内置常量 `metre`，以及 1.5.6 里"任何"时机可用的函数。
- 不能引用对象：值里的裸标识符或路径若在词法环境里找不到，报错"元数据不能引用对象 X"（不做场景树查找，也不退化成字符串——D4；要存一个名字写字符串 `"X"`）。词法环境里找到的名字若其值是引用或集合（over / copy 块里的 `it`、集合值的 `let`），同样报错"元数据不能引用对象 X"。井号记号在元数据值里是标签引用，同样报错"元数据不能引用对象 #t"（要存颜色写 `"#abc"`）。`where` 报错"where 只能在求解阶段使用"；`all()`、`kind()`、`children()`、`descendants()`、`count()`、关系谓词报错"X() 只能在求解阶段使用"。
- 求值结果必须是下表的类型之一；其他值（引用、集合、模式值、正则、缺失值、含列表的列表）报错"元数据的值只能是数、字符串、布尔、向量或它们的列表"。

| 类型 | 写法 | 约束 |
|---|---|---|
| 数 | 数字字面量、算术、函数 | 有限双精度（溢出与 NaN 按 1.5.2 报错） |
| 字符串 | 字符串字面量（1.2.4） | 任意长度（可以为空串） |
| 布尔 | `true` / `false`、比较、逻辑 | |
| 向量 | `a,b,…` 或 `(a,b,…)` | 长度 ≥ 2，分量都是数；单个数是数不是向量 |
| 列表 | `[t₁; t₂; …]` | 至少 1 项；每项是数、字符串、布尔或向量；项不能是列表 |

- **求值次数**：语句每生成一个节点，它的元数据就在该节点的上下文里求值一次：模板体内的语句每个实例一次，repeat 体内的语句每个阵列实例一次，被 copy 复制的语句每次复制一次（在原语句的环境里，8.3.5），重建型修改后一次（8.3.6）。所以 `~ww=w`（w 是模板参数）、`~i=idx` 随实例不同而不同。非节点语句（8.3.8）的元数据也求值一次（错误照常报告）。

```s3d
let unit = 0.5
repeat posts n=4 step=3,0,0 ~src="posts" {
  cyl p r=0.2 h=3 ~i=idx ~len=3*unit ~part="post"     // 每个实例各自求值：posts.0.p 的 i 是 0
}
box pad size=4,1,4 ~fit=0.93 ~src="merged_1#2" ~tags=["wall"; "ext"] ~color="#abc"
```

### 8.1.4 键

- 键是标识符，大小写敏感，不得是关键字（`where and or not in true false`，词法上已排除）。键可以与属性名、保留名、where 字段名相同（`~kind=1`、`~size="x"`、`~src=…` 都合法）；与 where 字段（`w h d x y z top bottom kind name mat it`）同名的键在 where 里读不到（8.2.2），实现**应**对这样的元数据项给警告"元数据键 X 与 where 字段同名，在 where 里读不到"。
- 同一语句（或同一文件头）里同一键出现两次报错"重复的元数据 k"：该键在这条语句上**不存在**（两个值都不采用），该语句其他的元数据项与节点不受影响（节点不退化，1.1.4 第 3 条）。
- 一条语句上元数据项的个数不限。不同语句的元数据互不影响（没有继承，除 8.3 节明确写出的传播规则）。
- `lang` 在文件头之外是普通键：不被规范解释，照常附在语句上并输出；实现**应**警告"lang 只在文件头有意义"。

### 8.1.5 文件头元数据与 `lang`

- 文件头的文法与判定在 01-syntax.md 1.3.1：一个文件（主文件与每个被 import 的文件各自）的第一个非空、非注释的行若只由元数据项组成，它是**文件元数据行**；每个文件至多一行。它不属于任何语句、不生成节点；它的元数据叫**文件元数据**。
- 文件元数据的求值上下文是全局帧（1.5.8）：可以引用 `metre` 与最外层 `let`（let 对整块可见，与书写顺序无关），其余规则与 8.1.3 相同。
- `lang` 是本规范保留的唯一键（D7）：值必须求值为数 $2$（`2`、`2.0`、`1+1` 都可以）；缺省等价于 2；值是其他数或其他类型报错"不支持的语言版本"，整个文件不编译（主文件：编译结果没有节点与输出，错误列表只有这一条；被 import 的文件：不导入，错误带该文件）。它是声明，不切换语义（本版只有一种语义）。
- 文件元数据的其他键不被规范解释；输出见 8.4.3。

```s3d
~lang=2 ~generator="s3d-reverse" ~source="spaceport.L1.glb"
material steel color=#7f8b96 metal=0.6 rough=0.4
box pad size=10,1,10 mat=steel ~fit=1 ~src="pad"
```

### 8.1.6 错误、警告与恢复

元数据的错误只影响出错的键（1.1.4 第 3 条）；下表是本章定义的全部诊断。

| 诊断 | 触发 | 效果 |
|---|---|---|
| 错误"元数据不能引用对象 X" | 值里的名字不在词法环境里；词法环境里的名字其值是引用或集合（`it`、集合值的 let）；`#tag` | 该键不存在 |
| 错误"元数据的值只能是数、字符串、布尔、向量或它们的列表" | 结果是引用、集合、模式值、正则、缺失值、含列表的列表 | 该键不存在 |
| 错误"where 只能在求解阶段使用"、"X() 只能在求解阶段使用" | 值里用了 where 或求解后才可用的函数 | 该键不存在 |
| 错误"重复的元数据 k" | 同一语句或文件头里同键两次 | 该键不存在 |
| 算术 / 函数的类型错误与"结果不是有限数"（1.5.2、1.5.6） | 值求值失败 | 该键不存在 |
| 错误"不支持的语言版本" | 文件头 `lang` 不是数 2 | 整个文件不编译 |
| 错误"语句缺少种类词"（1.3.1） | 文件头之后又出现只含元数据项的行 | 该行丢弃 |
| 错误"多余的内容"（约束行）、"元数据写成 ~名字=值，要写在属性之后"（表达式内，1.2.10） | 元数据项出现在文法不接受的位置 | 该语句丢弃（语法错误） |
| 警告"元数据键 X 与 where 字段同名，在 where 里读不到" | 8.1.4 | 无 |
| 警告"lang 只在文件头有意义" | 8.1.4 | 无 |
| 警告"没有节点带元数据 X" | 8.2.2 第 5 步 | 无 |

"该键不存在"意味着：节点照常生成、不退化；where 里读该键得到缺失值；输出的 `meta` 里没有该键。元数据求值失败的节点与其他节点完全一样（进 `all()`、`kind()`、标签索引、全局索引，参与求解与事实）。

## 8.2 两条保证

### 8.2.1 保证一：不参与几何与语义求值

除 8.2.2 的 where 读取之外，语言里**没有任何**读取元数据的构造：属性值、模板参数、let、定位关系、材质、事实提供者、语义语句的求值都不读元数据。精确地说，任何节点的下列各项都**不依赖**任何语句的元数据：

1. 节点的生成、路径、名字、种类、标签、子节点顺序与节点顺序（1.6 节）；
2. 局部变换 $(R, t)$、世界变换、局部 / 世界 / 紧包围盒、外包络、几何（SDF、凸块、三角化）；
3. 空间事实（06-facts.md）及其顺序；
4. 概念成员、模式匹配、检查结果、样式与变体的选择集（07-semantics.md）——**除非**该语句的选择器用 `where` 显式读了元数据键；
5. 有效材质与颜色（10-materials.md）；
6. 诊断——除 8.1.6 列出的元数据自身的诊断。

可检验的表述：设 $F$ 是一组源文件（主文件与它 import 的文件），$F^-$ 是把 $F$ 里除文件头 `lang` 以外的全部元数据项删掉得到的文件。若 $F$ 里没有任何 where 谓词按 8.2.2 第 2 步读到元数据键，则 $F$ 与 $F^-$ 的编译结果**逐位相同**，只除：(a) 各处 `meta` 字段（8.4 节）；(b) 8.1.6 的诊断。若 $F$ 里有 where 谓词读了元数据键，元数据影响结果的**唯一**途径是这些谓词的真值（从而是这些选择器的选择集）。

推论：元数据值不能引用对象（8.1.3），所以它不构成求解的依赖边，不影响依赖排序与后置（03-solving.md）；元数据求值在展开时完成，求解与语义阶段不再求值。

### 8.2.2 保证二：可在 where 里读

对 `S where P` 的每个成员 $m$，谓词 $P$ 里的一个**单段裸标识符** $k$（不带坐标后缀、不是函数调用、不是关键字）按下面的顺序解析——这是 01-syntax.md 1.6.5 与 1.7.3 在元数据上的展开，两处必须一致：

1. $k$ 是 where 字段（`w h d x y z top bottom kind name mat it`）→ 字段值（1.7.3）。**内置字段优先**：同名的元数据键在 where 里永远读不到。
2. $m$ 的元数据（按 8.3 节的归属；影子读原件的）含键 $k$ → 该键的值（8.1.3 的类型之一）。
3. where 外层的词法环境（`let`、模板参数、`i j k idx`、over / copy 块的 `it`……，1.5.8）含 $k$ → 该值。
4. 按 1.6.5 第 2、3 步在场景树与全局索引里找到对象 $k$ → 引用。
5. 都没有 → **缺失值**（1.5.5）。若整棵场景树（含皮肤子树）没有任何节点的元数据含键 $k$，实现**应**给警告"没有节点带元数据 X"（每条语句、每个键至多一次）。

- 多段路径（`a.src`、`it.src`）永远不读元数据：按 1.5.4 的后缀规则报错"a 中没有子对象或锚点 src"。元数据只能通过成员自己的裸键读取；别的节点的元数据不可寻址。
- 读取的时机：几何时机的 over / drop 选择器可以读（元数据是静态量，1.7.4）；外观时机的 over、style、variant、concept、pattern、check 的选择器与表达式可以读；`let` 的值在被这些地方读到时也可以含 where 谓词（1.5.8）。
- 对影子的读取得到原件的值（8.3.4），所以 `all() where src == "n1"` 同时选中原件与它的影子。

```s3d
drop all() where fit < 0.3                       // 几何时机：静态量
style all() where src ~ /^merged_/ color=#ffcc00  // 外观时机
concept imported = all() where src ~ /./          // 有 src 键的全部节点
check "导入件都有拟合度" count(imported where not (fit >= 0)) == 0
```

### 8.2.3 谓词里的类型规则

元数据值在谓词里按 1.5.5 的规则参与运算；本节补全元数据特有的情况。

| 值的类型 | 可用的运算 | 结果 |
|---|---|---|
| 数 | `< > <= >= == !=`、算术、数学函数 | 按 1.5.2、1.5.5 |
| 字符串 | `== !=`（按码点）、`~ /re/`（搜索匹配，1.2.9） | 布尔 |
| 布尔 | `== !=`、`and or not`；可直接作谓词 | 布尔 |
| 向量 | `== !=`（逐分量；长度不同为假）、与同长向量加减、与数乘除 | 按 1.5.2、1.5.5 |
| 列表 | `== !=`：两边都是列表、同长且逐项按 `==` 相等时为真 | 布尔；其他运算报错"无法计算 A op B" |
| 缺失值 | 任何比较、`~`、`and`、`or`、`not` → **假**；算术与函数 → 缺失值；整条谓词的值是缺失值 → 该成员不选中；作集合、点、参照物或属性值 → 报错"元数据键 X 缺失" | （1.5.5） |

- 运算的操作数类型不符（`fit ~ /1/`：`~` 左边是数；`src < 1`：`<` 两边不都是数；`lock and true`：`lock` 是数）按 1.5.5 报类型错误，该语句无效（1.10.2）。**缺失值永远不引起类型错误**：成员没有该键只会让谓词为假，不会让语句失效。
- 两边类型不同时 `==` 为假、`!=` 为真（1.5.5）：`fit == "1"`（数对字符串）为假。
- `~ /re/` 只对字符串；要对数做模式匹配，先在源文件里把它写成字符串。

## 8.3 元数据属于哪个节点

### 8.3.1 总则

- 一条生成节点的语句的元数据附在**该语句产生的节点**上；节点的元数据 = 它的源语句的元数据在生成该节点的上下文里求值的结果（8.1.3）。节点从生成到输出，元数据只在 8.3.6 的重建时重新求值，其余任何阶段都不改变它。
- 元数据**不沿树继承**：子节点不带父节点的元数据，容器不带子节点的元数据。
- 退化节点（1.1.4）照常带它的元数据。被 drop 的节点连同元数据一起消失。
- 由实现生成、没有源语句的节点（阵列实例、副本组、皮肤节点）的元数据是空映射；影子是例外（8.3.4）。

### 8.3.2 模板

- 模板实例语句的元数据附在**实例节点**上，在实例语句的上下文里求值（可用实例所在块的 let 与 `i j k idx`）。
- 模板体内语句的元数据附在它们各自生成的节点上，每个实例各求值一次，上下文是模板体帧（看得见参数与体内 let，1.5.8）。派生模板的实例按派生链展开每个体，各体内语句的元数据同样附在各自的节点上。
- `def` 语句自己的元数据属于模板定义（8.3.8）：实例节点不带它，派生模板也不继承它。
- 元数据不是模板参数：实例语句上的 `~k=v` 不传给模板体；模板体内读不到实例的元数据。

```s3d
def hut(w=4) ~src="lib/hut" {               // 属于定义，不进实例
  box body size=w,3,w ~part="body" ~ww=w    // 每个实例各求值：h1.body 的 ww 是 4，h2.body 的是 6
}
hut h1 ~src="n1"                            // h1 的元数据 {src:"n1"}
hut h2 w=6 ~src="n2"
```

### 8.3.3 阵列

- `repeat` 语句的元数据附在 repeat 节点上。阵列实例节点（段 `0`、`1`、…）的元数据是空映射（它们没有源语句，与标签的规则一致，1.6.7）。
- repeat 体内语句的元数据附在各实例里它们生成的节点上，每个实例各求值一次（`~i=idx` 随实例变）。
- `over 阵列 { … }`（04-derivation.md）块里新语句的元数据同上，每个实例一次。

### 8.3.4 副本与影子

- 容器式 `mirror` / `rotate` 语句的元数据附在该容器节点上；副本组 `mirrored`、`r<k>` 的元数据是空映射。
- 副本式 `mirror R of=A` / `rotate R of=A`：节点 R 的元数据是 R 语句**自己的**（不取 A 的；A 的元数据仍在 A 上）。
- **影子**（副本里对应原件子节点的节点）的元数据 = 对应原件节点的元数据（同一个映射；1.6.3、1.7.3）。影子没有自己的源语句，这是唯一的"读别的节点"的规则。对影子的 over（孪生体，04-derivation.md）不改变这一点：影子仍读原件的元数据；孪生块里新加的语句的元数据属于新节点。
- 原件被重建（8.3.6）后影子跟着读重建后的元数据。

### 8.3.5 拷贝

`copy R of=A`：

- R 的元数据 = **合并**：先取 A 的源语句的元数据（在 A 的原语句环境里重新求值，8.1.3），再逐键用 copy 语句自己的元数据覆盖；结果的键顺序 = A 的键按原顺序（被覆盖的键保留位置、取新值），后接 copy 语句独有的键按 copy 语句里的顺序。copy 语句没有元数据项时 R 的元数据就是 A 的。
- A 子树里的语句被重新展开（04-derivation.md），每个生成的节点带它自己语句的元数据（在原语句环境里求值）。
- copy 复制的是 A 的**定义**（源语句）：A 在被 copy 前后通过 over 得到的修改不进 R，但 over 不改元数据，所以这一点对元数据没有影响；A 被重建型修改后再 copy，复制的是重建后的语句（元数据相同，参数可能不同）。
- copy 块里的 over / drop 的元数据属于那些修改语句（8.3.8），不合并到 R 或它的子节点；块里新语句的元数据属于新节点。

```s3d
box a size=1,1,1 ~src="n1" ~fit=0.9
copy b of=a at=3,0,0 ~fit=1 ~note="dup"      // b 的元数据 {src:"n1", fit:1, note:"dup"}
copy c of=a at=6,0,0                         // c 的元数据 {src:"n1", fit:0.9}
```

### 8.3.6 修改：over / drop、重建、换形

- `over` 与 `drop` 语句自己的元数据属于**那条修改语句**（8.3.8），**不合并**到被选中的节点：`over tower lv=10 ~why="加层"` 之后 tower 的元数据不变。
- over 的块里新语句的元数据属于新节点（在块帧里求值；`it` 不能出现在元数据值里，8.1.3）。
- **就地修改**（改属性，04-derivation.md）不碰元数据。
- **重建型修改**（改模板参数、改阵列 `n`、换形 `: T`）：新节点的元数据 = **源语句**的元数据在重建上下文里重新求值的结果，所以依赖参数的元数据随新参数变（`~ww=w` 在 `over h w=8` 后是 8），不依赖参数的不变。换形对 D11 表的**每一种**"原 → 目标"组合都保留元数据（表里"标签与元数据"列恒为"保留"），包括容器 → 基本体被拒绝的情形（节点不变，元数据自然不变）。重建时源语句的子语句重新展开，子节点各带自己语句的元数据；此前经 over 块加入的子节点随旧子树一起丢失（04-derivation.md）。
- `drop` 的元数据同样只属于 drop 语句；被 drop 的节点消失。

### 8.3.7 变体皮肤

- 被变体选中的节点保留并隐藏，它的元数据不变。皮肤节点 `skin` 的元数据是空映射；皮肤模板体内语句生成的节点各带自己语句的元数据（每个皮肤各求值一次）。
- `variant` 语句自己的元数据属于该语句（8.3.8），不进皮肤。
- 皮肤子树不进 `all()`，所以 `all() where …` 读不到皮肤节点的元数据；通配、`children()`、`descendants()` 选中的皮肤节点在 where 里按常规读（1.6.4）。

### 8.3.8 非节点语句

不生成节点的语句的元数据**只保存、不作用**：实现必须把它保留在该语句的记录上（供读取源码与语句列表的工具使用），编译的任何阶段都不读它，它不传播给任何节点。归属与输出：

| 语句 | 元数据属于 | 求值帧 | 输出（8.4.3） |
|---|---|---|---|
| `def` | 模板定义；实例与派生模板不继承 | 全局帧（看不见参数） | `defs` 条目 |
| `let` | 该 let | 所在块的帧 | 不输出 |
| `import` | 该 import 语句（层） | 全局帧 | 层的条目（05-layers.md） |
| `material` | 该材质定义；同名覆盖时元数据随整条定义被替换（10-materials.md） | 全局帧 | `materials` 条目 |
| `over` / `drop` | 该修改语句；不合并到目标 | 写它处的帧 | 不输出 |
| `concept` / `pattern` / `check` / `variant` | 该语句 | 全局帧 | 各自的条目 |
| `style` | 该语句 | 全局帧 | 不输出 |
| 文件头 | 该文件 | 全局帧 | 顶层 `meta`（主文件）；层的条目（被 import 的文件） |

### 8.3.9 汇总表

| 节点 | 元数据 |
|---|---|
| 实体、曲线、group / union / subtract / intersect、repeat、容器式 mirror / rotate、模板实例、mesh | 自己语句的 |
| 块内语句生成的节点（容器块、repeat 体、模板体、copy 块、over 块、孪生块、皮肤体） | 自己语句的，每次生成各求值一次 |
| 阵列实例 `r.0` | 空 |
| 副本组 `mirrored`、`r<k>` | 空 |
| 副本式节点 `mirror R of=A` 的 R | R 语句自己的 |
| 影子（含被孪生修改的影子） | 对应原件节点的 |
| copy 节点 | 原件语句的 ∪ copy 语句的（后者逐键覆盖） |
| 重建型修改 / 换形后的节点 | 源语句的，重新求值 |
| 就地修改后的节点、被变体隐藏的节点、退化节点 | 不变 |
| 皮肤节点 `skin` | 空 |

## 8.4 输出

### 8.4.1 节点的 `meta` 字段

- 编译输出里每个节点条目（`nodes[]`，各章定义其他字段）都有 `meta` 字段：一个 JSON 对象，键是元数据键（原样，不转换大小写），值按 8.4.2 映射。没有元数据的节点输出 `{}`；字段**总是存在**。
- 键的顺序 = 8.3 节定义的该节点元数据的顺序（源语句里各项的先后；copy 按 8.3.5 的合并顺序）。实现必须按此顺序写出（D15：输出不得依赖哈希顺序）。
- 影子的 `meta` 写出原件的元数据（与 8.3.4 一致，不是空对象）；阵列实例、副本组、皮肤节点写 `{}`。
- 元数据求值失败的键不出现（8.1.6）。

```json
{ "path": "pad", "kind": "box", "meta": { "fit": 0.93, "src": "merged_1#2", "tags": ["wall", "ext"], "color": "#abc" } }
```

### 8.4.2 值到 JSON 的映射

| 元数据值 | JSON |
|---|---|
| 数 | JSON 数字。整数值（$\lvert v \rvert < 2^{53}$）写成不带小数点与指数的十进制整数（`1`、`-2`）；其他值用能无损还原双精度值的最短往返十进制表示；`-0` 写成 `0` |
| 字符串 | JSON 字符串（UTF-8；按 JSON 规则转义） |
| 布尔 | `true` / `false` |
| 向量 | 数字数组 `[x, y, …]` |
| 列表 | 数组，各项按本表映射（项是向量时是数组的数组） |

输出不区分向量与列表（`~a=1,2` 与 `~a=[1;2]` 都输出 `[1,2]`）；两者在 where 里仍是不同类型（8.2.3）。

### 8.4.3 文件头与非节点语句的输出

- 编译输出的顶层有 `meta` 字段：主文件的文件元数据，键顺序同文件头；`lang` **总是存在**且值为 `2`（文件头没写时补上，写在最前）。没有文件头时是 `{ "lang": 2 }`。
- 被 import 的文件的文件元数据随 05-layers.md 定义的层列表输出，每层一个 `meta` 字段（形状同上，`lang` 同样总是存在）。
- 非节点语句的元数据只在该语句有输出条目时输出，字段名一律是 `meta`、形状同 8.4.1：`materials` 的每个条目（10-materials.md）、`defs` 的每个条目（04-derivation.md）、`concepts[]`、`patterns[]`、`checks[]`、`variants[]` 的每个条目（07-semantics.md）。`let`、`import`、`over`、`drop`、`style` 没有输出条目，它们的元数据不进编译输出（工具从源码或语句列表读取，8.3.8）。
- 输出格式之外的场合（错误文案、大纲文本）不要求显示元数据。

## 8.5 不保留键名

- 本规范**不定义任何键的含义**，编译器对任何键都没有特殊处理（唯一例外是文件头的 `lang`，8.1.5）。本章与第 1 章示例里出现的 `src`、`fit`、`note` 等键只是语法用例，不是规范的一部分。
- 工具**可以**约定键名及其值的形状（例如逆向管线写什么、意图机制读什么）；这些约定写在 `docs/agent.md`，不写进规范，规范也不为它们预留语义。一个遵守本规范的实现只需保证 8.1–8.4：接受任何键、原样保存、在 where 里可读、原样输出。
- 新的键不需要向规范登记；两个工具用同一键名表示不同含义是工具之间的事，编译器不仲裁。
